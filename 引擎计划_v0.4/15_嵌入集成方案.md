# 15 · 嵌入集成方案（v0.4.1 已定）

> 用户 2026-11-21 定下三项决定，本文写清它们对架构和计划的影响。
> 本文与 00–14 号文档冲突时，**以本文为准**；涉及的文档已同步修改。

| # | 决定 | 原计划 | 现在 |
|---|---|---|---|
| D1 | 引擎**嵌入现有 Go 服务** | 独立进程 `cmd/harnessd` | 宿主服务 import `harness` 包，把 `http.Handler` 挂到自己的路由上；没有独立进程 |
| D2 | 前端**嵌进现有 Next.js 应用** | 独立的 `web/` 应用 | 宿主应用新增 `/canvas` 路由模块，外加一个能嵌进对话消息的 `<CanvasCard>` 组件 |
| D3 | 首批模型：**OpenAI 兼容接口、Anthropic、Gemini** | 前两家 | 三家都在 M1–M2 完成；国内厂商和本地模型走 OpenAI 兼容接口 |

> 下文把"现有 Go 服务"称为**宿主服务**，"现有 Next.js 应用"称为**宿主应用**。其他文档里残留的 `harnessd` 一词，统一理解为"宿主服务中挂载的 harness 模块"。

## 1. 后端：嵌入宿主服务

### 1.1 目录：放在宿主仓库里

```
<宿主仓库>/
├─ ...宿主原有代码
└─ harness/                    ← 新增，整块属于本项目
   ├─ schema/                  JSON Schema（唯一事实来源）
   ├─ engine/                  内核库：不依赖 HTTP，不依赖宿主（depcheck 强制）
   ├─ api/                     HTTP 路由、SSE、幂等、错误码（原 internal/api、internal/sse）
   ├─ host/                    ★ 宿主接入层：Deps 接口、Config、New/Handler/Run/Shutdown
   ├─ gen/                     schema 生成的 Go 类型
   └─ tools/depcheck/
```

- **用宿主的 Go module**，不另建 go.mod。好处是升级依赖时只有一套版本；代价是 harness 的依赖会出现在宿主的 go.mod 里。如果宿主对依赖管控很严，可以退而把 `harness/` 做成子 module，再用 `replace` 引用，结构不用变。
- 原来的 `internal/api`、`internal/sse` 改名为 `harness/api`、`harness/api/sse`。Go 的 `internal` 只允许父目录内部 import，宿主的 main 不在 harness 下，用 internal 会 import 不到。
- depcheck 规则在原有基础上加一条：`harness/engine/**` **不得 import 宿主的任何包**。宿主的能力只能通过 `host.Deps` 接口注入。

### 1.2 接入方式（宿主侧只需要十几行代码）

```go
// 宿主 main.go 或 wire 里
hx, err := host.New(host.Config{
    DataDir:      cfg.Harness.DataDir,          // SQLite 文件、工作区 blobs
    MaxRuns:      cfg.Harness.MaxRuns,          // 并发运行上限
    MaxNodeConc:  cfg.Harness.MaxNodeConc,      // 全局节点并发上限，防止挤占宿主
    Models:       cfg.Harness.Models,           // 三家 provider 配置（不含密钥）
    MCPServers:   cfg.Harness.MCP,
}, host.Deps{
    Auth:    hostAuth,              // host.Authenticator：从请求中取出当前用户
    Secrets: hostSecrets,           // host.SecretStore：按名称取 API key
    Logger:  logger.With("mod", "harness"),
    Metrics: promRegistry,          // prometheus.Registerer，指标加 hx_ 前缀
    DB:      nil,                   // nil 表示用独立的 SQLite；传入 *sql.DB（Postgres）则复用宿主数据库
})
if err != nil { return err }

router.Mount("/api/harness/v1", hx.Handler())   // chi；gin 用 gin.WrapH(hx.Handler())；标准库用 mux.Handle
go hx.Run(ctx)                                   // 后台：迁移、崩溃恢复、调度器、清理任务
defer hx.Shutdown(shutdownCtx)                   // 停止接收新运行 → 写检查点 → 超时后取消
```

```go
// harness/host/deps.go
type Authenticator interface {
    // 从宿主的会话或令牌中解析出用户；解析失败返回 ErrUnauthenticated，返回 401
    FromRequest(r *http.Request) (authz.Principal, error)
}
type SecretStore interface {
    Get(ctx context.Context, name string) (string, error) // 例如 "openai.default"、"anthropic.default"、"gemini.default"
}
```

### 1.3 必须处理的几个嵌入问题

| 问题 | 表现 | 处理 |
|---|---|---|
| **宿主的 `http.Server.WriteTimeout` 会切断 SSE** | 运行事件流 30 秒后断开，前端反复重连 | SSE handler 里用 `http.NewResponseController(w).SetWriteDeadline(time.Time{})` 清掉写超时；每 15 秒发一次 `: ping` 注释帧 |
| **宿主的 gzip 中间件** | 事件被压缩后缓冲，前端迟迟收不到 | 对 `Content-Type: text/event-stream` 豁免压缩；设置 `X-Accel-Buffering: no` 和 `Cache-Control: no-cache` |
| **宿主的请求日志或 body 记录中间件** | 记录 SSE 长连接 body，内存一直涨 | 对 `/api/harness/v1/*/events`、`/stream` 跳过 body 记录 |
| **宿主的全局请求超时（context deadline）** | 长连接被 cancel | 这两个路由从超时中间件中排除；或者 `hx.Handler()` 内部用 `context.WithoutCancel` 加自己的取消来源 |
| **资源挤占** | 引擎并发跑大量节点，宿主接口变慢 | `MaxNodeConc`、各资源池配额、模型调用的令牌桶都有上限；执行器逐个 `recover()`，panic 不会传到宿主 |
| **数据库冲突** | 表名撞车 | 所有表加 `hx_` 前缀；goose 版本表命名为 `hx_goose_db_version` |
| **启动和关闭顺序** | 宿主重启时运行中断 | `Run` 启动时做崩溃恢复，从检查点续跑；`Shutdown` 先拒绝新运行，等安全点写完检查点，超时后硬取消，状态记为 `cancelled(cause=shutdown)`，下次启动可以续跑 |
| **多副本部署** | 两个宿主副本同时调度同一个运行 | 第一阶段要求只有一个副本开启调度（`Config.Scheduler=true`），其余副本只提供 API；租约机制见 04 号 §6 |

### 1.4 存储选择

| 情况 | 方案 |
|---|---|
| 宿主没有数据库，或者不想共用（默认） | `DataDir/harness.db`，独立 SQLite（WAL） |
| 宿主已有 Postgres，希望统一运维 | 传入 `Deps.DB`，引擎走 Postgres 实现（原计划在 M5，**现在提前到 M2 末**，任务 M2-18）。所有表加 `hx_` 前缀，放在独立 schema `harness` 中 |

## 2. 前端：嵌入宿主 Next.js 应用

### 2.1 目录（按宿主现有约定调整前缀，`src/` 是否存在都可以）

```
<宿主应用>/
├─ app/
│  └─ canvas/
│     ├─ layout.tsx            加载字体和作用域令牌，包一层 <div className="hx-root">
│     └─ [graphId]/page.tsx    展开态和全屏态（服务端组件只负责取初始图文档）
└─ features/canvas/            ← 新增功能模块，自成一体
   ├─ index.ts                 对外只导出：CanvasCard、CanvasWorkspace、useCanvasTheme
   ├─ canvas/                  命令式渲染层（从旗舰 demo 的 src/ 迁移）
   ├─ components/              面板、控件（React）
   ├─ state/                   zustand：createGraphStore() 等工厂函数
   ├─ protocol/gen/            schema 生成的 TS 类型
   ├─ protocol/client.ts       REST 和 SSE 客户端
   ├─ lib/runBridge.ts         高频事件按 rAF 合并后直接写画布
   └─ styles/tokens.scoped.css 由 tokens.css 构建得到（见 2.3）
```

### 2.2 和宿主对话的衔接

| 形态 | 实现 |
|---|---|
| **卡片**（对话消息里） | 宿主渲染对话消息时，遇到 harness 返回的画布消息类型，就渲染 `<CanvasCard graphId runId />`。卡片只读，用 canvas 绘制缩略图，订阅运行事件 |
| **展开**（中间栏） | 在对话页内用 FLIP 展开，**不跳路由**，这样对话上下文和输入框都保留。URL 用 `?canvas=<graphId>` 浅更新，刷新后能恢复 |
| **全屏 / 直接打开** | 跳转到 `/canvas/[graphId]` |

**每个画布一个 store 实例**：对话里可能同时出现多张卡片，所以 zustand 不能用全局单例，而是用 `createStore()` 工厂函数加 React Context，每个 `CanvasCard`、`CanvasWorkspace` 各自持有一份。

### 2.3 样式隔离与主题

- **令牌作用域化**：构建脚本把 `tokens.css` 里的 `:root, [data-theme="light"]` 改写成 `.hx-root, .hx-root[data-theme="light"]`，生成 `tokens.scoped.css`。这样 `color-scheme` 和变量都不会影响宿主的其他页面。变量本来就带 `--hx-` 前缀，不会和宿主撞名。
- **class 前缀**：组件 class 全部是 `hx-` 前缀的 BEM 写法。如果宿主用了 Tailwind 的 preflight，它会重置 `button`、`input` 的样式，`.hx-root` 下的基础样式会显式补回来，见设计规范 docs/10。
- **字体**：用 `next/font/google` 加载 Geist、Geist Mono、Noto Sans SC（中文按需子集），Next 会自动托管到本站，内网环境也能用。只在 `app/canvas/layout.tsx` 和 `CanvasCard` 里引入。
- **主题桥接**：`useCanvasTheme()` 读取宿主的主题（`next-themes` 的 `resolvedTheme`，或 `<html class="dark">`），同步到 `.hx-root[data-theme]`。**宿主没有主题系统时默认浅色。**
- **SSR**：画布用 `dynamic(() => import('…'), { ssr: false })` 引入。

### 2.4 请求路径

| 请求 | 方案 |
|---|---|
| REST | 同源时直接请求 `/api/harness/v1/...`；不同源时，用 `next.config` 的 `rewrites` 代理到宿主服务 |
| SSE | **推荐让浏览器直连宿主服务**（同站子域，CORS 加 `credentials`），不经过 Next 代理。如果必须经代理：自托管的 Next rewrites 可以流式转发，但前面有 nginx 时要设置 `proxy_buffering off`；部署在会缓冲响应的托管平台上时，必须直连 |
| 鉴权 | 沿用宿主的 cookie 或 token。`EventSource` 同源时会自动带 cookie；跨源时用 `withCredentials: true`；如果宿主用 Bearer token，就用 `fetch` 流式实现 SSE 客户端（`protocol/client.ts` 已封装） |
