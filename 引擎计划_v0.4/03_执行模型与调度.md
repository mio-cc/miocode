## 1. 运行的生命周期

```
POST /graphs/{id}/runs
   │
   ▼
[created] ── 冻结快照（graph_version + 解析后的 NodeDef + Mandate 快照）
   │
   ▼
[running] ── 调度器循环：就绪判定 → 入队 → 取令牌 → 执行器 → 写事件
   │   ├── 某节点 waiting（人工 / 审批）→ 运行整体仍是 running，只是该支路挂起
   │   ├── 用户暂停 → [paused]：不再派发新节点，正在执行的节点到下一个安全点停下
   │   └── 急停 / 取消 → [cancelling] → [cancelled]
   ▼
[succeeded] | [failed] | [cancelled]
```

| 运行状态 | 含义 | 进入条件 | 允许的下一个状态 |
|---|---|---|---|
| `created` | 已建，尚未调度 | 创建接口返回 | running, cancelled |
| `running` | 调度中 | 快照冻结完成 | paused, cancelling, succeeded, failed |
| `paused` | 不派发新节点 | 用户 / 模型（有权限）请求暂停 | running, cancelling |
| `cancelling` | 正在把取消传到所有节点 | 取消或急停 | cancelled |
| `succeeded` | 所有出口节点完成 | 根图出口全部 done/skipped | — |
| `failed` | 出现未被处理的失败 | 失败沿升级路由冒到根图仍无人处理 | — |
| `cancelled` | 已取消 | 所有节点进入终态 | — |

### 1.1 冻结快照
运行开始时把以下内容一起冻结，写入 `runs.snapshot`（内容寻址，见 04 §6）：

```go
type RunSnapshot struct {
    GraphID      string            `json:"graph_id"`
    GraphVersion int64             `json:"graph_version"`
    Graph        *graph.Graph      `json:"graph"`        // 展开后的根图（子图引用按 pin 解析）
    NodeDefs     map[string]string `json:"nodedefs"`     // type → nodedef 内容哈希
    Mandates     []authz.Mandate   `json:"mandates"`     // 运行开始时生效的授权书
    Inputs       map[string]any    `json:"inputs"`       // 根图入口端口的值
    Budget       Budget            `json:"budget"`
    Seed         int64             `json:"seed"`         // 供需要随机的执行器使用，回放一致
}
```

- **子图引用**：`pin=snapshot` 按版本取；`pin=link` 在冻结时解析到当时的最新版本并记下版本号。运行过程中不再跟随更新。
- 运行中的改图不改快照，而是生成"待应用补丁"，在安全点生效（§8）。

## 2. 节点状态机

```go
package run

type NodeState uint8

const (
    StIdle NodeState = iota
    StQueued
    StRunning
    StWaiting   // 等人工 / 审批 / 外部回调
    StDone
    StFailed
    StCancelled
    StSkipped
    StCached
)

func (s NodeState) Terminal() bool {
    return s == StDone || s == StFailed || s == StCancelled || s == StSkipped || s == StCached
}
```

### 2.1 合法转换表

| 从 \ 到 | queued | running | waiting | done | failed | cancelled | skipped | cached |
|---|---|---|---|---|---|---|---|---|
| idle | ✔ 输入就绪 | | | | | ✔ | ✔ 上游未激活 | ✔ 命中缓存 |
| queued | | ✔ 拿到令牌 | | | | ✔ | | |
| running | ✔ 重试回排 | | ✔ Ask/人工 | ✔ | ✔ | ✔ | | |
| waiting | | ✔ 审批通过 / 回调到达 | | | ✔ 驳回 / 超时 | ✔ | | |
| failed | ✔ 用户手动重试 | | | | | | | |

```go
var legal = map[NodeState]uint16{ // 位图：允许进入的状态
    StIdle:    bit(StQueued) | bit(StCancelled) | bit(StSkipped) | bit(StCached),
    StQueued:  bit(StRunning) | bit(StCancelled),
    StRunning: bit(StQueued) | bit(StWaiting) | bit(StDone) | bit(StFailed) | bit(StCancelled),
    StWaiting: bit(StRunning) | bit(StFailed) | bit(StCancelled),
    StFailed:  bit(StQueued),
}

func (r *Run) transition(path Path, to NodeState, cause string) error {
    cur := r.state[path]
    if legal[cur]&bit(to) == 0 {
        // 非法转换：不 panic，记一条 engine.illegal_transition 事件并拒绝。
        r.emit(EvIllegalTransition{Path: path, From: cur, To: to, Cause: cause})
        return ErrIllegalTransition
    }
    r.state[path] = to
    return r.emit(EvNodeState{Path: path, From: cur, To: to, Cause: cause})
}
```

规则：**状态只能由调度器改**。执行器通过 RunCtx 请求（Ask、Fail、返回结果），调度器统一落事件。这样事件日志是唯一事实来源，崩溃恢复时重放事件即可得到相同状态。

## 3. 数据流调度器

### 3.1 就绪判定
节点就绪 = 以下全部满足：
1. 当前状态为 `idle`（或重试中的 `queued`）。
2. 所有**必填**输入端口都有值；可选端口如果有连线，也要等上游到终态（done/skipped/cached）。
3. 所有入边的上游都已到终态。若某入边上游是 `skipped` 或分支未激活该出口 → 该边视为"未激活"。
4. 若**所有**入边都未激活 → 节点标记 `skipped`（向下游传播）。部分未激活：可选端口为空值，必填端口未激活 → `skipped`。
5. 所在作用域（循环本轮、扇出某份）处于活动中。

```go
func (s *Scheduler) readiness(p Path) readiness {
    n := s.node(p)
    allInactive, anyPending := true, false
    for _, e := range s.inEdges(p) {
        up := s.state(e.FromPath)
        switch {
        case !up.Terminal():
            anyPending = true
        case s.edgeActive(e):
            allInactive = false
        }
    }
    if anyPending { return notReady }
    if len(s.inEdges(p)) > 0 && allInactive { return skip }
    for _, port := range n.Def.RequiredInputs() {
        if !s.hasValue(p, port) { return skip }
    }
    return ready
}
```

### 3.2 调度循环

```go
type Scheduler struct {
    run      *Run
    ready    *prioQueue        // 就绪队列（小顶堆）
    global   *semaphore.Weighted
    pools    map[string]*Pool  // 资源池：llm:openai/gpt-x、tool:search …
    events   chan schedEvent   // 执行器完成、审批回调、取消、外部事件
}

func (s *Scheduler) Loop(ctx context.Context) error {
    s.seed()                                    // 首轮：入口节点、无入边节点
    for {
        s.dispatch(ctx)                         // 尽量多地派发
        select {
        case ev := <-s.events:
            s.handle(ev)                        // 落事件 → 更新状态 → 重新判定下游
        case <-ctx.Done():
            return s.cancelAll(ctx.Err())
        }
        if s.finished() { return s.finish() }
    }
}

func (s *Scheduler) dispatch(ctx context.Context) {
    for s.ready.Len() > 0 && !s.run.paused {
        item := s.ready.Peek()
        pool := s.pools[item.PoolKey]
        if !s.global.TryAcquire(1) { return }     // 全局并发满
        if pool != nil && !pool.TryTake() {       // 资源池令牌不足：留在队首，等令牌补充事件
            s.global.Release(1); return
        }
        s.ready.Pop()
        s.transition(item.Path, StRunning, "dispatch")
        go s.execute(ctx, item)                   // 执行器在独立 goroutine
    }
}
```

**单写者原则**：`Loop` 是运行状态唯一的写者，所有执行器 goroutine 只往 `s.events` 发消息。这样不需要细粒度锁，也保证事件顺序确定。

### 3.3 优先级
`prioQueue` 按以下键排序（小者优先）：

| 序 | 键 | 说明 |
|---|---|---|
| 1 | `escalationBoost` | 由升级处理派生的节点优先（0/1） |
| 2 | `critical` | 位于关键路径（下游节点数多）优先，冻结时预计算 |
| 3 | `round` | 循环轮次小的优先，避免跨轮饥饿 |
| 4 | `userPriority` | 节点参数 `priority`（P0–P2） |
| 5 | `seq` | 入队序号，保证稳定 |

### 3.4 资源池与令牌桶
每个模型和工具都属于一个资源池，同时受**并发上限**和**速率**两种限制：

```go
type Pool struct {
    Key         string
    Concurrency *semaphore.Weighted // 同时在飞的调用数
    Rate        *rate.Limiter       // golang.org/x/time/rate：每分钟 N 次
    Waiting     atomic.Int64        // 排队数，供前端显示背压
}
```

- 池按"模型资源节点的 provider+model"或"工具 ID"建立，配置来自宿主配置中的 `harness:` 段，节点参数可以调小、不能调大。
- 节点执行器里每次真正调用模型或工具时都要 `pool.Acquire(ctx)`。执行器级的 `TryTake` 只是派发前的粗过滤；执行器内一次运行可能多次调用模型（Agent 内部的工具循环）。
- 令牌不足时节点仍是 `running`，但发 `node.throttled` 事件，前端显示斜纹"排队"。

### 3.5 背压与有界队列
- 扇出、流式输出向下游传值时走**有界通道**（默认容量 = 下游并发 × 2）。通道满时上游的 `Emit` 阻塞，形成背压。
- 就绪队列本身不设上限，但扇出一次性产生的子任务数受 `fanout.max_items`（默认 1000）限制，超出则节点失败并升级。

## 4. Executor 接口与 RunCtx

```go
package exec

type Executor interface {
    Kind() string                                       // "Agent"、"扇出"…
    Validate(n *graph.Node, g *graph.Graph) []graph.Diag // 图检查阶段调用
    Run(rc RunCtx, in Inputs) (Outputs, error)
}

// 可选能力
type Resumable interface { Resume(rc RunCtx, cp Checkpoint) (Outputs, error) } // 从检查点继续
type Cacheable interface { CacheKey(n *graph.Node, in Inputs) (string, bool) }  // 返回 false 表示不缓存

type Inputs  map[string]Value
type Outputs map[string]Value

type Value struct {
    Type   types.Ref       `json:"type"`
    Data   json.RawMessage `json:"data,omitempty"`
    Ref    string          `json:"ref,omitempty"`    // ws://sha256/...，大内容走指针
    Taint  bool            `json:"taint,omitempty"`  // 来自外部内容
    Partial bool           `json:"partial,omitempty"`
}
```

```go
type RunCtx interface {
    context.Context                       // 取消与超时
    Path() Path                           // 根图/闭环迭代#r2/执行池/执行者#3
    Node() *graph.Node
    Params() Params                       // 已合并：定义默认值 ← 实例参数 ← 转端口的输入
    Seed() int64

    Emit(port string, v Value) error      // 流式输出；阻塞即背压
    Progress(frac float64, note string)   // 0–1，前端进度条
    Log(level slog.Level, msg string, kv ...any)

    Checkpoint(state any) error           // 写检查点（见 04 §5）
    Escalate(e Escalation) error          // 走升级端口，不终止节点
    Ask(req ApprovalReq) (ApprovalResp, error) // 阻塞：节点进入 waiting，直到审批结果

    Budget() BudgetView                   // 剩余 tokens / 时间 / 调用次数
    Charge(u Usage) error                 // 记账；超出预算返回 ErrBudgetExceeded

    LLM(ref string) (llm.Client, error)   // 已套好资源池、授权、计量
    Tool(id string) (tools.Handle, error)
    Workspace() ws.Store                  // 读写 ws:// 对象
    Ledger(scope string) ledger.Handle
    Subgraph(g *graph.Graph, in Inputs, opt SubOpts) (Outputs, error) // 循环、扇出、子图引用使用
}
```

**约定**
- 执行器**不得**直接访问 store、HTTP 或全局变量，所有外部能力都从 RunCtx 拿。这样测试时可以注入 Fake。
- 返回 `error` 时必须用 §10 的错误类型包装，调度器据此决定重试、升级还是失败。
- `Ask` 阻塞期间执行器 goroutine 挂起；进程崩溃后恢复时，调度器从检查点调 `Resume`，并在 `ApprovalResp` 到达后继续（见 04 §6）。

## 5. 13 个执行器的实现要点

| # | 执行器 | 是否调用模型 | 缓存默认 | 是否可恢复 | 子作用域 |
|---|---|---|---|---|---|
| 1 | 资源 | 否 | always | — | — |
| 2 | Agent | 是 | never | 是（工具循环中途） | — |
| 3 | 上下文装配 | 可选（summarize） | auto | — | — |
| 4 | 工具 | 否 | L0 按请求 TTL | 是（幂等键） | — |
| 5 | 扇出 | 否 | — | 是（按份） | 每份一个 |
| 6 | 汇合 | 否 | — | — | — |
| 7 | 聚合 | 否 | always | — | — |
| 8 | 分支 | 否 | always | — | — |
| 9 | 循环 | 否 | — | 是（按轮/按事件） | 每轮一个 |
| 10 | 账本 | 否 | never | — | — |
| 11 | 人工 | 否 | never | 是（挂起） | — |
| 12 | 子图端口 | 否 | — | — | — |
| 13 | 子图引用 | 否 | — | 是 | 子图一个 |

### 5.1 资源
- 把 `params.value` 校验为 `kind` 对应的 schema，输出 `资源引用<kind>`。
- 模型资源**只输出引用**（`{provider, model, sampling}`），密钥不进值，也不进事件（见 05 §7）。
- 列表资源支持 `source=file|library`，冻结时解析并按内容哈希存入工作区。

### 5.2 Agent
```go
func (a *Agent) Run(rc exec.RunCtx, in exec.Inputs) (exec.Outputs, error) {
    pkt := in["context"].MustContextPacket()           // 上下文包，必须来自装配节点（内核锁）
    cli, _ := rc.LLM(in["model"].Ref)
    prompt := ctxasm.Render(pkt, rc.Params())           // 六段已在装配节点算好，这里只拼成消息
    tools := rc.ToolsFromPorts("tools")                 // 只有连线进来的工具（连线即授权）

    var st agentState                                   // 可从检查点恢复
    for turn := st.Turn; turn < rc.Params().Int("limits.inner_turns"); turn++ {
        resp, err := cli.Complete(rc, llm.Req{Messages: prompt.WithHistory(st.Msgs),
            Tools: tools.Specs(), Output: rc.Params().Schema("output_schema")})
        if err != nil { return nil, classify(err) }
        rc.Charge(resp.Usage)
        if len(resp.ToolCalls) == 0 {
            v, err := structured.Decode(resp, rc.Params().Schema("output_schema"), a.repair(rc))
            if err != nil { return nil, exec.Retryable(err) }
            return exec.Outputs{"result": v}, nil
        }
        st.Msgs = append(st.Msgs, resp.AsMessage())
        for _, tc := range resp.ToolCalls {             // 工具调用；L2+ 走授权（可能 Ask）
            out := tools.Call(rc, tc)
            st.Msgs = append(st.Msgs, out.AsMessage())  // 工具结果已裁剪并带原文指针
        }
        st.Turn = turn + 1
        rc.Checkpoint(st)                               // 每轮工具循环后存一次
    }
    return nil, exec.Escalation("inner_turns_exhausted")
}
```
- `lifecycle=resident`：执行器不在 Run 返回后销毁，而是挂在循环（event 模式）里，每次事件唤醒时由 ctxasm 按 `memory_policy` 重建上下文（见 06 §7）。
- 输出通过 `output_mode=stream` 时，每个 token 片段通过 `Emit` 发给下游可流式的端口；最终值仍然以一次完整 `result` 结束。

### 5.3 上下文装配
- 调用 `ctxasm.Assemble(recipe, sources, targetModel)`，输出 `上下文包` 和 `dropped` 指针列表，具体见 06。
- `on_overflow=summarize` 时通过 `summarizer` 端口的模型调用，计入本节点成本。
- 缓存键 = 配方哈希 + 各输入值哈希 + 目标模型窗口。

### 5.4 工具
- `mode=endpoint`：执行器本身不调用，只输出一个工具端点句柄；真正调用发生在 Agent 内部。
- `mode=direct`：调用一次。幂等键 = `run_id/path/attempt_key`，其中 `attempt_key` 默认是请求体哈希。L1+ 工具若事件日志里已有该键的成功结果，**直接返回记录值，不再调用**（04 §6.3）。
- 调用前 `authz.Check(tool.call)`；L3 在图检查阶段已经要求前面接人工节点。

### 5.5 扇出
```go
func (f *Fanout) Run(rc exec.RunCtx, in exec.Inputs) (exec.Outputs, error) {
    items := f.items(in)                                     // items 或 n
    sem := semaphore.NewWeighted(int64(rc.Params().Int("concurrency")))
    results := make([]exec.Value, len(items))
    g, gctx := errgroup.WithContext(rc)
    for i, it := range items {
        if done, ok := f.cp.Done[i]; ok { results[i] = done; continue } // 恢复：已完成的份不重跑
        i, it := i, it
        g.Go(func() error {
            if err := sem.Acquire(gctx, 1); err != nil { return err }
            defer sem.Release(1)
            sub := f.bodyWithVary(i)                          // vary：改 body 里某参数路径
            out, err := rc.Subgraph(sub, f.shardInputs(in, it), exec.SubOpts{
                Scope: fmt.Sprintf("#%d", i), Isolated: rc.Params().Bool("isolation"),
                Budget: f.split(rc.Budget(), i, len(items))})
            if err != nil && f.onFail() == "skip" { results[i] = exec.Null(); return nil }
            results[i] = out["out"]
            f.cp.Done[i] = results[i]; rc.Checkpoint(f.cp)
            return err
        })
    }
    err := f.collect(g, results)                              // wait: all / k_of_n / timeout
    return exec.Outputs{"results": exec.List(results), "meta": f.meta()}, err
}
```
- **隔离**：每份有独立的局部账本和独立上下文；`isolation=false` 时共享本层账本，但仍然不会共享 Agent 历史。
- **collect**：`k_of_n` 拿到 K 份即取消其余份（取消传播，§6）；`timeout` 到时取已完成的，未完成的标为 `partial`。
- `budget_split`：`equal` 平分；`on_demand` 共享一个池，先到先用；`weighted` 按 `vary` 中的权重分配。

### 5.6 汇合
- 动态插口 `in_*`；`wait=all|k_of_n|first|timeout`。`first` 拿到首个值后，向其余未完成上游发**软取消**（只取消仅为本汇合服务的上游支路，见 §6.2）。
- `shape=dict` 时以插口名为键。

### 5.7 聚合（确定性）
- 内置算子：`count group ratio vote dedupe sort top_k filter concat stats divergence`。
- 表达式和自定义脚本都在**确定性沙箱**中运行：无时间、无随机、无 IO。脚本用 `expr-lang/expr` 编译后的程序，或第二阶段用 goja（JS）跑纯函数，禁止全局对象。
- `levels` 示例（闭环模板）：
```yaml
op: group_ratio
key: cluster
levels:
  - {name: 共识, when: "ratio == 1"}
  - {name: 多数, when: "ratio >= 0.66"}
  - {name: 独有, when: "count == 1"}
```

### 5.8 分支
- 表达式引擎选 **`github.com/expr-lang/expr`**：纯 Go、类型检查、可以编译缓存、可以禁用函数。
- 编译时只暴露 `value`（输入值的结构化字段）和 `round`、`meta` 等只读环境；通过 `expr.Env` 限制可用字段，禁止调用任意函数。
- `match=first` 激活第一个为真的出口；`all` 激活全部为真的出口。被激活出口记在该节点 `node.state`（to=done）事件的 `active_outs` 字段，调度器据此判定边是否激活。

### 5.9 循环
两种模式：

| | rounds | event |
|---|---|---|
| 驱动 | 上一轮出口 → 下一轮入口 | 事件源到达（端口数据、定时、账本 watch、外部回调） |
| 典型 | 闭环迭代 | 主脑（长驻） |
| 退出 | `exits` 表达式、`max_rounds`、`stall`、预算 | `exits`、`idle_timeout`、预算、运行取消 |
| 检查点 | 每轮结束 | 每个事件处理完 |

```go
for r := cp.Round + 1; ; r++ {
    if ex := l.checkExits(state, r); ex != "" { return l.out(state, ex) }
    l.applyPendingPatch(rc)                         // 安全点：运行中改图在这里生效（§8）
    out, err := rc.Subgraph(l.body, l.carry(state), exec.SubOpts{Scope: fmt.Sprintf("#r%d", r)})
    if err != nil { return nil, err }
    state = l.next(state, out)                      // 只保留 carry 指定的字段
    if l.stalled(state) { return l.out(state, "stall") }
    rc.Checkpoint(loopCP{Round: r, State: state})
}
```
- **carry**：只把 `carry.fields` 列出的字段带进下一轮，`carry_budget` 超出时按 `carry.policy` 压缩旧轮次（调用 summarizer）。
- **stall**：每轮计算 `stall.metric`（表达式，如 `len(gap.gaps)`），连续 `stall.rounds` 轮没有严格变好即退出。
- 内核强制至少一个有限出口；未配置时自动补 `max_rounds=10`，并在图检查里给警告。
- event 模式下事件进入循环自己的有界队列，按 `queue` 策略（优先级、合并键）排序；一次处理一个事件。

### 5.10 账本
- `op=read|write|append|cas|watch`。账本按作用域存储（`local` = 当前子图实例，`parent`，`named`）。
- **写入校验**：字段属性 `readonly_except`、`append_only`、`require_reason` 在这里由内核执行。
- `cas`：带读到的版本号写入，版本不符返回 `ErrConflict`（可重试错误）。
- `watch`：注册订阅，字段变化时向所在 event 循环投递 `ledger.changed` 事件。

### 5.11 人工
- 调用 `rc.Ask(...)`；节点进入 `waiting`，生成 `approvals` 记录，前端和对话同时显示。
- 结果到达 → `running` → 按 outcome 激活对应出口。`timeout` 到期 → 走 `on_timeout` 指定的出口，或失败。
- 挂起期间进程可以重启：审批记录在库里，恢复后节点保持 waiting，结果到达时继续。

### 5.12 子图端口
- `entry`：把父级传入的值作为本层入口值发出。`exit`：收集值交还父级。
- `summary`：在 `trigger` 满足时生成简报值，经父级子图引用节点的 `summary` 输出向上发；超出 `max_chars` 由 summarizer 压缩。
- `escalation`：按 `routes` 决定在本层路由到某节点，或冒泡给父级（§10）。

### 5.13 子图引用
- 解析 `ref@版本`；`overrides` 替换内部资源、配方、策略引用；`exposed` 覆盖可暴露参数。
- **作用域**：新建子作用域，局部账本隔离；只把子图 `writeback` 声明的字段写回父账本。
- **预算划拨**：从父预算切出 `budget` 额度给子图；子图超额 → `ErrBudgetExceeded` → 升级。
- **权限**：子图有效授权 = 父级生效授权 ∩ grant ∩ 子图声明需求（authz 计算，见 07）。
- **深度**：路径深度超过 `max_depth`（内核上限 8）直接失败；递归引用在图检查阶段拒绝。
- `ref` 转成端口时（模型自主编排），收到的图先过 `graph.Validate` 和 `authz.CheckGraph`，再挂载执行；生成的图写入事件日志（见 10）。

## 6. 取消与暂停的传播

### 6.1 Context 树
```
runCtx (WithCancelCause)
 └─ nodeCtx 根图/闭环迭代         ← 循环
     └─ scopeCtx #r2               ← 本轮
         └─ nodeCtx 执行池          ← 扇出
             ├─ scopeCtx #0 → nodeCtx 执行者 → llmCallCtx
             └─ scopeCtx #1 → …
```
- 每个节点执行、每个子作用域、每次模型或工具调用都派生自上一级 context。取消上级即自动传到下级。
- `context.Cause` 记录原因：`user_cancel`、`emergency_stop`、`k_of_n_satisfied`、`timeout`、`budget`，写进每个被取消节点的 `node.state`（to=cancelled）事件。

### 6.2 软取消与硬取消
| 类型 | 触发 | 行为 |
|---|---|---|
| 硬取消 | 用户取消、急停、预算耗尽 | 立即 cancel context；模型流式请求中断；正在执行的工具若不可中断则等待其返回但丢弃结果 |
| 软取消 | `k_of_n` 满足、汇合 `first` | 只取消"仅服务于被满足节点"的上游支路（冻结时计算支配关系），共享上游不受影响 |

### 6.3 暂停
- 暂停不 cancel context。调度器停止派发；执行器在调用 `rc.LLM/Tool/Emit/Checkpoint` 时检查暂停标志并阻塞（即"安全点"）。
- 继续 → 释放阻塞。暂停超过 `pause_timeout`（默认 24h）→ 自动取消。

## 7. 超时、重试、幂等

| 层 | 默认 | 配置位置 |
|---|---|---|
| 单次模型调用 | 120s | 模型资源 `timeout` |
| 单次工具调用 | 60s | 工具节点 `config.timeout` |
| 节点执行 | 300s | 节点 `limits.timeout` |
| 运行整体 | 无 | 运行参数 `budget.time` |

重试策略按错误类别（§10）：
```go
type RetryPolicy struct {
    Max      int           // 默认 2
    Base     time.Duration // 1s
    Factor   float64       // 2
    Jitter   float64       // 0.2
    On       []ErrClass    // 默认 [Transient, RateLimited, FormatInvalid]
}
```
- 节点重试时 `attempt` 加 1，状态 `running → queued → running`，事件记录每次尝试。
- **幂等键**：`{run_id}/{path}/{attempt_key}`。`attempt_key` 对 direct 工具默认是请求哈希，对 Agent 内部工具调用是 `turn/index`。重试同一节点时幂等键不变，所以有副作用的工具不会重复执行。

## 8. 安全点与运行中改图

1. 运行中收到对该图的 Op（人或模型），Op 先照常提交到图的新版本。
2. 运行订阅图变更；对影响本次运行的 Op，计算"可热更新补丁"：
   - 只改参数（例如并发、模型、轮数）→ 可热更新。
   - 增删节点、连线、改子图结构 → 仅当变更全部位于某个**循环体**或**事件循环体**内部时可热更新。
   - 其他 → 不热更新，只在下次运行生效，并通知前端。
3. 补丁挂到目标循环的 `pendingPatch`，在下一轮开始（或下一个事件）时 `applyPendingPatch` 应用，写事件 `run.graph_swapped{op_ids, at_round}`。
4. 正在执行的节点永不被改动。

## 9. 流式输出与部分结果

- 端口声明 `stream: true` 的输出可以多次 `Emit`；下游端口也声明 `stream: true` 时，下游节点在**第一个片段到达**即可就绪（流式就绪），否则等最终值。
- 片段事件 `node.chunk` **不落持久化**（只走 SSE，可配置采样落盘），最终值落 `node.output`。
- 部分结果：超时或 `k_of_n` 时，节点以 `Partial=true` 的值结束，状态仍为 `done`，事件带 `partial: true`；下游可以用表达式 `value.partial` 判断。

## 10. 错误分类与升级路由

```go
type ErrClass uint8
const (
    ErrTransient      ErrClass = iota // 网络、5xx：重试
    ErrRateLimited                    // 429：按 Retry-After 重试
    ErrFormatInvalid                  // 结构化输出不合格：修复后重试
    ErrBudgetExceeded                 // 预算：升级
    ErrAuthDenied                     // 授权拒绝：升级
    ErrNeedsApproval                  // 需审批：转 waiting（不是失败）
    ErrUserInput                      // 参数/图错误：失败，不重试
    ErrStructural                     // 目标结构性无法达成（执行器主动报）：升级
    ErrInternal                       // 引擎 bug：失败 + 告警
)
```

处理顺序：**重试 → 本层升级路由 → 冒泡 → 根图失败**。

```go
func (s *Scheduler) onError(p Path, err error) {
    c := exec.Class(err)
    if s.retry.Should(p, c) { s.requeue(p); return }
    esc := exec.ToEscalation(p, err)                  // 升级@1：kind, severity, question, options
    for scope := s.scopeOf(p); scope != nil; scope = scope.Parent {
        if route := scope.EscalationPort.Match(esc); route != nil {
            if route.To == "bubble" { continue }
            s.deliver(route.To, esc)                  // 交给本层某节点（如决策者）处理
            s.transition(p, StFailed, "escalated_handled")
            return
        }
    }
    s.toRootQueue(esc)                                // 根级升级队列：主脑 / 用户
    s.transition(p, StFailed, c.String())
}
```

- 升级 `merge_key` 相同的在队列里合并计数，不重复打扰。
- 失败节点的下游：必填输入缺失 → `skipped`；运行最终是否 `failed` 取决于根图出口是否都有结果。
