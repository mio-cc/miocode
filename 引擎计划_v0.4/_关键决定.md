# 引擎计划 · 关键决定（所有计划文档必须一致遵守）

> **v0.4.1 已定（2026-11-21）**：① 引擎**嵌入现有 Go 服务**，不再单独起进程；② 前端**嵌入现有 Next.js 应用**，作为 `/canvas` 路由模块，并提供可以嵌进对话的 `<CanvasCard>`；③ 首批模型为 **OpenAI 兼容、Anthropic、Gemini**。具体见 [15_嵌入集成方案.md](15_嵌入集成方案.md)，本文中与之冲突的内容以 15 号为准。


> 这份是写计划用的共享底稿。13 份详细文档都以这里为准；需要偏离时，在文档里写明理由。

## 技术栈
- 前端：Next.js（App Router，TypeScript，React）。画布是 'use client'，拖拽和缩放绕过 React 渲染（见设计规范 docs/17、18）。
- 后端：Go 1.23+。
- 引擎内核 `harness/engine/` 是一个**可嵌入的 Go 库**，不依赖 HTTP，也不依赖宿主；`harness/api` 提供 HTTP + SSE（`http.Handler`），由 `harness/host` 组装后**挂载到现有 Go 服务的路由上**。
- 存储：第一阶段 SQLite（modernc.org/sqlite，纯 Go，免 CGO），通过 `store` 接口抽象，后续可换 Postgres。
- 所有 ID 用 ULID；时间一律 UTC，展示时转本地时区。

## 核心模型
- **图文档（Graph Doc）**：JSON，由 JSON Schema（`schema/graph.schema.json`）定义，前后端共用。TS 类型和 Go 结构体都从 schema 生成，不手写。
- **Op**：唯一修改入口。字段 `{id, kind, actor, mandate_id, reason, target, payload, base_version, taint, ts}`，每种 Op 都有 inverse。流水线：校验 → 授权 → 图检查 → 应用 → 写事件 → 广播。
- **运行（Run）**：每次运行把当时的图冻结成一份快照（`graph_version`）。运行中改图在**安全点**生效，安全点是循环的下一轮或事件的下一次。
- **事件溯源**：运行状态的唯一来源是追加写入的事件日志 `run_events`，节点状态、时间线、留痕都从它投影出来。断点续跑 = 重放事件 + 从最近检查点恢复。
- **节点执行器接口**（Go）：
  ```go
  type Executor interface {
      Kind() string
      Validate(n *Node, g *Graph) []Diag
      Run(ctx RunCtx, in Inputs) (Outputs, error)   // 可多次 Emit 流式输出
  }
  ```
  13 个原子节点各有一个内置执行器；自定义节点（script/prompt/http/mcp/子图）也走同一个接口。
- **节点状态机**：idle → queued → running → (done | failed | waiting | cancelled | skipped | cached)，waiting → running。
- **调度**：数据流驱动。节点所有必填输入就绪就进入就绪队列；全局有并发上限，每个资源池（模型、工具）有独立配额，用令牌桶限流，超出排队（背压）。
- **有副作用的工具**（L1 以上）必须带幂等键 `run_id/node_path/attempt_key`。

## 通信
- 前端 → 后端：REST（JSON）。Op 用 `POST /graphs/{id}/ops`，带 `base_version`，版本冲突返回 409 和最新版本，前端走合并或转成草稿。
- 后端 → 前端：**SSE**（`GET /runs/{id}/events?since=seq`）推送运行事件；图协同编辑的广播也走 SSE（`/graphs/{id}/stream`）。选 SSE 的理由：单向推送足够，自动重连，`Last-Event-ID` 天然支持断线续传，经过代理更容易。双向实时的需求以后再评估是否换 WebSocket。
- 事件信封：`{seq, run_id, ts, kind, path, data}`，`path` 是层级路径 ID，例如 `根图/闭环迭代#r2/执行池/执行者#3`。

## 模型与工具
- 模型适配层 `llm/`：统一接口 `Complete(ctx, Req) (Stream, error)`，屏蔽各厂商差异。结构化输出的优先级：原生 JSON schema > 工具调用 > 文本解析加修复。首批接 3 家：OpenAI 兼容接口、Anthropic、Gemini（官方 SDK `google.golang.org/genai`）；国内厂商和本地模型走 OpenAI 兼容接口。
- 工具层 `tools/`：内置检索、HTTP、文件、代码执行（沙箱子进程，第一阶段可以先不做），以及 **MCP 客户端**，接入任意 MCP 服务器作为工具节点。
- 每个工具注册时声明风险等级 L0–L3。

## 授权
- 五档：0 只读、1 建议、2 部分、3 高度、4 完全。授权书（Mandate）是一种文档，可以按对象（会话、图、子图、节点）挂载，向下继承，子级可以覆盖。
- 每个 Op 和每次工具调用都要调用 `authz.Check(actor, action, target, ctx) Decision`，结果是 allow、ask（需要审批）或 deny。
- 污染标记：由外部内容引出的 Op 和工具调用带 `taint=true`；开启时一律转为 ask。
- 急停：服务级的全局开关，以及每次运行各自的开关。模型无权调用急停的解除接口。
- 所有决策都写进审计日志。

## 模型自主编排
- 编排者 = 上下文装配 → Agent（output_schema = `GraphPatch`，tools = 图操作工具）→ 子图引用（ref 由端口传入）。
- GraphPatch 就是一组 Op，提交时同样走 Op 流水线和授权检查。1 档时生成提议（`proposal`），不直接生效。
- 运行时由模型生成的图写入事件日志，回放时直接使用记录下来的图。

## 里程碑
- **M0 地基（2 周）**：schema、代码生成、仓库骨架、存储接口、CI
- **M1 能跑的最小闭环（3 周）**：图的增删改与 Op、调度器、资源/Agent/上下文装配/工具/分支/汇合 6 个执行器、1 家模型适配、SSE 事件流、前端画布能看到真实运行状态
- **M2 完整节点集（3 周）**：扇出、聚合、循环、账本、人工、子图端口、子图引用；检查点与断点续跑；Anthropic 和 Gemini；MCP 工具；宿主使用 Postgres 时提供对应实现
- **M3 授权与安全（2 周）**：授权书、五档、审批流、污染标记、急停、审计
- **M4 模型自主编排（3 周）**：GraphPatch、提议与幽灵节点、运行时展开、运行后优化、评测子图
- **M5 观测与打磨（2 周）**：时间线与时间旅行、成本计量、OpenTelemetry、性能压测、Postgres 适配

以上工期按 1–2 名全职开发估算。
