# 00 引擎实施计划 · 总览

> 版本 v0.4 草案 · 技术栈：前端 Next.js（App Router, TS）+ 后端 Go 1.23+
> 共享底稿：`_关键决定.md`。本组文档与它冲突时，以底稿为准并回来修正本文。

## 1. 引擎要做成什么

一句话：**把画布上的图真正跑起来，而且能让人和大模型用同一套操作去改它、跑它、看它。**

| 能力 | 第一阶段要达到的程度 |
|---|---|
| 图存储与编辑 | 图文档持久化；所有修改都是 Op，带版本、可撤销、可分支合并 |
| 执行 | 13 个原子节点全部可执行；数据流调度；循环、扇出、子图嵌套；并发与资源配额 |
| 长时运行 | 事件溯源 + 检查点；进程重启后能接着跑；人工审批可挂起一天 |
| 模型与工具 | 3 家模型（OpenAI 兼容、Anthropic、Gemini）；内置检索/HTTP/文件；任意 MCP 服务器 |
| 上下文 | 提示词六段自动拼装；配方驱动装配；预算与溢出策略 |
| 授权 | 五档授权按对象挂载；审批流；污染标记；急停；审计 |
| 模型自主编排 | 模型输出 GraphPatch；1 档提议、≥2 档直接生效；运行时展开子图；回放可复现 |
| 观测 | 层级路径 ID；事件流实时推到画布；时间线、成本、留痕、单节点重放 |

## 2. 第一阶段不做什么

| 不做 | 原因 / 什么时候再做 |
|---|---|
| 多租户、团队权限、SSO | 先单用户本地 token；M5 之后 |
| 分布式调度（多机 worker） | 内核接口预留，单进程先跑通；`store` 换 Postgres 后再评估 |
| 实时多人光标协同（CRDT） | 用 Op + 乐观锁 + SSE 广播已够用；人与模型并发靠草稿分支 |
| 代码执行的强隔离沙箱 | M2 只做子进程 + 超时 + 目录限制，标记为 L2；强沙箱（gVisor/Firecracker）后置 |
| 可视化的类型/节点编辑器 | 先用 YAML/JSON 注册扩展；前端只读展示 |
| 移动端 | 不做 |

## 3. 整体架构

```
┌──────────────────────────── 浏览器 ────────────────────────────┐
│ 宿主 Next.js 应用 /canvas（'use client' 画布）                               │
│  canvas/ 命令式渲染层 ── state/ (zustand) ── lib/protocol 客户端 │
└──────────────┬──────────────────────────────▲──────────────────┘
       REST (JSON, Op 提交)            SSE (运行事件 / 图广播)
               │                              │
┌──────────────▼──────────────────────────────┴──────────────────┐
│ 宿主 Go 服务 + harness/host（挂载）                                         │
│  internal/api  路由/鉴权/幂等      internal/sse  订阅/续传       │
└──────────────┬─────────────────────────────────────────────────┘
               │ 进程内调用（engine 是库）
┌──────────────▼─────────────────────────────────────────────────┐
│ engine/                                                         │
│  graph · schema · op ──► authz ──► run ──► sched ──► exec/*      │
│                    │                 │           │              │
│                    │               ctxasm       llm ── tools ── mcp
│                   orch（模型编排，产出 Op）        │              │
│                    └────────── obs（事件/指标/留痕）─┘             │
│  store（接口） ─► sqlite 实现 / 以后 postgres                     │
└───────┬────────────────────┬─────────────────────┬─────────────┘
        │                    │                     │
   SQLite 文件          工作区 blobs          模型 API / MCP 进程
   (graphs, ops,        (内容寻址目录         (OpenAI 兼容,
    run_events…)         ws://sha256/…)        Anthropic, stdio/HTTP)
```

依赖方向只能自上而下；`engine` 不依赖 `internal/*` 和 HTTP。详见 01。

## 4. 运行一次的完整时序

```
用户         画布(宿主应用)    harness/api         engine/run+sched        exec/*            store           SSE
 │ 点运行 ▶     │                   │                    │                   │                 │               │
 │────────────►│ POST /runs        │                    │                   │                 │               │
 │             │ {graph_id,branch} │                    │                   │                 │               │
 │             │──────────────────►│ authz.Check(run)   │                   │                 │               │
 │             │                   │──────────────────► │ 冻结快照           │                 │               │
 │             │                   │                    │ graph_version=v42 │                 │               │
 │             │                   │                    │ Validate(图检查)  │                 │               │
 │             │                   │                    │──────────────────────────────────────►│ runs 行       │
 │             │◄──── 201 {run_id} │                    │                   │                 │               │
 │             │ GET /runs/{id}/events (SSE, since=0)   │                   │                 │               │
 │             │────────────────────────────────────────────────────────────────────────────────────────────► │
 │             │                   │                    │ 入口节点就绪      │                 │               │
 │             │                   │                    │ 令牌桶取配额      │                 │               │
 │             │                   │                    │──────────────────►│ Run(ctx,in)     │               │
 │             │                   │                    │                   │ ctxasm 装配     │               │
 │             │                   │                    │                   │ authz(tool)     │               │
 │             │                   │                    │                   │ llm.Complete    │               │
 │             │                   │                    │◄── Emit(进度/流)  │                 │               │
 │             │                   │                    │ append run_event ─────────────────────►│ seq=118       │
 │             │                   │                    │──────────────── publish ─────────────────────────────►│
 │             │◄──────────────────────────────────────────────────────────────── event: node.progress ─────────│
 │ 节点变橙/进度│ rAF 节流后直接改 DOM                    │                   │                 │               │
 │             │                   │                    │◄── Outputs        │                 │               │
 │             │                   │                    │ 下游就绪 → 循环   │                 │               │
 │             │                   │                    │ 检查点(每轮)  ─────────────────────────►│ checkpoints   │
 │             │                   │                    │ … 人工节点 → waiting，等 approvals …  │               │
 │ 点批准       │ POST /approvals/{id}/resolve           │                   │                 │               │
 │             │──────────────────►│──────────────────► │ 恢复该节点        │                 │               │
 │             │                   │                    │ 出口节点完成      │                 │               │
 │             │◄──────────────────────────────────────────────────────────────── event: run.status   ─────────│
```

要点：
1. **运行永远基于冻结的版本**。运行中改图产生新版本，只在安全点（循环下一轮、事件下一次）被 `run` 采纳，并发事件 `run.graph_swapped`。
2. **状态的唯一来源是 `run_events`**。前端看到的节点状态、时间线、成本全是投影。
3. **任何外部动作前都要过 `authz.Check`**：Op、工具调用、模型换档、子编排者创建。

## 7. 关键风险 Top 10

| # | 风险 | 影响 | 对策 | 文档 |
|---|---|---|---|---|
| 1 | 类型系统过度设计，拖慢 M1 | 高 | M1 只实现名义类型 + 任意 + 列表展开；继承与版本迁移放 M2 | 02 |
| 2 | 循环 + 子图 + 扇出嵌套后调度器语义不清 | 高 | 子图/循环/扇出统一为"作用域运行"（child run scope），调度器只处理扁平图；写确定性测试 | 03 |
| 3 | 事件量过大（每 token 一条）拖垮 SQLite 和 SSE | 高 | 流式 token 不落库，只在内存广播；落库的是节流后的 progress（≤4 次/秒/节点）和终态 | 04、09 |
| 4 | 模型结构化输出不稳定导致大量重试 | 中 | 三级策略 + 自动修复 + 录制回放测试；失败走升级端口 | 05 |
| 5 | 崩溃恢复后有副作用工具重复执行 | 高 | 幂等键强制；工具调用"意图事件"先落库再执行 | 04、05 |
| 6 | 人与模型同时改图，冲突频繁 | 中 | 模型默认在草稿分支；可交换 Op 自动 rebase；冲突转草稿 | 08 |
| 7 | 4 档完全授权下的提示词注入 | 高 | 污染标记默认开；工具结果打 taint 并沿数据流传播 | 07 |
| 8 | 前端高频事件导致画布卡顿 | 中 | SSE 消费在 rAF 合并；节点状态直接改 DOM，不进 React | 09 |
| 9 | 代码生成链（Schema → Go/TS）工具不成熟 | 中 | M0 先做技术验证；必要时手写少量 Go 类型 + schema 测试保证一致 | 01、02 |
| 10 | 成本失控（模型自主加节点、循环跑满） | 中 | 预算是一等字段：运行/子图/节点三级额度，超出即挂起 | 03、10、11 |
