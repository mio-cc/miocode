# 13 里程碑与任务拆解

> **v0.4.1**：根据嵌入决定（15 号），调整了 M0-01、M0-06、M0-10，新增 M0-12、M2-17（Gemini）、M2-18（Postgres，原 M5-06 提前）；任务总数 88，合计 137 人天（逐项累加）。

> 按 1–2 名全职开发估算，共约 15 周。人天 = 1 名熟练工程师的有效工作日。
> 任务编号 `Mx-nn`；「包」对应 01 号文档的模块；「依赖」写任务编号；「验收」写可检验的标准。
> 前端任务的包名用 `web/…`。

## 总览

**演示脚本**：
1. 在对话里输入"帮我做一个竞品定价调研流程"，档位为 1。
2. 画布上逐个出现幽灵节点，用户点"全部采纳"。
3. 运行时 B 公司的数据查不到，编排者展开「换数据源」子图；其中发邮件的 L2 操作被挂起等待审批，用户批准。
4. 运行结束后点"优化"，模型给出 3 条补丁和评测对比：通过率 0.78 → 0.92。用户采纳。
5. 回放旧版本，结果完全一致。

**风险**：
- 模型生成的图质量不稳定。对策：草稿上的修复提示 + `run_subgraph` 试跑 + 评测门槛；编排者角色卡要用评测集反复迭代。
- 成本高。对策：编排使用独立预算；开发阶段全部用录制带。

## 关键路径

```
M0-02 schema → M0-03 codegen → M1-01/02/03 类型与校验 → M1-04/05 Op 流水线
   → M1-07/08 run + 调度 → M1-12 Agent 执行器 → M2-08 检查点 → M2-03 循环 → M2-07 子图
   → M3-04 Check 接入 → M4-04 补丁 → M4-06 提议 → M4-08 运行时展开 → M5-01 时间旅行
```

关键路径上的任何一项延期，都会直接推迟整体交付。**M2-08 检查点**和 **M4-06 提议**这两项最复杂，各自预留了 1 天缓冲。
