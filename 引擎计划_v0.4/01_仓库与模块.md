# 01 仓库与模块

> 目标：在宿主仓库里就能 `make dev` 拉起宿主服务（已挂载 harness）和宿主应用；包边界清晰，禁止循环依赖；engine 和宿主之间只通过 `harness/host` 的接口交互。

---

## 1. 目录树（嵌入宿主，v0.4.1）

> 引擎嵌入现有 Go 服务，前端嵌入现有 Next.js 应用，见 [15_嵌入集成方案.md](15_嵌入集成方案.md)。不再单独建 monorepo，也没有独立的 `cmd/harnessd` 进程。

**宿主 Go 仓库**

```

**宿主 Next.js 应用**

```
<宿主应用>/
├─ app/canvas/layout.tsx           # next/font 加载字体；作用域令牌；<div className="hx-root">
├─ app/canvas/[graphId]/page.tsx   # 展开态 / 全屏态
└─ features/canvas/                # 自成一体的功能模块
   ├─ index.ts                     # 对外只导出 CanvasCard / CanvasWorkspace / useCanvasTheme
   ├─ canvas/                      # 命令式渲染层（由旗舰 demo 的 src/ 迁移而来）
   ├─ components/  state/  lib/(runBridge.ts T.ts)
   ├─ protocol/gen/*.ts            # ← schema 生成
   ├─ protocol/client.ts  sse.ts
   └─ styles/tokens.scoped.css     # 由设计规范 tokens.css 构建：:root → .hx-root

schema 放在 Go 仓库的 `harness/schema/`。前端的生成物通过 `make hx-gen` 写进宿主应用的 `features/canvas/protocol/gen/`。如果两个仓库是分开的，就由 CI 发布一个 npm 包 `@<org>/harness-protocol`，宿主应用依赖它。

## 2. Go 包职责与核心接口

| 包 | 职责 | 依赖 |
|---|---|---|
| `harness/gen` | schema 生成的纯数据类型 | 无 |
| `engine/graph` | 内存图模型、索引（按 id、按端口反查）、遍历、深拷贝 | gen |
| `engine/schema` | NodeDef/类型注册表、类型兼容、T 推断、图检查、版本迁移 | gen, graph |
| `engine/op` | Op 应用、逆操作、rebase、三方合并、拖动合并 | gen, graph, schema |
| `engine/authz` | 授权书解析、Check、污染、急停 | gen, graph |
| `engine/store` | 持久化接口 + sqlite/mem 实现 | gen |
| `engine/blob` | 工作区内容寻址存储 | 无 |
| `engine/obs` | 事件信封、路径 ID、成本累计、指标 | gen |
| `engine/llm` | 模型适配 | obs |
| `engine/tools` | 工具注册与调用（含裁剪、指针） | blob, obs |
| `engine/mcp` | MCP 客户端，桥接为 tools.Tool | tools |
| `engine/ctxasm` | 上下文装配、提示词六段拼装 | schema, blob, llm(仅 token 计数) |
| `engine/exec/*` | 13 个执行器 | exec 接口、ctxasm、llm、tools |
| `engine/sched` | 就绪判定、并发、资源池、令牌桶、虚拟时钟 | graph, obs |
| `engine/run` | 运行生命周期、作用域、安全点、崩溃恢复 | sched, exec, store, authz, obs |
| `engine/orch` | GraphPatch、图操作工具、提议、运行时展开 | op, schema, authz, tools |
| `harness/api` | HTTP 路由、幂等、错误码（鉴权委托给 host.Authenticator） | engine/*, host |
| `harness/api/sse` | 订阅中心、续传、长连接适配 | obs, store |
| `harness/host` | 宿主接入层：组装 engine 和 api，定义 Deps 接口 | engine/*, api |

        harness/api      harness/api/sse
               \            /
                 engine/run ─────────── engine/orch
               /     |      \              |    \
       engine/sched  exec/*  authz        op    tools

            obs  ctxasm llm tools        schema  mcp
                    |        |             |
                 schema    blob          graph
                    \                     /
                     ─────── gen ────────
           store ───────────┘（store 只依赖 gen）

CI 用 `go list -deps` + 自写脚本 `harness/tools/depcheck` 校验：`harness/engine/**` 不得 import `harness/api`、`harness/host`、宿主的任何包，以及 `net/http`（`llm`、`tools/builtin/http`、`mcp/http` 例外）。

### 核心接口（Go）

```go
// engine/exec/executor.go
type Executor interface {
    Kind() string                                   // "Agent" / "扇出" …
    Validate(n *graph.Node, g *graph.Graph) []schema.Diag
    Run(ctx RunCtx, in Inputs) (Outputs, error)
}

type RunCtx interface {
    context.Context
    Path() obs.Path                                 // 根图/闭环迭代#r2/执行池/执行者#3
    Node() *graph.Node
    Emit(ev obs.Event)                              // 进度、流式片段
    Checkpoint(state []byte) error
    Escalate(e Escalation) error                    // 走升级端口
    Ask(req ApprovalReq) (ApprovalResult, error)    // 挂起等待审批
    Budget() *obs.Budget
    Authz() authz.Checker
    Blob() blob.Store
    LLM(ref string) (llm.Model, error)
    Tools() tools.Set                               // 只含连到本节点的工具（连线即授权）
    RunChild(scope ChildScope) (Outputs, error)     // 扇出/循环/子图用
}

// engine/store/store.go
type Store interface {
    Graphs() GraphRepo
    Ops() OpRepo
    Runs() RunRepo
    Events() EventRepo          // Append / Range(since) / Tail
    Checkpoints() CheckpointRepo
    Approvals() ApprovalRepo
    Mandates() MandateRepo
    Audit() AuditRepo
    Tx(ctx context.Context, fn func(Store) error) error
}

// engine/llm/llm.go
type Model interface {
    Complete(ctx context.Context, req Req) (Stream, error)
    CountTokens(msgs []Msg) (int, error)
    Window() int
}

// engine/tools/tool.go
type Tool interface {
    Name() string
    Risk() authz.Risk                // L0..L3
    Schema() json.RawMessage         // 参数 JSON Schema
    Call(ctx context.Context, req Call) (Result, error)
}
```

## 3. Next.js 侧结构要点

| 目录 | 规则 |
|---|---|
| `app/` | 路由与布局；服务端组件只负责取初始数据（图文档、会话），然后交给客户端组件 |
| `components/` | 面板、控件，普通 React，订阅 zustand 的**低频**切片（选中、面板开合） |
| `canvas/` | `'use client'`；`CanvasHost` 只在挂载时初始化命令式渲染器，之后 React 不再重渲染它；节点/连线/视口全部 ref 直改 DOM |
| `state/` | zustand：`graphStore`（图数据）、`uiStore`（选中、工具）、`runStore`（运行状态，**只存聚合**，高频状态走 canvas 直写）、`historyStore` |
| `protocol/` | schema 生成的类型和手写客户端；store 用 `createStore()` 工厂函数，每个画布实例各有一份（对话里可能同时有多张卡片） |

服务端组件 vs 客户端组件：画布、检查器、节点库、运行抽屉、对话输入全部 `'use client'`；`layout.tsx`、会话列表初始数据可为服务端组件。

## 4. 代码生成流水线

```
schema/*.schema.json
   ├─► Go:  github.com/omissis/go-jsonschema   →  harness/gen/*.go
   └─► TS:  json-schema-to-typescript           →  <宿主应用>/features/canvas/protocol/gen/*.ts
```

| 选项 | 结论 |
|---|---|
| Go 生成器 | **omissis/go-jsonschema**（维护活跃、支持 2020-12 主要关键字、可生成校验）。备选 atombender/go-jsonschema（原版，较旧）。M0 第 1 周做 PoC，若对 `oneOf`/判别联合支持不足，判别联合（Op、RunEvent）改为手写 Go 接口 + 生成的 payload 结构 |
| TS 生成器 | **json-schema-to-typescript**；判别联合生成为 union type |
| 运行时校验 | Go：`santhosh-tekuri/jsonschema/v6` 对入站 JSON 做 schema 校验；TS：`ajv`（仅开发态校验） |
| 一致性保障 | CI 跑 `make gen && git diff --exit-code`，生成物不一致即失败 |

### Makefile（并入宿主，目标统一加 hx- 前缀）

```makefile
HX_WEB ?= ../<宿主应用>          # 宿主 Next.js 应用的路径；同仓时改成相对目录

hx-gen:     ## 从 schema 生成 Go / TS
	go run github.com/omissis/go-jsonschema/cmd/gojsonschema -p gen \
	  --output harness/gen/types.go harness/schema/*.schema.json
	npx json-schema-to-typescript -i 'harness/schema/*.schema.json' -o $(HX_WEB)/features/canvas/protocol/gen
	node harness/tools/scope-tokens.mjs  > $(HX_WEB)/features/canvas/styles/tokens.scoped.css

hx-test:
	go test ./harness/... -race -count=1

hx-lint:
	golangci-lint run ./harness/...
	go run ./harness/tools/depcheck

dev:        ## 宿主原有的 dev 目标：宿主服务已挂载 harness，前端照常启动
```

## 5. 依赖库选型

| 用途 | 选型 | 理由 | 备选 |
|---|---|---|---|
| HTTP 路由 | `harness/api` 内部用标准库 `net/http` ServeMux（1.22+ 支持方法和路径模式），对外只暴露 `http.Handler` | 不把路由框架强加给宿主；chi、gin、echo 都能直接挂载 | `go-chi/chi/v5`（宿主本来就用 chi 时也可以） |
| SQLite | `modernc.org/sqlite` | 纯 Go，`CGO_ENABLED=0` 可交叉编译 | `mattn/go-sqlite3`（更快但需 CGO） |
| SQL 访问 | `database/sql` + 手写 SQL；查询生成用 `sqlc` | 迁移到 Postgres 时差异可控 | `sqlx` |
| 迁移 | `pressly/goose` | 支持嵌入 SQL 文件 | `golang-migrate` |
| ULID | `oklog/ulid/v2` | 有序、可排序、无协调 | `google/uuid` v7 |
| 表达式（分支） | `expr-lang/expr` | 安全、无副作用、可编译缓存 | `google/cel-go`（更重） |
| JSON Schema 校验 | `santhosh-tekuri/jsonschema/v6` | 2020-12 完整 | `xeipuuv/gojsonschema`（旧草案） |
| YAML | `goccy/go-yaml` | 带行号报错 | `gopkg.in/yaml.v3` |
| 日志 | 标准库 `log/slog` | 结构化、零依赖 | zerolog |
| 可观测 | `go.opentelemetry.io/otel` | 标准 | — |
| 指标 | `prometheus/client_golang` | 标准 | OTel metrics |
| 限流 | `golang.org/x/time/rate` | 令牌桶 | 自写 |
| Gemini | `google.golang.org/genai` | 官方 SDK，同时支持 Gemini API 和 Vertex AI | REST 直连 |
| MCP | `mark3labs/mcp-go` | 社区活跃，stdio/SSE/HTTP | 官方 Go SDK（若届时稳定优先换） |
| 测试 | `stretchr/testify`、`pgregory.net/rapid`（属性测试） | 常用 | `gopter` |
| 前端状态 | `zustand` | 体积小，可在 React 外 `getState/subscribe`，适合命令式画布 | jotai、valtio |
| 前端 e2e | Playwright | — | — |

## 6. CI

```yaml
# 并入宿主 CI（摘要）
jobs:
  harness-go:
    steps:
      - run: make hx-gen && git diff --exit-code
      - run: make hx-lint
      - run: go test ./harness/... -race -count=1 -coverprofile=cover.out
  harness-web:            # 在宿主应用仓库或目录中执行
    steps:
      - run: pnpm i --frozen-lockfile
      - run: pnpm lint && pnpm test -- features/canvas
      - run: pnpm build
  harness-e2e:
    needs: [harness-go, harness-web]
    steps:
      - run: 启动宿主服务（ci 配置，harness.DataDir=临时目录） &
      - run: 启动宿主应用 &
      - run: pnpm exec playwright test e2e/canvas
```

门禁：生成物一致；依赖方向检查（engine 不得依赖宿主）；`-race` 通过；`engine/op`、`engine/schema`、`engine/sched` 覆盖率 ≥ 80%；宿主应用的视觉回归中 `/canvas` 以外的页面无变化（样式隔离）。
