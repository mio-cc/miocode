# 04 持久化与断点续跑

> 对应包：`engine/store`（接口）、`engine/store/sqlite`（第一阶段实现）、`engine/run`（投影与恢复）、`engine/ws`（工作区）。
> 原则：**运行状态的唯一事实来源是 `run_events`**；节点状态、时间线、成本都是投影。图的唯一事实来源是 `ops` + `graph_versions`。

---

## 1. 事件溯源总体设计

```
            写                                   读
Op ──► ops（追加）──► graph_versions（快照，每 N 个 Op 或每次运行冻结）
Run ─► run_events（追加，seq 单调）──► 投影：node_state / timeline / cost（内存 + 物化表）
                                    └─► SSE（按 seq 推送，断线用 Last-Event-ID 续传）
        checkpoints（执行器内部状态，按 path 覆盖最新）
        ws 对象（内容寻址的大块数据：原文、上下文包、生成的图）
```

- **追加写、不改不删**（清理策略除外，§8）。
- 每个事件写入后才算发生：调度器先 `AppendEvents` 成功，再改内存状态、再推 SSE。保证"推给前端的一定已落盘"。
- 物化投影表（`run_node_state`）只是加速查询的缓存，可从事件全量重建。

## 2. SQLite 表结构

使用 `modernc.org/sqlite`。连接参数：`_pragma=journal_mode(WAL)&_pragma=synchronous(NORMAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(ON)`。

> **表的归属**：每张表只在一份文档里定义。`ops`、`branches`、`graph_versions`、`undo_stack` 归 08 号，`approvals`、`audit`、`mandate_bindings` 归 07 号（`mandates` 表在本文，字段语义见 07），`proposals` 归 10 号，`rolecards`、`experiences` 归 06 号，`tool_calls` 归 05 号；其余表归本文。迁移文件按归属拆分，命名为 `NNN_<所属包>_<表>.sql`。

-- 表 ops：结构以 08_Op与协同编辑.md 为准，这里不重复定义。
CREATE INDEX ops_graph_ts ON ops(graph_id, ts);

-- 表 graph_versions：结构以 08_Op与协同编辑.md 为准，这里不重复定义。

-- 运行

  graph_version INTEGER NOT NULL,

  started_by    TEXT NOT NULL,
  replay_of     TEXT,                       -- 回放来源 run_id

  tokens_out    INTEGER NOT NULL DEFAULT 0,
  cost_micros   INTEGER NOT NULL DEFAULT 0, -- 费用，百万分之一元
  owner_lease   TEXT,                       -- 当前执行该运行的进程实例 ID

CREATE INDEX runs_status ON runs(status);

CREATE INDEX run_events_kind ON run_events(run_id, kind, seq);

-- 投影（可重建）
CREATE TABLE run_node_state (
  run_id TEXT, path TEXT, state TEXT, attempt INTEGER,

-- 工作区对象元数据（内容本身在文件系统）

CREATE INDEX approvals_pending ON approvals(status, created_at) WHERE status='pending';

-- 授权书

-- 账本

  field TEXT NOT NULL,

  PRIMARY KEY (scope, field, version)

## 3. store 接口

```go
package store

type Store interface {
    Graphs() GraphStore
    Runs() RunStore
    Blobs() BlobStore
    Approvals() ApprovalStore
    Mandates() MandateStore
    Audit() AuditStore
    Registry() RegistryStore      // nodedefs + types
    Ledger() LedgerStore
    Tx(ctx context.Context, fn func(Store) error) error // 事务；嵌套调用复用外层事务
    Close() error
}

type GraphStore interface {
    Create(ctx context.Context, g GraphMeta) error
    Get(ctx context.Context, id string) (GraphMeta, error)
    // 以 baseVersion 做乐观锁：head != baseVersion 返回 ErrVersionConflict（含当前 head）
    AppendOps(ctx context.Context, graphID, branch string, baseVersion int64, ops []OpRecord) (newVersion int64, err error)
    ListOps(ctx context.Context, graphID, branch string, sinceVersion int64, limit int) ([]OpRecord, error)
    SaveVersion(ctx context.Context, v GraphVersion) error
    LoadVersion(ctx context.Context, graphID, branch string, version int64) (GraphVersion, error) // 不存在时：找最近快照 + 重放 ops
    Branches(ctx context.Context, graphID string) ([]Branch, error)
}

type RunStore interface {
    Create(ctx context.Context, r RunMeta) error
    Get(ctx context.Context, id string) (RunMeta, error)
    UpdateStatus(ctx context.Context, id, status string) error
    AppendEvents(ctx context.Context, runID string, evs []Event) (lastSeq int64, err error) // seq 由存储分配
    Events(ctx context.Context, runID string, sinceSeq int64, limit int) ([]Event, error)
    EventsByPath(ctx context.Context, runID, pathPrefix string, sinceSeq int64) ([]Event, error)
    PutCheckpoint(ctx context.Context, cp Checkpoint, keepHistory bool) error
    Checkpoint(ctx context.Context, runID, path string) (Checkpoint, bool, error)
    CheckpointAt(ctx context.Context, runID, path string, seq int64) (Checkpoint, bool, error)
    AcquireLease(ctx context.Context, runID, owner string, ttl time.Duration) (bool, error)
    RenewLease(ctx context.Context, runID, owner string, ttl time.Duration) error
    Unfinished(ctx context.Context) ([]RunMeta, error) // 恢复用：status in (running, paused, cancelling)
    UpsertNodeState(ctx context.Context, rows []NodeStateRow) error
}

type BlobStore interface {
    Put(ctx context.Context, r io.Reader, mediaType string) (Ref, error) // 返回 ws://sha256/<hex>
    Get(ctx context.Context, ref Ref) (io.ReadCloser, BlobMeta, error)
    Stat(ctx context.Context, ref Ref) (BlobMeta, error)
    Incr(ctx context.Context, ref Ref, delta int) error
    GC(ctx context.Context, olderThan time.Duration) (removed int, err error)
}
```

写入批量：调度器把同一轮循环里产生的事件**攒批**（最多 64 条或 20ms）一次 `AppendEvents`，一个事务内完成，并同步更新 `runs.last_seq` 与 `run_node_state`。

### 4.1 投影实现
```go
type Projector interface { Apply(e Event) }

type NodeStateProj struct{ m map[string]*NodeStateRow }
func (p *NodeStateProj) Apply(e Event) {
    switch e.Kind {
    case "node.state":
        d := e.Data.(NodeStateData); r := p.row(e.Path)
        r.State, r.Attempt, r.LastSeq = d.To, d.Attempt, e.Seq
        if d.To == "running" && r.StartedAt == "" { r.StartedAt = e.TS }
        if isTerminal(d.To) { r.EndedAt = e.TS }
    case "budget.charged":
        d := e.Data.(ChargeData); r := p.row(e.Path)
        r.Tokens += d.Tokens; r.CostMicros += d.CostMicros
    }
}
```
- **时间线**：从 `node.state` 推出每个节点的区间 `[running, terminal)`，`waiting` 段单独标记，`node.throttled` 推出排队段。
- **时间旅行**：查询 `seq ≤ t` 的事件重放到投影即得到那一刻的状态。前端需要时，服务端用 `checkpoint_history` 加速：取最近的 `node_state` 快照（每 500 条事件存一次投影快照到 blobs）再增量重放。

## 5. 检查点策略

| 执行器 | 写检查点时机 | 内容 |
|---|---|---|
| Agent | 每轮工具循环结束 | 消息历史引用、turn、已调用工具的幂等键 |
| 扇出 | 每份完成 | `Done map[int]Value` |
| 循环（rounds） | 每轮结束 | round、carry 状态、stall 计数 |
| 循环（event） | 每个事件处理后 | 队列游标、长驻 Agent 的记忆引用 |
| 人工 | 进入 waiting 时 | approval_id |
| 子图引用 | 子图入口完成 | 子作用域 ID、预算剩余 |
| 其他 | 不写（节点幂等 / 快速，直接重跑） | — |

- 检查点内容序列化为 JSON 存 blobs，表里只存指针。每个 `(run, path)` 只保留最新；`keepHistory=true`（循环每轮）额外进 `checkpoint_history`，用于"从此检查点重跑"。
- **一致性**：写检查点与对应的 `checkpoint.saved` 事件在同一事务中。

## 6. 崩溃恢复

### 6.1 租约
- 进程启动生成实例 ID；执行一个运行前 `AcquireLease(ttl=30s)`，执行期间每 10s 续租。
- 租约过期的运行可以被任何实例接管。第一阶段单进程，也走这套逻辑，便于以后多实例。

### 6.2 恢复算法
```go
func (e *Engine) Recover(ctx context.Context) error {
    runs, _ := e.store.Runs().Unfinished(ctx)
    for _, rm := range runs {
        if ok, _ := e.store.Runs().AcquireLease(ctx, rm.ID, e.instance, 30*time.Second); !ok { continue }
        snap := e.loadSnapshot(ctx, rm.SnapshotRef)
        r := run.New(snap, e.deps)

        // 1. 重放事件，重建内存状态（不触发任何副作用）
        for evs := range e.store.Runs().EventsStream(ctx, rm.ID, 0) {
            for _, ev := range evs { r.ApplyReplay(ev) }
        }
        // 2. 处理"在飞"的节点：最后状态是 running/queued
        for _, p := range r.InFlight() {
            if cp, ok, _ := e.store.Runs().Checkpoint(ctx, rm.ID, p); ok && r.Exec(p).Resumable() {
                r.ScheduleResume(p, cp)              // 从检查点继续
            } else {
                r.Requeue(p, "recovered")            // 重新执行；有副作用的工具靠幂等键去重
            }
        }
        // 3. waiting 节点保持 waiting；若审批已在离线期间决定，补投递结果
        for _, a := range e.pendingResolvedApprovals(ctx, rm.ID) { r.DeliverApproval(a) }
        // 4. 若 status=cancelling，继续完成取消；paused 保持暂停
        go e.drive(ctx, r)                          // 进入正常调度循环
        r.Emit(EvRunStatus{Cause: "recovered"})
    }
    return nil
}
```

### 6.3 副作用去重
- `tool.call` 事件按 `idem_key` 建索引（`run_events_kind` + JSON 提取，或另建 `tool_calls(idem_key PRIMARY KEY, result_ref)` 表）。
- 重新执行工具前先查：已有成功结果 → 直接返回记录的结果，写 `tool.call{replayed:true}`。
- 调用外部系统时把幂等键通过请求头 `Idempotency-Key` 透传（支持的 API 才有效）；不支持的 L2+ 工具，若检测到"已发起但无结果"的记录，**转为人工确认**，不自动重发。

### 6.4 模型调用的恢复
- Agent 每轮后有检查点，崩溃最多损失一轮模型调用的 token。
- `llm.call` 的响应存 blobs，回放与单节点重放时可以直接用录制的响应。

## 7. 回放、单节点重放与"从此检查点重跑"

| 操作 | 新建运行 | 使用 | 是否调用模型/工具 |
|---|---|---|---|
| **回放（replay）** | 是，`replay_of=原 run` | 原快照 + 原事件里的 `llm.call/tool.call/orch.expanded` 录制值 | 否，全部用录制值 |
| **单节点重放** | 否（临时执行） | 节点记录的输入 + 录制响应 | 默认否；可选"实时重放"真调用一次对比 |
| **从此检查点重跑** | 是 | 原快照 + 截止到该检查点 seq 的事件 + 检查点状态 | 检查点之后的部分真调用 |
| **从此节点重跑** | 是 | 上游节点输出复用（缓存），该节点及下游重跑 | 该节点起真调用 |

```go
func (e *Engine) RerunFromCheckpoint(ctx context.Context, runID, path string, seq int64, patch *GraphPatch) (string, error) {
    src, _ := e.store.Runs().Get(ctx, runID)
    snap := e.loadSnapshot(ctx, src.SnapshotRef)
    if patch != nil { snap = snap.With(patch) }          // 允许改参数后重跑
    newID := ulid.Make().String()
    e.store.Runs().Create(ctx, RunMeta{ID: newID, ReplayOf: runID, …})
    prefix, _ := e.store.Runs().EventsUntil(ctx, runID, seq) // 复制前缀事件（标记 copied_from）
    e.store.Runs().AppendEvents(ctx, newID, rewrite(prefix, newID))
    cp, _, _ := e.store.Runs().CheckpointAt(ctx, runID, path, seq)
    return newID, e.startFrom(ctx, newID, path, cp)
}
```

## 8. 工作区与指针（ws://）

- 地址格式：`ws://sha256/<64 hex>`，内容寻址，相同内容只存一份。
- 第一阶段落本地目录：`$HARNESS_DATA/blobs/ab/cd/<hash>`（前两级分桶），元数据进 `blobs` 表。
- 写入：流式计算 sha256 → 先写临时文件 → `rename` 到目标位置（原子）→ upsert 元数据。
- 大小阈值：值的 JSON > 8KB 自动转指针（`Value.Ref`），事件里只存指针和摘要。
- 引用计数：图版本、运行快照、检查点、事件里的指针在写入时 `Incr`；清理时 `Decr`。
- 以后换 S3 / MinIO：只换 `BlobStore` 实现，地址格式不变。

### 8.1 保留与清理
| 数据 | 默认保留 | 说明 |
|---|---|---|
| ops、graph_versions | 永久 | 图历史 |
| 运行事件 | 90 天 | 可按图配置；被标记"收藏"的运行永久 |
| `node.progress`、`node.throttled` | 7 天 | 高频低价值，先清 |
| checkpoint_history | 运行结束后 14 天 | 最新检查点随运行保留 |
| blobs | 引用计数为 0 且 7 天无访问 | `GC` 每日执行 |
| audit | 1 年 | 不可删除，只能归档导出 |

清理任务每天凌晨跑，分批删除（每批 5000 行），避免长事务锁库。

## 9. 并发写入与事务

- SQLite 只有一个写者。服务里用**单个写连接 + 写队列**（`chan writeReq`），读用连接池（`SetMaxOpenConns(8)`）。WAL 模式下读不阻塞写。
- 每个运行的事件由该运行的调度器串行写，天然有序；不同运行之间并发写在写队列里排队，攒批后 1 个事务提交多个运行的事件。
- Op 提交：`AppendOps` 在事务里 `SELECT head_version … ` 比对 `baseVersion`，不符返回 `ErrVersionConflict{Head}`；符合则写 ops、更新 head。
- 账本 `cas`：`INSERT … WHERE (SELECT max(version) …) = ?`，影响行数为 0 即冲突。

## 10. 迁移到 Postgres 的差异点

| 方面 | SQLite（M0–M4） | Postgres（M5） |
|---|---|---|
| 驱动 | modernc.org/sqlite | jackc/pgx/v5 |
| JSON 列 | BLOB（文本 JSON） | JSONB，可建 GIN 索引 |
| 时间 | TEXT（RFC3339） | timestamptz |
| seq 分配 | 事务内 `last_seq+1` | 同；或 `run_events` 按 run 分区 |
| 写并发 | 单写者队列 | 多写者，按 run_id 行锁 |
