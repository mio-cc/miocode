# 07 授权与安全

> 包：`engine/authz`（判定）、`engine/run`（挂起/恢复）、`internal/api`（审批接口）。
> 与 `_关键决定.md` 一致：五档 0–4、授权书可按对象挂载、`Check()` 返回 allow / ask / deny、污染标记默认开启、急停模型无权解除、所有决策写审计。

---

## 1. 设计目标

| # | 目标 | 落地 |
|---|---|---|
| A1 | 授权可调，不死板 | 五档 + 按维度覆盖 + 例外项 + 时效，全部是数据，可编辑 |
| A2 | 允许完全授权 | 4 档 = 与用户同权，包括修改自身所在层、下放完全权限 |
| A3 | 出了问题能恢复 | 无论哪一档都保留：留痕、版本快照、急停 |
| A4 | 判定统一 | Op 和工具调用都只走一个入口 `authz.Check` |
| A5 | 判定可解释 | 每个决定都带理由链（命中哪份授权书、哪条规则） |
| A6 | 判定快 | 单次 Check < 50µs（内存缓存解析结果），不阻塞调度 |

非目标（第一阶段）：多租户 RBAC、组织级策略、SSO。第一阶段只有一个"所有者"用户。

## 2. 核心模型

### 2.1 主体 Principal

```go
package authz

type PrincipalKind string

const (
    PUser     PrincipalKind = "user"      // 人
    PModel    PrincipalKind = "model"     // 某个模型实例（某次运行中的某个 Agent 节点）
    PNode     PrincipalKind = "node"      // 非模型节点（如工具节点的 direct 调用）
    PExternal PrincipalKind = "external"  // 外部触发：定时器、Webhook、API 调用
)

type Principal struct {
    Kind     PrincipalKind `json:"kind"`
    ID       string        `json:"id"`        // user: 用户ID；model: run_id/node_path
    Tags     []string      `json:"tags"`      // 如 "主脑"、"编排者"，来自节点实例 tags
    Parent   *Principal    `json:"parent,omitempty"` // 子编排者指向生成它的编排者
    RunID    string        `json:"run_id,omitempty"`
    NodePath string        `json:"node_path,omitempty"`
}
```

规则：

- 用户永远是 4 档之上的"所有者"，不受授权书约束，但受急停约束（急停后用户也只能解除急停和只读，防止误操作扩大）。
- 模型主体的权限 = 它所在对象解析出的有效授权书 ∩ 父主体（若有）下放的授权。
- 外部触发默认 0 档，需要显式授权书。

### 2.2 动作 Action

动作覆盖全部 Op 种类和工具调用，统一成字符串枚举，便于写进授权书：

## 3. 授权书 Mandate

### 3.1 Go 结构体

```go
type Level int // 0 只读 1 建议 2 部分 3 高度 4 完全

type Mandate struct {
    ID        string     `json:"id"`         // ULID
    Name      string     `json:"name"`       // "谨慎协作"
    Level     Level      `json:"level"`
    Grantee   Selector   `json:"grantee"`    // 授予谁：tag:编排者 / model:* / external:webhook
    Overrides *Overrides `json:"overrides,omitempty"` // 仅 2 档有效（3、4 档用 Except）
    Except    []Action   `json:"except,omitempty"`    // 3、4 档：这些动作要 ask
    Deny      []Action   `json:"deny,omitempty"`      // 任何档：这些动作直接 deny
    Expires   Expiry     `json:"expires"`
    Taint     TaintMode  `json:"taint"`      // "ask"(默认) | "allow"
    Delegable DelegMode  `json:"delegable"`  // 下放规则，见 §10
    L3SkipHuman bool     `json:"l3_skip_human,omitempty"` // 仅用户可设
    CreatedBy Principal  `json:"created_by"` // 必须是 user
    CreatedAt time.Time  `json:"created_at"`
    Revoked   *time.Time `json:"revoked,omitempty"`
}

type Overrides struct {
    Scope        []string          `json:"scope,omitempty"`   // glob：根图/闭环迭代/**
    Ops          map[Action]Effect `json:"ops,omitempty"`     // allow | ask | deny
    ToolsMaxRisk int               `json:"tools_max_risk"`    // 0..3
    ToolsAllow   []string          `json:"tools_allow,omitempty"`
    Models       []string          `json:"models,omitempty"`  // 允许使用的模型引用，空 = 不限
    Budget       *Budget           `json:"budget,omitempty"`
    MaxNodes     int               `json:"max_nodes,omitempty"`
    MaxDepth     int               `json:"max_depth,omitempty"`
    AllowSpawn   bool              `json:"allow_spawn"`
}

type Budget struct {
    Tokens int64         `json:"tokens,omitempty"`
    CostCN float64       `json:"cost_cny,omitempty"`
    Time   time.Duration `json:"time,omitempty"`
    Calls  int           `json:"calls,omitempty"`
}

type Expiry struct {
    Kind  string     `json:"kind"`            // "run" | "session" | "forever" | "until"
    Until *time.Time `json:"until,omitempty"`
    RunID string     `json:"run_id,omitempty"`
}

type Effect string
const ( Allow Effect = "allow"; Ask Effect = "ask"; Deny Effect = "deny" )
```

### 3.2 五档的默认矩阵

`levelDefault(level, action)` 是硬编码表，授权书在此基础上覆盖：

| 动作 \ 档位 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| graph/run/trace.read | allow | allow | allow | allow | allow |
| op.*（结构修改） | deny | propose¹ | 看 Overrides.Ops，默认 allow（scope 内） | allow | allow |
| op.remove_node / ungroup | deny | propose | ask | allow | allow |
| res.edit_role_card / recipe | deny | propose | ask | allow | allow |
| res.switch_model | deny | propose | 看 Models | allow | allow |
| authz.set_mandate | deny | deny | deny | ask | allow² |
| authz.request_elevation | deny | allow | allow | allow | allow |
| run.start / pause | deny | ask | allow | allow | allow |
| run.cancel | deny | allow | allow | allow | allow |
| orch.spawn | deny | deny | 看 AllowSpawn | allow | allow |
| orch.self_modify | deny | deny | deny | ask | allow |
| tool.L0 | deny | allow³ | allow | allow | allow |
| tool.L1 | deny | ask | ≤ToolsMaxRisk 则 allow | allow | allow |
| tool.L2 | deny | ask | ≤ToolsMaxRisk 则 allow，否则 ask | allow | allow |
| tool.L3 | deny | ask | ask | ask | allow⁴ |
| estop.trigger | allow | allow | allow | allow | allow |
| estop.release | deny | deny | deny | deny | **deny** |

1. `propose` 是 ask 的特殊形式：不挂起，而是写成提议，在画布上显示为幽灵节点，等待采纳。
2. 4 档可以修改授权书，但**不能修改把自己授权为 4 档的那份**，只能新建更窄的授权书。这条防止模型删掉自己的审计开关。
3. 1 档执行只读工具是为了让模型能"看清楚再提议"，比如检索文档、读取图。
4. L3 在 4 档下可以 allow，但图检查仍会要求"L3 工具前接人工节点"，除非用户在授权书里显式设置 `l3_skip_human: true`。见 §11。

急停解除是唯一的硬编码 deny：不受任何授权书影响，只有 `PUser` 能执行。

## 4. 挂载、继承与覆盖

### 4.1 挂载表

```sql
CREATE TABLE mandate_bindings (
  id          TEXT PRIMARY KEY,
  mandate_id  TEXT NOT NULL REFERENCES mandates(id),
  anchor      TEXT NOT NULL,     -- "session:s1" / "graph:g1" / "path:根图/闭环迭代" / "node:n12"
  grantee     TEXT NOT NULL,     -- "tag:编排者" / "model:*" / "external:*"
  priority    INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_mb_anchor ON mandate_bindings(anchor);
```

### 4.2 解析算法

最具体的挂载点优先；同一层上有多条时，按 priority 高的优先；找到第一份匹配主体的授权书就停止，即**就近覆盖，不做叠加**。叠加规则太难解释，用户在画布上看到的"这个节点是几档"必须只对应一份授权书。

```go
func (r *Resolver) Effective(p Principal, t Target) (*Mandate, []string /*理由链*/) {
    for _, anchor := range t.Chain() {
        for _, b := range r.bindingsAt(anchor) {           // 已按 priority 降序
            if !b.Grantee.Match(p) { continue }
            m := r.mandate(b.MandateID)
            if m.Revoked != nil || m.Expires.Expired(r.now(), p.RunID) { continue }
            return m, []string{"命中 " + m.Name + " @ " + anchor}
        }
    }
    return defaultMandate(p), []string{"无授权书，使用默认 " + defaultName(p)}
}

// 默认：模型 1 档（建议），外部 0 档，节点 direct 调用继承所在子图对模型的授权
```

结果按 `(principal.Tags, principal.Parent, target.Chain)` 缓存。授权书或挂载变化时，按 anchor 前缀失效缓存。

## 5. Check() 实现

```go
type Request struct {
    Who    Principal
    Act    Action
    Target Target
    Taint  bool               // 由外部内容引出
    Cost   *Budget            // 预计消耗（工具调用、模型调用时填）
    Patch  *PatchStats        // 图修改时：新增节点数、深度等
}

type Decision struct {
    Effect   Effect   `json:"effect"`     // allow | ask | deny
    Propose  bool     `json:"propose"`    // 1 档：以提议形式落地
    Reasons  []string `json:"reasons"`
    Mandate  string   `json:"mandate_id"`
    AskKind  string   `json:"ask_kind,omitempty"` // "approval" | "elevation" | "taint" | "budget"
}

func (a *Authz) Check(ctx context.Context, req Request) Decision {
    // 0. 用户直通（急停除外）
    if req.Who.Kind == PUser {
        if a.estop.Active(req.Who.RunID) && !estopSafe(req.Act) {
            return a.audit(req, Decision{Effect: Deny, Reasons: []string{"急停中，仅允许只读和解除急停"}})
        }
        return a.audit(req, Decision{Effect: Allow, Reasons: []string{"所有者"}})
    }
    // 1. 硬规则
    if req.Act == ActEstopRelease {
        return a.audit(req, deny("急停只能由用户解除"))
    }
    if a.estop.Active(req.Who.RunID) && !estopSafe(req.Act) {
        return a.audit(req, deny("急停中"))
    }
    // 2. 解析有效授权书
    m, why := a.res.Effective(req.Who, req.Target)
    d := Decision{Mandate: m.ID, Reasons: why}
    // 3. 显式 deny
    if contains(m.Deny, req.Act) {
        return a.audit(req, d.with(Deny, "授权书显式禁止 "+string(req.Act)))
    }
    // 4. 档位默认 + 覆盖
    eff, propose, r := evalLevel(m, req)
    d.Effect, d.Propose = eff, propose
    d.Reasons = append(d.Reasons, r...)
    // 5. 例外项（3/4 档）
    if eff == Allow && (m.Level >= 3) && contains(m.Except, req.Act) {
        d = d.with(Ask, "命中例外项").kind("approval")
    }
    // 6. 资源限制
    if eff != Deny {
        if over, why := a.budget.WouldExceed(req.Who.RunID, m, req.Cost); over {
            d = d.with(Ask, why).kind("budget")
        }
        if req.Patch != nil {
            if why := checkPatchLimits(m, req.Patch); why != "" {
                d = d.with(Ask, why).kind("approval")
            }
        }
    }
    // 7. 污染
    if req.Taint && m.Taint != "allow" && d.Effect == Allow && mutating(req.Act) {
        d = d.with(Ask, "由外部内容引出的操作需确认").kind("taint")
    }
    return a.audit(req, d)
}
```

`evalLevel` 实现 §3.2 的矩阵。2 档时依次检查：`Scope` 的 glob 是否匹配 `Target.Path` → `Ops[act]` → 工具风险是否不超过 `ToolsMaxRisk` → `Models`。不满足条件时，2 档返回 **propose**，也就是范围外只能提建议，不会直接 deny。这是用户要求的"部分授权"语义。

**判定顺序的意义**：显式禁止 > 档位 > 例外 > 资源 > 污染。后面的步骤只会把结果收紧（从 allow 变成 ask），永远不会放宽。

## 6. 审批流

### 6.1 表

```sql
CREATE TABLE approvals (
  id           TEXT PRIMARY KEY,
  run_id       TEXT,                  -- 运行外（设计时）的审批为 NULL
  graph_id     TEXT NOT NULL,
  node_path    TEXT,
  principal    TEXT NOT NULL,         -- JSON
  action       TEXT NOT NULL,
  target       TEXT NOT NULL,         -- JSON
  kind         TEXT NOT NULL,         -- approval | elevation | taint | budget | human_node
  summary      TEXT NOT NULL,         -- 给人看的一句话
  detail_ref   TEXT,                  -- ws:// 指针：完整请求、证据
  reasons      TEXT NOT NULL,         -- JSON 数组
  status       TEXT NOT NULL,         -- pending | approved | rejected | expired | cancelled
  scope        TEXT,                  -- once | forever（批准时填）
  decided_by   TEXT,
  decided_at   TEXT,
  expires_at   TEXT,
  created_at   TEXT NOT NULL
);
CREATE INDEX idx_appr_pending ON approvals(status, created_at);
```

### 6.2 挂起与恢复

```go
// 执行器里
dec := rc.Authz(authz.Request{...})
switch dec.Effect {
case authz.Allow:
case authz.Deny:
    return nil, rc.Fail(ErrDenied{dec})
case authz.Ask:
    res, err := rc.Ask(Approval{Kind: dec.AskKind, Summary: ..., Reasons: dec.Reasons})
    // rc.Ask 写入 approvals、发出 node.state(to=waiting) 事件、写检查点，然后阻塞在 channel 上
    // 进程崩溃后重启：从 approvals 读到 pending → 节点恢复为 waiting
    // 审批到达 → run 发出 approval.resolved 事件 → 唤醒
    if err != nil || !res.Approved { return nil, rc.Fail(ErrRejected) }
}
```

- **仅本次**：只放行这一次调用。
- **永久**：为请求者生成一条窄授权书（单一 Action + 单一 Target），挂载到对应 anchor，`Expires=forever`。界面上显示为"由审批 A-7 生成"，可以撤销。
- **超时**：`expires_at` 到期后由 sweeper 标记为 expired，按节点的 `on_timeout` 处理（reject / default / escalate），默认 reject。
- 同一节点、同一动作、同一目标的重复请求合并，引用同一条 approval。

### 6.3 接口

`GET /approvals?status=pending`、`POST /approvals/{id}/resolve {outcome:"approved"|"rejected", scope:"once"|"forever", note}`。审批结果通过 SSE `approval.resolved` 广播，画布、对话、通知三处会同步更新。

## 7. 提权申请与自动升降

### 7.1 提权

模型通过图操作工具 `request_elevation` 发起提权（见 10 号文档），请求内容是 `{to_level, scope, reason, duration}`。它是一种特殊的 approval（`kind=elevation`）：批准后生成授权书，挂到请求的 scope 上。

### 7.2 规则引擎

```go
type AutoRule struct {
    ID      string `json:"id"`
    When    string `json:"when"`    // expr 表达式，见下
    Then    Change `json:"then"`    // {set_level:2} | {set_level:"-1"} | {revoke:"run"}
    Anchor  string `json:"anchor"`
    Enabled bool   `json:"enabled"`
}
```

表达式使用 expr-lang/expr，变量来自计数器：

| 变量 | 含义 |
|---|---|
| `approved_streak` | 连续被批准的提议数 |
| `rejected_streak` | 连续被拒数 |
| `failures` | 本次运行的节点失败数 |
| `budget_ratio` | 已用预算 / 上限 |
| `event` | 当前触发事件名，例如 `run.status` |

内置规则（可关闭）：

```yaml
- when: approved_streak >= 10        ; then: {set_level: 2}
- when: budget_ratio >= 0.8          ; then: {set_level: 1}
- when: event == "run.status" && to in ["done","failed","cancelled"] ; then: {revoke: "run"}   # 回收"仅本次运行"的授权
- when: failures >= 3                ; then: {set_level: 1}
```

规则触发后生成新的授权书并挂载，旧的标记为 superseded；所有改动都写审计，并通过 SSE 推送 `mandate.changed`。规则引擎**只能降档或升到用户事先写好的目标档**，不能自行决定升档幅度。

## 8. 污染标记

### 8.1 来源与传播

```
工具结果（网页 / 文件 / 邮件 / MCP 外部数据）  taint=true
      │  写入信封 Envelope.Taint
      ▼
上下文装配：任一输入段 taint → 上下文包 taint（并记录是哪一段）
      ▼
Agent 输出：上下文包 taint → 输出信封 taint
      ▼
由该输出引出的 Op / 工具调用：Request.Taint = true
```

```go
type Envelope struct {
    Type     string          `json:"type"`
    Version  string          `json:"schema_version"`
    Payload  json.RawMessage `json:"payload"`
    Refs     []string        `json:"refs,omitempty"`
    Taint    bool            `json:"taint,omitempty"`
    TaintSrc []string        `json:"taint_src,omitempty"` // 来源指针，便于界面展示"因为读了哪个网页"
    Seq      int64           `json:"seq"`
}
```

- 用户输入、图文档本身、角色卡、账本里由用户写入的字段：**不污染**。
- 污染只会累加，不会自动清除。用户在审批界面点"信任这次来源"后，该来源的指针加入本次运行的白名单，之后由它引出的操作不再污染。
- 只读动作不受污染影响；只有修改性动作（`mutating(act)`：op.*、res.*、authz.*、tool.L1+）会因污染变为 ask。
- 授权书 `taint: allow` 可以关闭污染检查（用户要求可关）。默认 `ask`。

### 8.2 为什么做到信封级而不是只做到节点级

如果只标记节点，一个 Agent 读了 1 篇网页和 10 份内部文档，整个节点的输出都会被标记，误报太多。做到段级以后，界面可以写明"因为第 3 段（来自 example.com）"，用户能判断是否信任这次来源。第一阶段先做到"段级记录、节点级判定"，P2 再考虑按段细化判定。

## 9. 急停

| 级别 | 作用范围 | 触发 | 解除 |
|---|---|---|---|
| 运行级 | 单个 run | 用户；规则引擎；模型自己（允许模型"踩刹车"） | 仅用户 |
| 全局 | 宿主服务中的整个 harness 模块 | 用户；`harnessctl estop` 命令行 | 仅用户 |

触发后：

1. 立即取消对应 run 的根 context，取消信号沿 context 树传播到所有执行器和进行中的模型、工具调用。
2. 所有模型主体视为 0 档；未决的 approval 一律标为 cancelled。
3. 写 `estop.triggered` 事件和审计记录，SSE 推送，前端顶栏切换为急停样式。
4. 已完成节点的结果和检查点保留，解除后可以"从检查点继续"。

实现：`estop` 状态存在内存原子变量里，同时持久化到 `settings` 表，重启后仍处于急停。`ActEstopRelease` 在 `Check()` 第 1 步就对非用户主体硬编码 deny，同时 API 层的 `/estop/release` 只接受用户 token。**两层都拦**，任何一层出错都不会导致模型解除急停。

## 10. 子编排者的授权下传

```go
type DelegMode string
const (
    DelegNarrow DelegMode = "narrow" // 默认：只能下放 ⊆ 自己的权限
    DelegFull   DelegMode = "full"   // 仅 4 档可用：可以原样下放完全权限
    DelegNone   DelegMode = "none"   // 禁止创建子编排者
)

func (a *Authz) Delegate(parent Principal, pm *Mandate, req Mandate) (*Mandate, error) {
    switch {
    case pm.Delegable == DelegNone:
        return nil, ErrNoDelegation
    case pm.Level == 4 && pm.Delegable == DelegFull:
        return req.ClampDepth(pm), nil                   // 只限制深度，不收窄权限
    default:
        return Intersect(pm, &req), nil                  // 档位取 min，各维度取交集，预算取 min(请求, 父剩余)
    }
}
```

- 子编排者的预算一律从父级预算里**划拨**，不会新增额度，即使 4 档也一样，防止无限递归烧钱。
- 嵌套深度上限 `MaxDepth`，默认 3，4 档也有上限（内核锁定，可配置到最多 8）。
- 子主体的 `Parent` 字段把整条下放链记进审计，界面上可以画出"你 → 编排者 → 子编排者"。

## 11. L3 工具与沙箱

### 11.1 L3 强制人工

- **图检查规则 V-L3**：任何 `risk=L3` 的工具节点，或者任何连了 L3 工具端点的 Agent，在数据流上游必须有一个人工节点，或者在授权书里写明 `l3_skip_human: true`（只能由用户设置，4 档模型也不能设置）。
- 运行时再查一次：即使图检查已经通过，L3 调用在 `Check()` 中 3 档及以下一律 ask。

### 11.2 代码执行沙箱（第一阶段取舍）

| 方案 | 隔离 | 成本 | 第一阶段 |
|---|---|---|---|
| 子进程 + 资源限制（Linux：setrlimit、seccomp；Windows：Job Object） | 中 | 低 | **采用**，仅允许本地开发模式 |
| Docker / Podman 容器（无网络、只读根、tmpfs 工作目录） | 高 | 中 | M3 接入，作为默认 |
| gVisor / Firecracker | 很高 | 高 | 不做 |
| WASM（wazero 运行 Python/JS 的 wasm 构建） | 高 | 中 | P2 评估 |

安全边界（无论哪种方案）：

- 默认无网络；要联网需在工具配置里声明白名单域名，并且升级为 L2。
- 只能读写本次运行的工作区目录。
- CPU 时间、内存、输出大小、进程数都有上限；超出后强制终止，并在节点上标记"沙箱超限"。
- 不传递任何环境变量和密钥。

## 12. 密钥与外部凭据隔离

- 密钥不进图文档、不进事件日志、不进上下文包。图里只存引用 `secret://openai/default`。
- 存储：第一阶段优先用环境变量；也可以放本地 `secrets.enc`（age 加密，口令由 OS keychain 提供）。由 `secrets.Provider` 接口统一获取。
- 解析时机：只在适配层发起 HTTP 请求的那一刻解析，用完不缓存到执行器的内存结构里。
- 日志脱敏：slog handler 对 `Authorization`、`api_key`、`token` 字段统一替换为 `***`。
- 模型永远拿不到密钥值。图操作工具里没有任何读取 secret 的接口，`read_graph` 返回时会把 secret 引用替换为 `<secret>`。

## 13. 审计日志

```sql
CREATE TABLE audit (
  seq         INTEGER PRIMARY KEY AUTOINCREMENT,
  ts          TEXT NOT NULL,
  principal   TEXT NOT NULL,   -- JSON，含 Parent 链
  action      TEXT NOT NULL,
  target      TEXT NOT NULL,
  effect      TEXT NOT NULL,   -- allow | ask | deny | approved | rejected
  mandate_id  TEXT,
  reasons     TEXT NOT NULL,
  op_id       TEXT,            -- 若为 Op
  approval_id TEXT,
  snapshot    TEXT,            -- 生效后的 graph_version，可回滚
  taint       INTEGER NOT NULL DEFAULT 0,
  prev_hash   TEXT NOT NULL,   -- 哈希链，防篡改
  hash        TEXT NOT NULL
);
```

- 只追加；每行 `hash = sha256(prev_hash || canonical(row))`。`harnessctl audit verify` 可以校验整条链。
- 读 allow 的审计默认采样（只记录 ask、deny 和修改性 allow），可以配置为全量。
- 前端审计页按主体、动作、时间过滤，每条可以跳转到对应的 Op、审批和快照，支持"回滚到此前"。

## 14. 威胁模型

| # | 威胁 | 场景 | 对策 |
|---|---|---|---|
| T1 | 提示词注入改图 | 网页里写"删除这个流程" | 污染标记 → ask；L3 强制人工；审计 |
| T2 | 模型解除急停 | 4 档模型调用解除接口 | `Check` 硬编码 deny + API 只接受用户 token |
| T3 | 模型篡改自己的授权 | 4 档模型修改授权书把审计关掉 | 不能修改授予自己的那份；审计不可关；哈希链 |
| T4 | 递归失控 | 编排者不断创建子编排者 | 深度上限 + 预算划拨 + 节点数上限 + 重复补丁检测 |
| T5 | 预算耗尽 | 扇出 N 设成 1000 | 预算 WouldExceed → ask；规则引擎 80% 自动降档 |
| T6 | 密钥泄露 | 模型被诱导输出 API key | 密钥从不进上下文；日志脱敏 |
| T7 | 数据外泄 | 执行者把内部数据发到外部 HTTP | HTTP 工具为 L2；域名白名单；污染下 ask |
| T8 | 沙箱逃逸 | 代码执行读宿主文件 | 容器无网络、只读根、工作区挂载；资源上限 |
| T9 | 重复副作用 | 重试导致邮件发两遍 | 幂等键；工具层去重表 |
| T10 | 越权读 | 子图读父级账本私有字段 | 作用域：局部账本 + writeback 声明；ACL 由字段属性决定 |
| T11 | 审批疲劳 | 用户随手全批 | 合并同类审批；"永久批准"生成窄授权书；审批卡写清风险等级 |
| T12 | 时间窗攻击 | 用户刚收回授权，在途调用仍执行 | 收回在安全点生效，但 L2/L3 调用在发出前再次 Check |
| T13 | 外部触发滥用 | Webhook 被刷 | external 默认 0 档；令牌鉴权；频率限制 |
| T14 | 回放被污染 | 回放时重新调用了外部工具 | 回放只用事件日志里记录的结果，不发真实调用 |
