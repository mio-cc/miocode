节点库：13 个原子节点

● 输入端口　● 输出端口。每个节点还会由内核自动加上「升级」和「留痕」两个端口。

自定义靠这五个机制，不靠改节点

业务含义通过类型引用、配方/策略引用、表达式三种"插槽"填进去。

参数可转端口
任何参数既能手填，也能接上游的输出，相当于 ComfyUI 的 widget → input
Agent(调度员).concurrency → 扇出.concurrency
三级锁
kernel：谁都改不了；def：节点作者锁定；none：实例上随意改
risk: {lock: kernel(只能调高)}
标签（tags）
节点里不写角色。"主脑"只是一个标签，类型的字段属性、账本权限、升级路由都通过标签引用它
intent: {readonly_except: [tag:主脑]}
钩子（hooks）
审核、限流、脱敏等策略挂在实例上，不用改节点本身
hooks: {before: [白名单], on_error: [上报]}
类型变量
端口类型跟着参数和连线走，选了什么输出类型，输出端口就变成什么
Agent.result: T (T = output_schema)

内核锁死的只有这 7 条

除此之外全部可以配置。

  1. 01Agentcontext 端口只接受上下文包，每个 Agent 看到什么都画在画布上
  2. 02上下文装配类型里标了 inherit 的字段必须透传，关键约束不会被裁掉
  3. 03工具风险等级只能调高；必须保留原文指针；L3 工具前必须接人工节点
  4. 04聚合 · 分支结果确定，不调用模型，可以缓存，方便排错
  5. 05循环只有循环节点能形成环，而且至少有一个有限出口
  6. 06账本写入要遵守字段属性，每次写入都留痕
  7. 07子图引用权限 = 授予 ∩ 声明 ∩ 父级；嵌套深度有上限
