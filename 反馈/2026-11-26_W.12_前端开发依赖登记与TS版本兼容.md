| 项 | 内容 |
|---|---|
| 类型 | R5 新依赖（另附 TS 7 与 typescript-eslint 兼容情况） |
| 发现于 | M1 第 ⑧ 片 `m1-web-base` 开工复查，2026-11-26 |
| 涉及文档 | `G.10` §3.4、`G.06.04` §1、`W.01`、`W.12`、`W.10`、`W.04.03` |

## 现象

1. **必需的 TypeScript / Vite / ESLint 配套开发依赖未登记在 `G.10` §3.4 与 `tools/deps/allow.txt`**：
   现有 `G.10` §3.4（及 `tools/deps/allow.txt`）已登记：`vite`、`typescript`、`eslint`、`typescript-eslint`、`eslint-plugin-react-hooks`、`eslint-plugin-react-refresh`、`stylelint`、`prettier`、`vitest`、`jsdom`、`@playwright/test`、`ajv`。
   但在 React 19 + TypeScript strict + Vite 8 + ESLint 10（flat config）下，以下 6 个标准配套开发包尚未登记：

   | 包名 | 用途 | 备选方案 | 许可证 | 维护情况 | 体积（unpacked，纯 devDep 不进产包） |
   |---|---|---|---|---|---|
   | `@vitejs/plugin-react`（`6.3.0`） | Vite 8 的 React Fast Refresh 与 JSX 构建插件 | 不用插件则开发模式无 React Fast Refresh | MIT | Vite 官方维护 | ~47 KB |
   | `@types/react`（`19.3.3`） | React 19 的 TypeScript 类型定义（`react` 包本身不自带 `.d.ts`） | 手写 React 19 类型声明不可行 | MIT | DefinitelyTyped 官方维护 | ~408 KB |
   | `@types/react-dom`（`19.3.0`） | `react-dom/client`（`createRoot`）与 `createPortal` 类型定义 | 同上 | MIT | DefinitelyTyped 官方维护 | ~33 KB |
   | `@types/node`（`26.6.11`） | `vite.config.ts`、`vitest.config.ts`、`W.04.03` 测试读 `schema/examples/`（`node:fs`、`node:path`、`process`）所需类型，也是 `vite`/`vitest` 的 peer | 手写 `node:*` 声明不可行 | MIT | DefinitelyTyped 官方维护 | ~2.5 MB |
   | `@eslint/js`（`10.0.1`） | ESLint 9/10 flat config 的 JS 推荐规则集（`js.configs.recommended`） | 不启用推荐规则会丢失大量基础 lint 检查 | MIT | ESLint 官方维护 | ~16 KB |
   | `globals`（`17.14.0`） | ESLint 10 flat config 声明 `globals.browser` / `globals.node` | 手工维护全套 DOM/Node 全局变量表易遗漏 | MIT | Sindre Sorhus 长期维护，ESLint 官方文档推荐 | ~259 KB |

   注：`W.04.03` 测试读取 `schema/examples/manifest.yaml` 与 `schema/builtin/aliases.yaml` 所需解析结构非常简单（2 层键值对/列表），前端线自行用 < 40 行纯函数解析，**不申请** `yaml` 依赖（遵守 `G.10-R3`）。`stylelint` 规则按 `G.06.03` / `G.04.06` 直接写进 `web/stylelint.config.js`，**不申请**额外的 stylelint preset。

2. **TypeScript 7.0.2 与 `typescript-eslint@8.74.0` 的兼容性冲突**：
   - 当前 `web/package.json` 固定了 `"typescript": "7.0.2"`（Go 原生重写版 `tsgo`，其 `package.json` 的 `"."` 导出只有 `version.cjs`，不再提供传统 JS Compiler API）。
   - `typescript-eslint@8.74.0`（及 `@typescript-eslint/parser@8.74.0`）的 `peerDependencies` 为 `typescript: >=4.8.4 <6.1.0`，其对 TypeScript 7 的实验支持要求 `@typescript/native: npm:typescript@>=7.1.0-dev`（非正式版），无法配合 `typescript@7.0.2` 运行 `strictTypeChecked`（`G.06.04` §1 要求的 `typescript-eslint` strict-type-checked）。
   - `typescript@6.0.3`（Apache-2.0，当前最新 6.x 正式版）提供完整 JS Compiler API，与 `typescript-eslint@8.74.0`、`vitest@5.1.2`（`--typecheck`）、`vite@8.3.8` 完全兼容。

## 可选方案

### 1. 新增开发依赖
| 方案 | 影响 |
|---|---|
| A（推荐） | 主线在 `G.10` §3.4 与 `tools/deps/allow.txt` 一次性登记上述 6 个 devDep（`@vitejs/plugin-react`、`@types/react`、`@types/react-dom`、`@types/node`、`@eslint/js`、`globals`），并合并进 `main` |
| B | 仅登记 `@types/react`、`@types/react-dom`、`@types/node`、`@vitejs/plugin-react`，ESLint 10 不用 `@eslint/js` 和 `globals` 而手写全局列表与规则 |

### 2. TypeScript 版本与 `typescript-eslint`
| 方案 | 影响 |
|---|---|
| A（推荐） | 在第 ⑧ 片 `W.12` 替换 `web/package.json` 桩时将 `typescript` 改为精确版本 `6.0.3`（已在 `G.10` 登记，Apache-2.0），让 `tsc --noEmit`、`vitest --typecheck`、`typescript-eslint` `strictTypeChecked` 全部正常工作；等 `typescript-eslint` 正式支持 TS 7 后在里程碑升级时再切回 7.x |
| B | 维持 `typescript@7.0.2`，改用 `typescript@7.1.0-beta` 作为别名依赖，风险是依赖非正式版且不稳定 |

## 建议

- 建议 **1 选 A**（一次性登记上述 6 个 MIT 许可的官方 devDep 到 `G.10` §3.4 和 `tools/deps/allow.txt`，同步提交推送 `sj` 与 `harness`）。
- 建议 **2 选 A**（确认允许将 `web/package.json` 的 `typescript` 从 `7.0.2` 调整为 `6.0.3`；若主线认可，前端线在 `P.09` §2.1 记入裁决并随 `W.12` 实施）。
- 收到主线回复并合入 `tools/deps/allow.txt` 后，前端线即可立刻 `rebase origin/main` 并开始第 ⑧ 片 `m1-web-base` 的代码实施与验证。
