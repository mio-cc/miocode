# 主流 harness 对照清单（demo v0.5）

> 目的：把主流 harness 在"设置、配置、模型、工具、接口管理"上的做法逐项对照，确认我们的 demo 都有对应位置；没做的写明原因和计划。
> 参考对象：DeepSeek Harness（dsh）、Codex 桌面版、Claude 桌面版、Dify、n8n、ComfyUI、Claude Code / Codex CLI。
> 日期：2026-11-22。demo：`sj/demo_v0.5/画布_demo_v0.5.html`。

## 1. 入口一览：东西在哪里管

| 我想… | 去哪里 | 快捷方式 |
|---|---|---|
| 填 API Key、换模型、测连接 | 设置 › **模型与提供方** | `Ctrl+,`；输入框模型菜单 › 管理模型… |
| 只给当前会话换模型、调推理强度 | 底部输入框右侧的**模型按钮** | 输入 `/模型` |
| 开关工具、调风险等级、配白名单 | 设置 › **工具** | — |
| 接 MCP 服务（文件系统、GitHub、数据库…） | 设置 › **MCP 服务**（支持粘贴 `mcpServers` JSON） | — |
| 装技能（SKILL.md） | 设置 › **技能** | 输入框 `@` 引用技能 |
| 装扩展包 | 设置 › **扩展包**（从 .zip 安装） | — |
| 管所有密钥 | 设置 › **密钥** | — |
| 看花了多少钱、设预算 | 设置 › **预算与用量** | 账户菜单 › 预算与用量 |
| 限并发、限每分钟请求 | 设置 › **并发与限流** | — |
| 看/改模型能做什么 | 设置 › **授权与安全**（档位 × 动作矩阵） | 顶部档位胶囊 |
| 本机地址、令牌、命令行、接口文档 | 设置 › **本机访问与命令行** | — |
| 数据放哪、占多少、导出、清空 | 设置 › **数据与存储** | — |
| 角色卡、配方、数据类型、子图库、模板 | **资源库**（左栏图标栏 📖、账户菜单、`/模板`） | — |
| 审批、运行完成/失败、连接出错 | 顶部条**铃铛**（通知中心，可直接批准/驳回） | — |
| 快捷键 | 设置 › 快捷键 | `?` |
| 重新走首次引导 | 账户菜单 › 重新查看引导；设置 › 关于 | URL 加 `?onboard=1` |

## 2. 逐项对照

| # | 能力 | 主流做法 | demo v0.5 | 状态 |
|---|---|---|---|---|

| 2 | 默认模型分工 | Dify：系统模型设置（推理 / 嵌入 / 重排）；Codex：模型 + 推理强度 | 编排者、新建 Agent 默认、摘要压缩、向量嵌入四个角色；默认推理强度；出错时换用顺序 | ✅（换用顺序的拖动排序只示意） |

| 4 | 工具管理 | Codex：沙箱 × 审批两维；Claude Code：权限白名单 | 8 个内置工具：开关、风险等级（只能调高，不低于下限）、频率上限、配置摘要；出站主机白名单；允许的文件目录 | ✅ |

| 8 | 密钥 / 凭据 | n8n：Credentials 统一管理；Dify：按提供方 | 密钥统一页：存储后端（系统密钥库 / 加密文件）、名称、末 4 位、用于谁、替换、删除（提示谁在用）；`${secret:名称}` 引用 | ✅ |
| 9 | 审批与权限 | Codex：workspace-write + on-request 为安全基线；Claude Code：默认询问 | 5 档授权 × 10 类动作矩阵（和后端判定同一份数据）；外部内容一律不可信（锁定）；同类审批合并；审批时限；沙箱后端、时限、内存、联网 | ✅ |

## 3. 主流有、我们暂时不做（写明理由）

| 能力 | 谁有 | 为什么不做 / 什么时候做 |
|---|---|---|
| 插件市场 | dsh、Dify、Codex | P.02 非目标；v1 只支持从文件安装 |
| 定时任务 / 计划运行 | dsh（实验）、Codex 自动化 | P.02 非目标；可以作为 M5 之后的扩展 |
| 云端执行、多人协作、团队空间 | Codex 云任务、Dify 工作区 | P.02 非目标（本机单用户） |
| 发布成 API / Webhook 触发 | Dify、n8n | P.02 非目标；本机 OpenAPI 只给命令行和扩展用 |
| 语音输入 | dsh（实验） | 价值低，暂不做 |
| Git / worktree 集成 | Codex | 我们不是编码 Agent；代码类任务用工具和 MCP（github）解决 |
