# G.01 文档体系规范

| 项 | 内容 |
|---|---|
| 编号 | G.01 |
| 类型 | 规范 |
| 上级 | G 工程规范 |
| 下级 | 无 |
| 状态 | 草稿 |
| 素材 | 新 |
| 最后修改 | 2026-11-22 |

## 1. 目的
项目用一棵文档树驱动实施。文档写得不统一，实施模型就会各自理解、各自发挥，越往后偏得越远。本规范规定文档本身怎么组织、怎么写、怎么改。

## 2. 适用范围
`sj/项目树_v0.5/` 下的全部文档。旧目录（引擎计划、设计规范、架构设计）只作素材，不再更新。

## 3. 规则
### 3.1 树与编号
- **G.01-R1** 每个树节点对应且只对应一份文档；树索引 `00_树索引.md` 和 `树索引.json` 是节点清单的唯一来源。
- **G.01-R2** 编号规则：一级用字母（P G C E B W U S Q O X T D R），下级逐级追加两位数字，如 `E.14.02.01`。
- **G.01-R3** 编号一旦分配不改、不复用。删除节点时状态改为"已废弃"，文件保留；新增节点只能在同级末尾追加编号。
- **G.01-R4** 文件路径按树索引"文件"列建立：有下级的节点是文件夹，节点自身的文档放在同名文件夹内；叶子是单独的 `.md` 文件。
- **G.01-R5** 树的结构（增删节点、移动节点）只能由设计方修改。实施方发现需要新节点时，按 `G.02.03` 上报。

### 3.2 上下层关系
- **G.01-R6** 下层只能细化上层，不能推翻上层。下层发现上层有问题时，不改自己去适应，而是上报，由设计方改上层。
- **G.01-R7** 冲突时的优先级：`P.04` 不变量 > `P.08` ADR > `C` 契约 > 一级分支总则 > 更上层的文档 > 更下层的文档。
- **G.01-R8** 同一事实只在一个地方写正文，其他地方只引用编号。特别是：数据结构只在 `C` 里定义；术语只在 `P.06` 里定义；依赖只在 `G.10` 里登记；错误码只在 `C.11` 里登记。
- **G.01-R9** 下层文档在"继承的上级约束"一节只写规则编号，不复制正文。

### 3.3 模板与内容
- **G.01-R10** 每份文档开头必须有文件头表：编号、类型、上级、下级、状态、素材、最后修改。
- **G.01-R11** 按类型套用 `01_文档模板.md` 里的模板；模板里的小节标题不能删，没有内容写"无"。
- **G.01-R12** 实施类叶子必须有实施卡。实施卡写不出来（比如还不知道要建哪些文件），说明这个叶子还不能交给模型实施。
- **G.01-R13** 规则必须逐条编号；每条只说一件事；写成可以判断"做到 / 没做到"的句子，不写"尽量""适当"这类词。必须保留弹性时，写明弹性的范围（例如"200–400ms"）。
- **G.01-R14** 用词只能用 `P.06` 的标准名。
- **G.01-R15** 引用其他文档写编号加名称，如 "`C.05.02` Op 类型目录"；引用规则写规则编号，如 "`G.05.01-R3`"；引用旧素材写缩写，如 "`引03` §4"。
- **G.01-R16** 代码、接口签名、数据结构直接贴代码块，不用文字描述。
- **G.01-R17** 不写人天、工期（P-R5）。
- **G.01-R18** 单份文档正文建议不超过 600 行。超过时说明这个节点应该再拆，上报设计方。

### 3.4 状态
| 状态 | 含义 | 实施模型能否据此开工 |
|---|---|---|
| 待写 | 只有索引，没有正文 | 不能 |
| 草稿 | 已写正文，未经检查 | 不能 |
| 已审 | 已通过一致性检查和用户确认 | 能 |
| 冻结 | 对应代码已经实现并通过验收；再改需走变更流程 | 能（改动需走变更流程） |
| 已废弃 | 不再使用 | 不能 |

- **G.01-R19** 状态从"草稿"到"已审"，需要满足：① 和所有祖先文档、引用的契约无冲突；② 引用的编号都存在；③ 用词符合 `P.06`；④ 实施卡完整（实施类叶子）。

### 3.5 修改流程
- **G.01-R20** 修改"已审"或"冻结"的文档：先写变更说明（改什么、为什么、影响哪些下层文档），设计方确认后再改，同时更新所有受影响的下层文档。
- **G.01-R21** 每次修改更新文件头的"最后修改"；重大修改在正文末尾加"变更记录"小节（日期、变更、原因）。
- **G.01-R22** 修改契约（`C`）时，必须同时检查所有引用它的文档（在树目录里搜索编号）。

## 4. 检查方式
| 规则 | 检查 |
|---|---|
| R1、R4、R10 | 脚本比对 `树索引.json` 和实际文件；检查文件头字段 |
| R14 | 脚本检查"不要叫"列里的词是否出现 |
| R15 | 脚本检查所有被引用的编号都存在 |
| 其他 | 设计方在批次检查时逐条核对 |

（检查脚本在 C 批次之前补上，放在 `sj/项目树_v0.5/tools/`。）

## 5. 例外
无例外。
