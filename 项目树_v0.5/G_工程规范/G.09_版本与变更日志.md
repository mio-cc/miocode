## 1. 目的
说清楚项目里有哪几种版本号、各自什么时候变，以及变更日志怎么写。

## 2. 版本号
| 版本 | 格式 | 变化规则 |
|---|---|---|
| 程序版本（`anydoor`、`anydoorctl`） | 语义化版本 `主.次.修订`，1.0 之前为 `0.次.修订` | 修订：只修缺陷；次：新功能、兼容修改；主：不兼容修改（1.0 之后） |
| schema、类型、NodeDef、扩展包、模板 | 见 `C.12` §2 | 和程序版本**独立**变化 |
| 数据库结构 | goose 迁移序号 | 每次结构变化加一个迁移 |

- **G.09-R1** 程序版本和 schema 版本分开：一次发布可以不改 schema，schema 升级也不强制程序升主版本。发布说明里写明本次程序支持的 schema 版本范围。
- **G.09-R2** 版本号在构建时注入（`-ldflags "-X main.version=…"`），代码里不写死。

## 3. 变更日志
- **G.09-R3** 根目录 `CHANGELOG.md`，格式按 Keep a Changelog：每个版本下分 `新增 / 变更 / 修复 / 移除 / 安全`。
- **G.09-R4** 每个 PR 在 `CHANGELOG.md` 顶部的 `未发布` 下加一行（只有内部重构、测试的 PR 可以不加），写用户能看懂的描述，不写实现细节。
- **G.09-R5** 涉及数据格式变化时，单独写一行"数据格式：图文档 1.0 → 1.1，旧文件会自动升级"。

## 4. 例子
```markdown
## [未发布]
### 新增
- 子图预览：点子图节点上的缩略图，可以在不离开当前层的情况下查看内部（W.06.13）
### 修复
- 连续拖动节点时历史记录出现多条（C.05.04）
```
