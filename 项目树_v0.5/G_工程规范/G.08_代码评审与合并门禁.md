## 1. 目的
规定合并前必须通过的自动检查，以及人工评审看什么。

## 3. 人工评审清单
| 看什么 | 怎么看 |
|---|---|
| 是否按文档做 | 交付说明和实施卡逐条对照（`G.02` §6） |
| 不变量 | 交付说明里列出的相关不变量是否真的没有违反 |
| 错误处理 | 失败路径有测试；错误有上下文；没有吞掉错误 |
| 并发 | goroutine 有所有者；取消能传到；共享状态有保护 |
| 安全 | 没有新的出站地址、新的文件访问、密钥接触 |
| 界面 | 截图和设计规范一致；深浅主题都检查过；键盘可操作 |
| 遗留物 | 没有调试代码、临时打印、注释掉的代码块（`G.02.05-R34`） |

## 4. 规则
- **G.08-R1** 自动门禁不通过的 PR 不进入人工评审。
- **G.08-R2** 评审意见引用规则编号（`G-R2`），例如"违反 G.05.02-R1"。
- **G.08-R3** 由模型实施的 PR 合并前必须同时满足：① 自动门禁全部通过（CI 还没有就绪的 M0 阶段，以验证者原样贴出的 `relay check` / `relay slice` 输出代替，`G.02.06-R17`）；② 交叉评审由实施者以外的一方完成，评审记录里没有未处理的"不符合""有疑问"（`G.02.06-R18`）。满足后由**验证者**合并，不需要用户逐次批准；合并后向用户报告合并提交号、检查结果和评审结论。实施者不能合并自己实施的 PR。不满足时停下，不合并，向用户说明原因（用户授权 2026-11-23，`P.09` K209）。用户随时可以收回这项授权，收回后恢复为每次合并由用户批准。
