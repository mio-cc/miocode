## 1. 目的
交付前由实施者自己逐项检查，把明显问题挡在评审之前。每一项都要能明确回答"是 / 否"。

## 2. 清单
### A. 范围
- [ ] 只改了任务包白名单里的文件
- [ ] 实施卡的每一条都已实现，没有遗漏
- [ ] 没有实现实施卡以外的功能
- [ ] 没有改动 `schema/`、`gen/`、`web/src/lib/protocol/generated/`

### B. 契约与不变量
- [ ] 用到的类型都来自生成代码，没有手写重复的结构
- [ ] 事件名、错误码、Op 类型都使用生成的常量，没有手写字符串
- [ ] 对照 `P.04`：本次改动涉及的不变量逐条确认没有违反（在交付说明里列出涉及哪几条）
- [ ] 修改图的代码全部走 Op（INV-08）
- [ ] 工具调用和 Op 都经过授权检查（INV-09）

### C. 依赖
- [ ] 没有新增依赖；或新增依赖已经在 `G.10` 登记并获批
- [ ] Go：`go mod tidy` 后 `go.mod` 无意外变化
- [ ] 前端：`pnpm-lock.yaml` 无意外变化
- [ ] `go run ./tools/depcheck` 通过

### D. 质量
- [ ] `go test ./... -count=1`（或任务包指定的范围）全部通过
- [ ] `pnpm -C web test`（涉及前端时）全部通过
- [ ] `golangci-lint run` / `pnpm -C web lint` 无新增问题
- [ ] `make gen && git diff --exit-code` 通过
- [ ] 实施卡的测试用例全部有对应测试，测试名里带用例编号
- [ ] 没有删除、跳过、放宽已有测试

### E. 规范
- [ ] 命名符合 `G.04`
- [ ] 错误处理符合 `G.05.01` / `G.13`
- [ ] 日志不含密钥和用户内容原文（`G.12`、INV-22）
- [ ] 前端：没有写死颜色、尺寸、时长（INV-20）
- [ ] 前端：所有界面文案用 `P.06` 的标准名

### F. 交付
- [ ] 交付说明已写（`G.02` §6）
- [ ] 有上报单时，受影响部分没有继续实施

## 3. 检查方式
清单 A、C、D 大部分可以由 CI 自动检查；B、E 由评审核对交付说明。
