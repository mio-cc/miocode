# G.02.01 实施任务包格式

| 项 | 内容 |
|---|---|
| 编号 | G.02.01 |
| 类型 | 规范 |
| 上级 | G.02 AI 实施者守则 |
| 下级 | 无 |
| 状态 | 草稿 |
| 素材 | 新 |
| 最后修改 | 2026-11-22 |

## 1. 目的
同一个叶子，给模型的上下文不同，产出就不同。任务包把"这次要做什么、依据是什么、做完怎么验收"固定下来，保证每次派任务都给足、不给多。

## 2. 规则
- **G.02.01-R1** 每个实施任务对应**一个**实施类叶子。一个叶子太大时，先拆叶子（上报设计方），不要在一个任务里做多个叶子。
- **G.02.01-R2** 只有状态为"已审"或"冻结"的叶子才能派任务（`G.01` §3.4）。
- **G.02.01-R3** 任务包必须包含下面第 3 节的全部部分，缺一不派。
- **G.02.01-R4** 任务包里的文档按原文附上，不做摘要（摘要会丢约束）。
- **G.02.01-R5** 文件白名单必须精确到文件路径；目录级授权只允许用于"新建该目录下的文件"。

## 3. 任务包结构
```markdown
# 任务包 · {叶子编号} {名称}

## A. 必读（按顺序）
1. G.02 AI 实施者守则
2. G.02.05 禁止事项总表
3. 祖先链：{一级总则} → … → {父节点}（全文）
4. 本叶子文档（全文，含实施卡）
5. 引用的契约：C.xx.xx …（全文）
6. 引用的规范：G.xx / U.xx / S.xx …（只附被引用的那几份）

## B. 文件白名单
- 可新建：…
- 可修改：…
- 只读参考：…

## C. 现有代码上下文
- 相关已实现模块的接口文件（只附接口，不附实现）

## D. 验收
- 实施卡里的测试用例
- 必须通过的命令：`go test ./engine/xxx/... -count=1`、`pnpm -C web test xxx` …

## E. 交付
- 按 G.02 §6 写交付说明
```

## 4. 示例
叶子 `E.14.07 聚合` 的任务包：
- 必读：G.02、G.02.05、E、E.01、E.14、E.14.07、C.03.01、C.04.01、C.04.02、C.06.02、C.11、G.05、Q.02。
- 可新建：`engine/exec/aggregate/aggregate.go`、`engine/exec/aggregate/aggregate_test.go`、`engine/exec/aggregate/ops.go`。
- 可修改：`engine/exec/registry_builtin.go`（只允许增加一行注册）。
- 验收：`go test ./engine/exec/aggregate/... -count=1` 全部通过；实施卡列出的 6 个算子用例全部覆盖。

## 5. 检查方式
派任务前由派发方（设计方或编排脚本）按第 3 节逐项检查。以后可以写成脚本，从 `树索引.json` 自动拼出任务包。
