# G.02.02 上下文最小集规则

|---|---|

| 类型 | 规范 |
| 上级 | G.02 AI 实施者守则 |
| 下级 | 无 |
| 状态 | 草稿 |

## 1. 目的
上下文太少，模型会自己补；上下文太多，模型会被无关内容带偏，或者"顺手"去改别的模块。本规则规定每类任务**需要读什么、不应该读什么**。

## 2. 规则
- **G.02.02-R1** 必读集合 = 守则（G.02、G.02.05）+ 祖先链 + 本叶子 + 本叶子引用的文档。不额外附加"可能有用"的文档。
- **G.02.02-R2** 引用只展开一层：本叶子引用了 A，就附 A；A 又引用了 B，不附 B。如果实施确实需要 B，说明本叶子漏了引用，应先修文档。
- **G.02.02-R3** 不附其他叶子的实施卡（避免模型去实现别的叶子）。
- **G.02.02-R4** 现有代码只附接口（Go 的接口和导出类型、TS 的类型和导出函数签名），不附实现。
- **G.02.02-R5** 不附旧素材（引擎计划、设计规范 v0.3 等）。素材已经被吸收进新文档，再附会引入过时内容。
- **G.02.02-R6** 不附聊天记录、讨论过程。只附结论文档。

## 3. 按任务类型的附加集合
| 任务类型 | 在 R1 之外还要附 |
|---|---|
| 内核 `E` 叶子 | `E.01` 内核总则；`G.05` Go 编码规范；`Q.02` 单元测试规范 |
| 后端 `B` 叶子 | `B.01`；`B.03` HTTP API 总则（写接口时）；`G.05`；`G.13` |
| 前端实现 `W` 叶子 | `W.01`；`G.06`；对应的 `U` 规范文档；`U.02` 设计令牌治理 |
| 画布引擎 `W.06.*` | 另加 `U.10` 画布视觉、`U.17` 性能体验预算 |
| 写测试 | `Q.01` 测试策略总则；对应的 `Q.xx` |
| 改配置 / 构建 | `G.11`、`O.01` |
| 涉及授权或工具调用 | `S.04`、`E.06` 的接口 |

## 4. 不应该附的
| 不附 | 原因 |
|---|---|
| 整棵树 | 太大，模型会抓错重点 |
| 同级其他叶子的正文 | 只附接口；正文会诱导模型去实现 |
| `P.03` 用户场景、`P.10` 参考与竞品 | 背景信息，不影响实施，容易让模型"借鉴"别人的设计 |
| `R` 附录 | 同上 |
| `P.09` 待决问题与已知不一致 | 它是裁决记录：每条裁决都已写进对应的文档（写了"已改"），实施者读对应文档就够了；附上它还会让每一棒的依据都因为新增一条裁决而失效（`G.02.06-R13`，`P.09` K199）。还没定的问题（Q）影响到某个叶子时，由设计方写进那个叶子 |

## 5. 检查方式
任务包拼装脚本按本表生成；人工派发时对照本表核对。
