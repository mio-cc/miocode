## 1. 规则
| 编号 | 规则 |
|---|---|
| G.05.03-R1 | 接口定义在**使用方**，而不是实现方。例外：跨包的核心接口（`Store`、`Model`、`Tool`、`Executor`）定义在 `E.01` 指定的位置，因为它们是内核的公开契约 |
| G.05.03-R2 | 接口尽量小；超过 5 个方法时说明理由 |
| G.05.03-R3 | 构造函数接收依赖（接口），返回具体类型：`func NewPipeline(s store.Store, a authz.Checker) *Pipeline` |
| G.05.03-R4 | 不使用包级可变变量（全局单例、全局注册表）。注册表、配置、时钟都通过构造函数传入，方便测试和多实例 |
| G.05.03-R5 | 每个包有 `doc.go`，第一句话说明包的职责，并写明对应的树节点编号，如 `// Package ctxasm 实现上下文装配（E.13）。` |
| G.05.03-R6 | 导出的东西要有注释；只为测试导出的放在 `export_test.go` |
| G.05.03-R7 | 包内实现细节放进 `internal/` 子包，避免被其他包误用 |
| G.05.03-R8 | 一个包只做一件事，名字就是这件事；文件超过 800 行时拆文件，包超过 5000 行时考虑拆包（上报设计方） |

## 2. 检查方式
`revive`（exported、package-comments）、`gochecknoglobals`（白名单：哨兵错误、生成的常量表）、`depcheck`。
