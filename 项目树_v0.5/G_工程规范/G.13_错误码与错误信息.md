## 1. 目的
规定错误码怎么用、错误信息怎么写。错误码本身登记在 `C.11`。

## 2. 规则
| 编号 | 规则 |
|---|---|
| G.13-R1 | 错误分两层：**给程序的**（错误码、details）和**给人看的**（message）。程序只根据错误码做判断，不解析 message |
| G.13-R2 | 给人看的 message 用中文，一句话，回答"发生了什么"和"怎么办"：好的例子"图已被修改，你的版本落后 2 个。已为你合并，请检查后重新提交"；不好的例子"操作失败"、"Error 409" |
| G.13-R3 | message 里不出现：堆栈、SQL、文件的绝对路径、内部包名、密钥 |
| G.13-R4 | 开发需要的细节放在日志里，用 `request_id` 关联；界面上提供"复制错误详情"按钮，复制的内容是错误码 + request_id + 时间，不含敏感信息 |
| G.13-R5 | 文案集中在 `schema/builtin/messages/*.zh.yaml`，按错误码索引，可以带变量 `{head}`、`{node}`；前后端都从这里取 |
| G.13-R6 | 新增错误码：先在 `C.11` 登记，再加文案，再写代码 |
| G.13-R7 | 同一个问题在界面上只报一次：例如 409 冲突由前端 Op 层处理成合并提示，不再弹通用错误提示（`W.05` §6.6）；协议层（`W.04`）只抛结构化错误，从不弹提示 |
| G.13-R8 | 用户能解决的错误给出操作入口（"打开设置"、"重试"、"撤销"）；用户解决不了的错误说明"这是程序问题"，并提供复制详情 |

## 3. 文案示例（`errors.zh.yaml`）
```yaml
graph_conflict: 图已被修改，你的版本落后 {behind} 个。{resolution}
node_locked: 「{label}」已锁定，只有你能修改。要让 AI 修改，请先解锁。
estopped: 急停中，AI 的操作和新的运行都已暂停。解除急停后才能继续。
provider_unavailable: 还没有可用的模型。请在设置里添加一个模型提供方。
internal: 程序出了问题，已记录。可以复制错误详情反馈给开发者。
```
