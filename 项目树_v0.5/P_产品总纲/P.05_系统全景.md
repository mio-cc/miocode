## 2. 一次运行的数据流
1. 用户点运行 → 前端 `POST /api/v1/runs` → 后端冻结图快照，写 `run.created` 事件。
2. `run` 按作用域展开图，`sched` 把输入都就绪的节点放进就绪队列，按资源池配额并发执行。
3. 每个执行器从 `RunCtx` 拿输入；Agent 节点通过 `ctxasm` 拿上下文包，通过 `llm` 调模型，通过 `tools` 调工具。每次工具调用之前都先过 `authz.Check`。
4. 所有状态变化都先写事件日志，再由 SSE 推给前端；前端按帧合并后画到画布上。
5. 碰到人工节点时，节点进入等待状态，前端出审批卡片；用户批准 → 先落事件 → 运行继续。
6. 每到安全点写检查点；进程崩溃后，从最近的检查点加上之后的事件恢复。

## 3. 一次"对话改图"的数据流
1. 用户在底部对话框输入，附带画布选中的节点 → `POST /api/v1/sessions/{id}/messages`。
2. `app/chat` 把会话摘要、当前图的精简视图、选中节点交给编排者（`orch`）。
3. 编排者用图操作工具一步步改草稿，产出 GraphPatch（一组 Op）。
4. GraphPatch 走 Op 流水线：校验 → 授权 → 图检查 → 应用 → 写事件 → 广播。档位 1 时只生成提议，前端显示成幽灵节点。
5. 回复通过会话流推回前端，显示在浮动回复和右栏对话页。
