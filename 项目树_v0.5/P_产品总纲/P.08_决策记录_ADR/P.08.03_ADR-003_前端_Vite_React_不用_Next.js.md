## 背景
v0.4 前端基于宿主的 Next.js 应用。独立产品之后，前端只服务于本机的一个用户，由 `harnessd` 静态提供。

## 考虑过的方案
| 方案 | 优点 | 缺点 |
|---|---|---|
| Next.js | 生态大，有 SSR | 本机单用户不需要 SSR；需要 Node 运行时或静态导出的种种限制；`use client` 约束多 |
| Vite + React + TypeScript | 纯客户端，构建产物是静态文件，可以直接打进二进制；开发启动快 | 没有 SSR（本项目不需要） |

## 决定
使用 Vite + React 19 + TypeScript strict + zustand。没有 SSR，没有 BFF。画布是自研的命令式渲染层，不依赖 React。

## 理由
静态产物可以直接 `go:embed`；画布性能关键路径本来就绕过 React；去掉 SSR 能消除一整类问题。

## 代价与后果
- 设计规范 18 号按 Next.js 写的目录和约束需要重写（K9）。

## 推翻条件
需要对外发布成可被搜索引擎收录的网站，或需要服务端渲染时。
