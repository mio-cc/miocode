## 背景
需要一个支持长时间运行、断点续跑、人工审批、循环和嵌套的执行内核。业界有很多现成的持久化执行框架。

## 考虑过的方案
| 方案 | 优点 | 缺点 |
|---|---|---|
| Temporal / Restate / DBOS / Inngest / Hatchet | 持久化执行成熟 | 都要求以代码定义流程，和"图文档是唯一事实来源"冲突；多数需要独立服务进程，与单二进制形态冲突 |
| LangGraph | 检查点、中断成熟 | Python / JS 生态；用代码定义图 |
| Vercel Workflow DevKit | 开发体验好 | 绑定特定运行环境 |
| Go 自研内核 + 事件日志 | 完全贴合 13 原子节点、Op、授权、回放的设计；可以打进单二进制 | 需要自己实现调度、检查点、续跑 |

## 决定
内核用 Go 自研：图模型、调度、执行器、Op、授权、事件日志全部自己实现。模型 SDK、MCP、沙箱、表达式求值、评测等外围能力使用现成组件。

## 理由
1. 本项目的核心价值（13 原子节点、Op 统一修改、模型作为操作者、授权贯穿）恰好是这些框架没有的部分，套用它们反而要绕路。
2. 事件溯源 + 检查点的模式在参考项目里已经被验证过（`P.10`），可以照着思路自己实现。
3. Go 便于编译成单个可执行文件，跨平台分发。

## 代价与后果
- 调度和续跑的正确性要靠严格测试保证：属性测试和故障注入是必须项（`Q.03`、`Q.09`）。

## 推翻条件
出现必须支持多机分布式执行的需求时，重新评估 Temporal 或 Restate 作为执行层。
