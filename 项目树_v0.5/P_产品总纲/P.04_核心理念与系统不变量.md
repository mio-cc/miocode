> 这里是全项目**永远不能违反**的规则。每条都写明违反会出什么问题，以及靠什么保证。下层文档引用时写编号，如"遵守 INV-08"。

## 1. 核心理念
1. **系统 = 节点库 + 契约层 + 运行时。** 主脑、智囊团、执行池这些"角色"只是用原子节点拼出来的模板，不是系统里写死的部分。
2. **积木拼完还是积木。** 任何子图对外都只是一块积木，可以无限组合、嵌套。
3. **节点内部可以聪明，节点之间必须"笨"。** 节点之间怎么通信、有什么权限、能怎么连，全部写死，由运行时强制执行。
4. **可扩展、高度自定义。** 节点、类型、工具、模型、配方、角色卡都可以注册扩展；内置的 13 个原子节点也走同一套注册机制，不享受特权。
5. **大模型是一等操作者。** 人和模型用同一套 Op 改图、跑图、看图。

## 2. 系统不变量
| 编号 | 不变量 | 违反会怎样 | 靠什么保证 |
|---|---|---|---|
| INV-01 | 原子节点只有 13 种：资源、Agent、上下文装配、工具、扇出、汇合、聚合、分支、循环、账本、人工、子图端口、子图引用。增减原子节点必须新开 ADR | 内核膨胀，"角色"被写死进系统 | `C.03` 注册表清单；评审 |
| INV-02 | 内置节点和扩展节点走同一套 NodeDef 注册，内核里不能有针对某个节点类型名的特殊分支（执行器内部除外） | 扩展节点做不到内置节点能做的事 | `E.03` 注册表；lint 规则禁止在调度和校验代码里比较类型名 |
| INV-03 | 子图对外只暴露端口、参数、摘要端口、升级端口、权限需求、预算需求 | 子图无法独立复用和替换 | `C.02.04` |
| INV-04 | 节点之间只通过端口连线传递数据；没有隐式共享状态。需要共享状态时，必须显式使用账本节点 | 运行不可复现，并行时出现竞态 | `E.14` 执行器只能拿到自己的输入 |
| INV-05 | 只有 Agent 节点调用模型（编排者本身也是 Agent） | 费用和行为无法统计、无法授权 | `E.10` 只向 Agent 执行器和编排者开放 |
| INV-06 | 只有循环节点能形成环 | 调度死锁，运行无法终止 | `E.03.03` 图校验规则 |
| INV-07 | Agent 的 context 输入只能来自上下文装配节点（ctx 端口严格匹配） | Agent 看到的内容失控，预算失效 | `C.04.02` 兼容规则 |
| INV-08 | Op 是修改图的唯一入口。人、模型、运行时、外部系统都一样；每种 Op 都有逆操作 | 改动无法审计、撤销、回放 | `E.05`；store 层不提供绕过 Op 的写接口 |
| INV-09 | 每个 Op、每次工具调用都必须经过 `authz.Check`，结果只有允许、需审批、拒绝三种 | 模型越权 | `E.06`；集成测试覆盖 |
| INV-10 | 急停只能由人解除。模型和运行时都无权调用解除接口 | 失控时停不下来 | `E.06.04`；API 层校验 actor |
| INV-11 | 运行状态的唯一来源是追加写入的事件日志；外部输入（审批结果、人工输入、回调）先落事件再处理 | 断点续跑和回放不可靠 | `E.09.01`、`E.16` |
| INV-12 | 每次运行冻结一份图快照；运行中改图只在安全点（作用域边界）生效 | 运行到一半图变了，结果说不清 | `E.16.02` |
| INV-13 | 任意一次运行都能从事件日志完整回放；回放不调用模型，直接使用记录下的结果，包括运行时展开的子图 | 回放产生费用，结果和原来不同 | `E.16.05`、`Q.09` |
| INV-14 | 有副作用的工具（风险等级 L1 及以上）必须带幂等键，调用前先落"意图"事件 | 续跑时重复发邮件、重复扣费 | `E.11` |
| INV-15 | 授权档位（模型能改多少）和工具风险等级（工具会碰到什么）是两个独立维度，不合并成一个矩阵 | 授权规则不可理解 | `C.09`、`E.06` |
| INV-16 | 由外部内容引出的 Op 和工具调用带污染标记；开启防护时一律转为需审批 | 提示词注入导致越权 | `E.06.03`、`S.05` |
| INV-17 | `schema/` 下的 JSON Schema 是数据格式的唯一事实来源，Go 和 TS 类型由它生成，不手写 | 前后端格式不一致 | `G.16`；CI 检查生成物一致 |
| INV-18 | 模型厂商差异写成数据（quirks 表），不散落在代码分支里 | 新增厂商要改一堆代码 | `E.10.05` |
| INV-19 | `engine/` 不依赖 `internal/`、`cmd/`，也不依赖 `net/http`（llm、内置 http 工具、mcp 例外） | 内核无法独立复用和测试 | `tools/depcheck` 进 CI |
| INV-20 | 界面上的颜色、尺寸、动效只能使用设计令牌（`--hx-*`），不写裸值 | 主题和视觉一致性失控 | `U.02`；样式 lint |
| INV-21 | 服务只监听 127.0.0.1；所有请求都要通过本机鉴权 | 局域网或恶意网页可以操控本机 | `B.03.05`、`S.02` |
| INV-22 | 密钥不进事件、不进日志、不进前端（界面只显示末 4 位） | 密钥泄露 | `S.03`；日志脱敏测试 |
| INV-23 | 所有 ID 使用 ULID；所有时间存 UTC，只在展示时转成本地时区 | 排序和跨时区错误 | `C.01` |
| INV-24 | 每个操作和事件都标明操作者（`user` / `model` / `runtime` / `external` 四种之一） | 无法区分人和模型做的事 | `C.05.01`、`C.06.01` |

## 3. 冲突时怎么判断
1. 先看是否违反上表任何一条。违反的方案直接否决。
2. 都不违反时，按第 1 节的理念取舍。
3. 仍然无法判断时，写进 `P.09` 待决问题，不要自行决定（见 `G.02.03`）。
