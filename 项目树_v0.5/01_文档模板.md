# 文档模板

> 所有文档按下面的模板写。先复制对应类型的模板，再填内容。没有内容的小节写"无"，不要删掉小节标题，方便检查有没有漏写。

---

## 通用文件头（所有类型都要有）

```markdown
# {编号} {标题}

| 项 | 内容 |
|---|---|
| 编号 | E.14.02 |
| 类型 | 总则 / 规范 / 实施 / 说明 |
| 上级 | E.14 exec 执行器 |
| 下级 | E.14.02.01、E.14.02.02、E.14.02.03（没有写"无"） |
| 状态 | 待写 / 草稿 / 已审 / 冻结 |
| 素材 | 引03 §5；demo src/28_run.js |
| 最后修改 | 2026-11-22 |
```

---

## A. 总则（一级分支用）

1. **这一枝管什么**：一段话。
2. **明确不管什么**：逐条列出，并写明归哪一枝管。
3. **下级清单**：编号、名称、一句话。
4. **整枝共同约束**：逐条编号 `{编号}-R1, R2…`，下级文档必须遵守。
5. **和其他分支的接口**：依赖谁、被谁依赖、通过什么契约（写 `C.xx` 编号）。
6. **本枝术语**：只列本枝特有、且已登记在 `P.06` 的术语。

## B. 规范

1. **目的**：为什么需要这条规范，不遵守会出什么问题。
2. **适用范围**：适用于哪些目录、哪些人或模型。
3. **规则**：逐条编号 `{编号}-R1…`；每条一句话说清楚，必要时附正例和反例。
4. **检查方式**：能自动检查的写工具和命令；不能自动检查的写评审时看什么。
5. **例外**：允许的例外及审批方式；没有就写"无例外"。

## C. 实施（产出代码的节点）

1. **职责**：一句话。
2. **不做什么**：逐条列出，并写明归谁做。
3. **继承的上级约束**：引用祖先文档里的规则编号，不要复制正文。
4. **接口**
   - 对外提供：类型、函数签名、HTTP 路径或组件 props（直接贴代码）。
   - 依赖：用到哪些其他模块的接口（写编号）。
5. **数据结构**：引用 `C.xx`；只允许定义模块内部私有的结构。
6. **行为**：正常流程分步写；状态变化画状态表。
7. **不变量**：任何时候都必须成立的条件。
8. **错误处理**：每种错误的触发条件、错误码（引用 `C.11`）、调用方能看到什么。
9. **性能与资源**：时间、内存、并发上限（有要求才写）。
10. **验收标准**：逐条可验证，每条对应至少一个测试用例。

### 实施卡（只有叶子才有）

```markdown
### 实施卡
- 要建 / 要改的文件：（列完整路径）
- 不许碰的文件：（列路径或目录）
- 函数签名：（贴代码）
- 测试用例：（编号、输入、期望输出）
- 允许使用的依赖：（只能从 G.10 已登记清单里选）
- 禁止事项：（引用 G.02.05，再加本叶子特有的）
- 完成标志：（引用 G.14，再加本叶子特有的）
```

## D. 说明

1. **读者**：谁会读，读完能做什么。
2. **正文**：按问题组织，一节回答一个问题。
3. **示例**：至少一个完整示例。
4. **相关文档**：编号列表。
