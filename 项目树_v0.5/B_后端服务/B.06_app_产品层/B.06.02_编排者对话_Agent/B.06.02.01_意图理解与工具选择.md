## 1. 职责
决定每条用户消息该怎么处理：回答、改图、控制运行、导航，或追问澄清；准备上下文，提供对话专用的工具集。

## 2. 不做什么
- 不实现图操作工具（`E.17.02`）

## 3. 继承的上级约束
`B.06.02-R1`–`R3`、`E.17`、`S.05`（外部内容）。

## 4. 接口
对话专用工具（在图操作工具集之外）：
| 工具 | 类型 | 作用 |
|---|---|---|
| `focus` | 导航 | 生成"看这里"卡片：`{graph_id, scope, node_ids, note}` |
| `open_graph` | 导航 | 切换会话的当前图 |
| `instantiate_template` | 改图 | 从模板新建图（`B.06.05`），授权按 `op.add_node` 判定 |
| `start_run` / `pause_run` / `cancel_run` | 运行 | 授权 `run.start` 等（1 档需审批，`C.09` §5） |
| `read_run` | 读 | 当前或指定运行的状态摘要、失败节点、费用 |
| `explain` | 读 | 读取节点定义和当前参数，供解释"这个节点是干什么的" |
| `ask_user` | 澄清 | 结束本次回复，向用户提问（可带选项按钮） |

## 5. 行为
**上下文**（配方"对话编排者配方@1"）：
1. 会话摘要（较早的消息压缩成的摘要，存会话 `digest` 字段）+ 最近 10 条消息原文。
2. 当前图的精简视图（`read_graph`，以用户所在的层为中心，深度 1）。
3. 选中附带（`C.10` Selection）：选中节点的完整参数；即使没选中，也有"用户当前所在的层"。
4. 最近一次运行的摘要（状态、失败节点、费用）。
5. 当前档位和它的含义（"你只能提出修改建议"）。

**处理方式**——不做单独的意图分类模型，由角色卡引导同一个 Agent 选择工具：
- 问题（"这个节点是干什么的"）→ 读类工具 + 文字回答，不产生 GraphPatch。
- 修改（"在这后面加人工复核"）→ 图操作工具改草稿 → `finish` → 按档位直接生效或变成提议。
- 运行控制（"跑一下"、"停"）→ 运行工具。
- 有歧义或缺关键信息 → `ask_user`，不猜。
- 对话框快捷 chips（`U.09.01`）只是预填文字，没有特殊处理。

**会话摘要**：消息超过 20 条时，在回复结束后把最早的 10 条交给内部摘要执行（`exec.Summarizer`），追加到会话摘要；摘要和原消息都保留，原消息不删。

## 6. 不变量
- 对话 Agent 的每次图修改都经过与其他模型相同的授权
- 急停时对话 Agent 只能使用读类工具

## 7. 错误处理
工具失败：作为工具结果交给模型；模型调用失败：回复失败（`message.failed`），显示错误和"重试"。

## 8. 验收标准
1. S2 场景：选中验收者 + "加人工复核" → 档位 1 提议 / 档位 3 直接生效（`E1701-T1`）
2. 问题不产生 GraphPatch
3. "跑一下"在 1 档产生审批
4. 急停时只能回答
5. 有歧义时追问
