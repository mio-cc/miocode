## 1. 职责
底部对话框背后的 AI。它就是 `E.17` 的编排者，以会话为上下文运行：理解用户的话 → 回答问题、修改图、控制运行、带用户去看画布上的某处 → 把回复和卡片流式写回会话。

## 2. 执行方式
- 每条助手回复是一次**内部运行**，`hx_runs.kind = chat`，`session_id` 为当前会话（运行列表默认不显示这类运行）。这样模型调用、工具调用、费用、授权、审计都复用内核的标准机制（`P.09` K36）。
- 运行的图是这个会话的**对话入口图**（`P.06`）：会话的 `entry_graph_id`，没有就用设置 `chat.entry_graph`（`C.10-R9`）。它是一张普通的图，用户可以在画布上打开、编辑，像别的 Agent 一样给对话 Agent 连模型、角色卡、提示词、工具，或接子图（`P.09` K233）。
- 默认的对话入口图由内置模板 `templates/_internal/chat.json` 在首次启动时生成，写进 `chat.entry_graph`：子图端口（入口：用户消息、会话上下文、选中附带）→ 上下文装配（配方"对话编排者配方@1"）→ Agent（`tags = [编排者]`；`model` ← 资源节点 kind=模型，取设置 `models.orchestrator`；`role` ← 资源节点 kind=角色卡"对话编排者@1"；`tools` ← 图操作工具集 + 对话工具集）→ 子图端口（出口：回复）。
- 每条回复冻结一份入口图快照再跑（INV-12）：回复过程中改入口图，从下一条回复起生效。
- actor：`model`，`id` = 实际使用的模型（`Session.orchestrator_model` 覆盖时是它，否则是入口图里连的），`instance_id = chat:<会话 ID>`，`tags` 取入口图里那个 Agent 节点的 `tags`（默认 `[编排者]`）。

## 4. 共同约束
- **B.06.02-R1** 对话 Agent 不是新的引擎概念，不享受任何特权：改图走 Op 流水线和授权（INV-08、INV-09）；急停时只能回答问题（`U.19.04`）。
- **B.06.02-R2** 同一会话同时只有一条回复在生成（`B.04.09`）。
- **B.06.02-R3** 对话 Agent 用的模型：`Session.orchestrator_model` 有值时用它（对话框上的临时覆盖，只对这个会话），否则用入口图里 Agent 的 `model` 端口上游的模型（默认入口图里是设置 `models.orchestrator`，`P.09` Q17、K233）；思考强度取 `Session.orchestrator_effort[编排者模型]`，没有记录时用设置里的默认强度（`C.10-R6`）；没有任何可用模型时，回复一条固定文案"还没有可用的模型……"并带"去设置"卡片，不报错。

- **B.06.02-R4** 设置或更换对话入口图时（`B.06.03`、`PATCH /sessions/{id}`）检查：恰好一个入口、一个出口子图端口，出口的回复由一个 Agent 节点提供；不满足返回 400，不新增诊断码。入口图里没有接图操作工具集时，对话 Agent 只能回答、不能改图，设置页和对话框提示一次。
- **B.06.02-R5** 对话 Agent 修改**自己正在使用的对话入口图**，授权动作按 `orch.self_modify` 判定（`C.09` §5：0–2 档拒绝、3 档需审核、4 档允许），不按普通的 `op.*`；用户修改不受限制（`P.09` K233）。
