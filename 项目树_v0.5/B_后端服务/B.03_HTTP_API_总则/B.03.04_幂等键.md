## 1. 职责
实现 `Idempotency-Key` 请求头：同一个键的重复请求返回第一次的结果，避免网络重试导致重复创建或重复提交。

## 2. 不做什么
- 不处理工具调用的幂等（`E.11.01`，那是另一套）

## 3. 继承的上级约束
`引09` §1、`C.11`（`idempotency_mismatch`）。

## 4. 接口
- 所有 POST 都可以带 `Idempotency-Key: <ULID>`；前端协议层对所有 POST 自动加（`W.04.01`）。
- 存储：`hx_idempotency(key, request_hash, response, status_code, created_at)`，保留 24 小时（`B.09` 清理）。

## 5. 行为
1. 收到带键的 POST：计算 `request_hash = sha256(方法 ‖ 路径 ‖ 规范化请求体)`。
2. 键已存在且哈希相同：直接返回保存的响应，加头 `Idempotent-Replay: true`。
3. 键已存在但哈希不同：409 `idempotency_mismatch`。
4. 键不存在：先插入占位记录（状态 in_progress），执行处理函数，保存响应（只保存 2xx 和 4xx；5xx 不保存，允许重试）。
5. 同一个键并发两个请求：第二个等第一个完成（最多 30 秒）后按第 2 步返回。

## 6. 不变量
- 同一个键的副作用最多发生一次

## 7. 错误处理
占位记录超时（处理函数 panic）：5 分钟后视为不存在。

## 8. 验收标准
1. 重复请求返回相同响应和 Replay 头
2. 不同请求体同一个键 409
3. 并发同键只执行一次
4. 5xx 可以重试
