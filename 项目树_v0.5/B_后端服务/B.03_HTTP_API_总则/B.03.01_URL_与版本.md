## 1. 职责
规定 URL 结构和版本策略。

## 2. 不做什么
- 不列出具体接口（`B.04`）

## 3. 继承的上级约束
`G.04.04`。

## 4. 接口
| 规则 | 内容 |
|---|---|
| 前缀 | `/api/v1` |
| 资源 | 小写复数名词，多个单词用连字符：`/graphs`、`/runs`、`/mcp-servers` |
| 子资源 | `/graphs/{id}/ops`、`/runs/{id}/events` |
| 动作 | 不能用标准方法表达时：`POST /资源/{id}/动词`（`/runs/{id}/pause`） |
| 方法 | GET 读、POST 新建或动作、PATCH 局部修改元信息、PUT 整体替换（只用于设置）、DELETE 删除（软删除） |
| 前端路由 | 非 `/api/` 前缀全部交给前端（`B.02`） |

## 5. 行为
- **版本**：v1 内只做兼容修改（`C.01-R17`）；破坏性修改出 `/api/v2`，v1 至少保留一个次版本周期。
- 响应头 `X-Harness-Version: <程序版本>`、`X-Schema-Version: <图文档格式版本>`。
- 前端发现服务端版本与自己构建时的版本不同（单二进制下只会在开发模式出现）：顶部提示"请刷新页面"。

## 6. 不变量
- 所有接口都在 `/api/v1` 下（health 的根路径别名除外）

## 7. 错误处理
不存在的路径：404 `not_found`；方法不支持：405 + `Allow` 头。

## 8. 验收标准
1. 路由表里没有违反命名规则的路径（脚本检查）
