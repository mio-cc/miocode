## 1. 职责
实现 Agent 的两种生命周期：`ephemeral`（每次执行从零开始）和 `resident`（长驻：在事件模式循环里被反复唤醒，保持记忆）。

## 2. 不做什么
- 不实现事件循环本身（`E.14.09.01`）

## 3. 继承的上级约束
`引06` §7、`P.09` K32、INV-04（共享状态必须走账本）。

## 4. 接口
```go
type MemoryPolicy struct {
    CompactAt    float64 // 0.4：工作记忆超过窗口 40% 时压缩
    KeepTurns    int     // 3：最近 3 次交互保留原文
    RebuildFrom  []string // 账本路径：目标树、决策日志、待决事项
    DigestBudget float64 // 0.08
    ReanchorEvery int    // 5：每 5 次唤醒重新插入原始意图和约束
}
```

## 5. 行为
- `ephemeral`：默认。每次执行只看本次的上下文包，执行完不保留任何东西。
- `resident`：只在 `trigger=event` 的循环内部有效（Validate：其他位置报 V03 warn 并按 ephemeral 处理）。每次唤醒的装配顺序：
  1. 账本快照（`RebuildFrom` 指定的字段，是长期记忆，每次读最新值）；
  2. 阶段摘要（账本 `digests[]` 最近 N 段）；
  3. 最近 `KeepTurns` 次交互原文（工作记忆，存检查点）；
  4. 本次触发事件（简报或升级）。
- 压缩：工作记忆超过阈值时，把较早的交互交给 `exec.Summarizer`（内部 Agent 执行，`P.09` K32），摘要追加到账本 `digests`，工作记忆只留最近 `KeepTurns` 次。
- 重新锚定：每 `ReanchorEvery` 次唤醒，在上下文最前面插入"原始意图 + 约束"，规则段要求模型回答"当前方向是否偏离初衷"。

## 6. 不变量
- 长驻 Agent 的记忆只存在于检查点和账本里（进程重启后可以完全恢复）

## 7. 错误处理
账本读取失败：transient。

## 8. 验收标准
1. 连续唤醒 20 次，工作记忆不超过阈值
2. 重启后恢复的记忆与重启前一致
3. 重新锚定按周期出现
