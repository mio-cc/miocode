## 1. 这一组管什么
`engine/llm`：Agent 节点和编排者调用模型的唯一通道（INV-05）。**按接口协议实现，不按厂商实现**（ADR-011，`P.09` K250）：代码只实现几种主流协议；接哪一家、地址、鉴权、请求头、模型名、请求体怎么改、能力是什么，全部写在**模型提供方**的配置里（`E.10.01` 的 `ProviderConfig`，在界面上是一种连接，`C.16`）。新增厂商、中转站、本地模型、私有部署只加配置，不改代码。

## 3. 两层：模型提供方与其他 API
| | 模型提供方（本组） | 其他 HTTP API（ComfyUI、出图、语音、搜索……） |
|---|---|---|
| 谁调用 | 只有 Agent 节点和编排者（INV-05） | 工具节点、声明式 http 节点（`E.11.04`、`C.03.04`），经过授权（INV-09）和出站白名单（`S.07`） |
| 怎么接 | 选一种接口协议，填提供方配置 | 写声明式节点或工具；多步请求、异步等结果、文件结果的写法在 M2 做（`P.07` M2、K250） |
| 共用 | 连接（`C.16`）、密钥库（`B.07.02`）、`{{secret:名}}` 的写法、"测试连接" | 同左 |

出图、嵌入、语音这类不是对话的模型不接进本组：它们按工具接入，结果是工作区文件或结构化数据，再交给后续节点。

## 4. 共同约束
- **E.10-R1** 只有 `RunCtx.LLM()` 能拿到可调用的 Client（INV-05）；`llm` 包本身不检查调用方，检查在 `exec`（`E.01` Caps）。
- **E.10-R2** 厂商差异写成数据（INV-18）：协议代码不知道自己连的是哪一家，按"协议 + 上游模型名"查 quirks 表（`E.10.05`），提供方配置再覆盖；代码里禁止比较厂商名、模型名（`G.05.05-R2`，`quirkscheck` 检查）。
- **E.10-R3** 三种协议共用一套契约测试（流式文本、工具调用、结构化输出、用量、错误、模型列表），全部用录放数据跑，测试不调真模型（`Q.06`）。
- **E.10-R4** 密钥只在发请求的那一刻通过 `SecretResolver` 取（`S.03-R3`）；提供方配置里只有密钥名。
- **E.10-R5** 在测试二进制里（`testing.Testing()` 为真），`E.10.01` 的 HTTP 传输层拒绝连接回环地址以外的主机，返回"测试中不允许调用真实模型"；只有 `-record` 录制时放开（`Q.06-R2`，`P.09` K191）。`E.10.01` 实现，三种协议的契约测试各验证一次。
- **E.10-R6** 协议只用 Go 标准库实现（`net/http`、自写的 SSE 解析），不引入厂商 SDK 和第三方聚合库（ADR-011、ADR-010）。
- **E.10-R7** 加一种协议：在 `engine/llm/protocol/<名>/` 写一个实现 `llm.Protocol` 的包，在组装处显式传给 `llm.NewRegistry`（不用 `init` 全局注册，`E-R3`），通过契约测试；不改其他协议和上层。协议名加进 `E.10.01` 的协议表。
