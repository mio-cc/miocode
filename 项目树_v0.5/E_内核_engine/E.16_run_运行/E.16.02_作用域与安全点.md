## 1. 职责
定义作用域和安全点，实现运行中改图的"热更新"：哪些修改可以在当前运行里生效、在哪个时刻生效。

## 2. 不做什么
- 不决定用户是否确认热更新（界面，`U.13`；`P.09` Q19）

## 3. 继承的上级约束
INV-12、`引03` §8、`_关键决定`（安全点 = 作用域边界）、`P.09` Q19。

## 4. 接口
```go
type Scope struct { Loc gen.Loc; Kind string }   // loop_round | fanout_item | subgraph_entry | event
func (r *Run) OnGraphChanged(version int64, ops []gen.Op)       // 由 op.Pipeline 的 afterCommit 通知
func (r *Run) ApplyPendingPatch(scope Scope) []gen.Op            // 执行器在安全点调用（循环每轮开始等）
```

## 5. 行为
| 作用域 | 安全点 |
|---|---|
| 循环的一轮 | 下一轮开始前 |
| 事件模式循环的一次事件 | 下一个事件开始处理前 |
| 扇出的一份 | 下一份开始前（已开始的份不受影响） |
| 子图引用的一次执行 | 子图入口执行前 |

1. 运行中图被修改（人或模型）：Op 照常进入图的新版本。
2. 运行判断这些 Op 是否影响本次运行：
   - 只改视图（`C.02.05-R2`）→ 忽略。
   - 只改参数 → 可以热更新。
   - 增删节点、连线、改子图结构 → 只有当修改**全部位于某个尚未执行完的循环体或子图内部**时可以热更新。
   - 其他 → 不热更新，只在下一次运行生效，并通知前端"这次运行不受影响"。
3. **默认需要用户确认**（`P.09` Q19）：可以热更新的修改先挂成"待确认"，前端提示"把这处修改应用到正在进行的运行？"；用户确认后挂到对应作用域的 `pendingPatch`。档位 4 的模型修改也需要用户确认。
4. 到达安全点时应用，写 `run.graph_swapped{from_version, to_version, op_ids, scope_path, at_round}`；运行快照本身不变，热更新记录在事件里，回放时按事件重现。
5. 正在执行的节点永远不被改动。

## 6. 不变量
- 正在执行的节点不受任何热更新影响
- 回放时热更新按事件重现，结果与原运行一致

## 7. 错误处理
补丁在安全点应用失败（校验不通过）：丢弃补丁，写 warn 事件，运行继续用原图。

## 8. 验收标准
1. 循环第 2 轮运行中改并发参数，第 3 轮生效
2. 改循环外结构不热更新
3. 未确认的修改不生效
4. 回放重现热更新
