## 1. 职责
实现取消和暂停沿 context 树传播，以及与急停的联动。

## 2. 不做什么
- 不实现急停状态管理（`E.06.04`）

## 3. 继承的上级约束
`引03` §6、`S.09` §2、`C.06.02`（cancelled 的 cause）。

## 4. 接口
```
runCtx（WithCancelCause）
 └─ 节点执行 ctx：根图/闭环迭代（循环）
     └─ 作用域 ctx：#r2
         └─ 节点执行 ctx：执行池（扇出）
             ├─ 作用域 ctx：#1 → 节点执行 ctx：执行者 → 模型调用 ctx
             └─ 作用域 ctx：#2 → …
```

## 5. 行为
| 类型 | 触发 | 行为 |
|---|---|---|
| 硬取消 | 用户取消、急停、预算耗尽、运行超时 | 立即 cancel 运行根 context；模型流式请求中断；不可中断的工具等它返回但丢弃结果；写 `run.cancel_requested` → 各节点 `cancelled{cause}` → `run.status: cancelled` |
| 软取消 | 汇合 first、扇出 k_of_n 满足 | 只取消专属上游支路或其余份（`graph.Dominated`）；共享上游不受影响；cause `k_of_n_satisfied` / `first_satisfied` |
| 暂停 | 用户暂停 | 不 cancel；停止派发；执行器在安全点阻塞 |

- `context.Cause` 记录原因，写进每个被取消节点的事件。
- 急停：`E.06.04` 通知 → 对应运行（全局急停 = 全部运行）硬取消，cause `estop`；**1 秒内**所有节点进入终态（`S.09` §4）：等待超过 1 秒仍未返回的工具调用，节点直接标 cancelled，结果到达后丢弃。
- 检查点保留，解除急停后可以从检查点分叉继续。

## 6. 不变量
- 取消后没有遗留的 goroutine（goleak 检查）
- 急停后 1 秒内所有节点终态

## 7. 错误处理
无。

## 8. 验收标准
1. 硬取消传播到最深层模型调用
2. 软取消不影响共享上游
3. 急停 1 秒内终态（虚拟时钟 + 真实时钟各一次）
4. goleak 通过
