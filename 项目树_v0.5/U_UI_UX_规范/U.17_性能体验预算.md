## 1. 体验预算（验收标准）
| 指标 | 目标 | 测量环境 |
|---|---|---|
| 首屏可交互（冷启动，打开浏览器到能操作） | ≤ 1.5 秒 | 中端笔记本（4 核、16GB），Chrome |
| 切换会话 | ≤ 300ms | 同上 |
| 进入 / 返回子图（不含转场动画） | ≤ 100ms | 200 节点的子图 |
| 任何操作的视觉反馈 | ≤ 100ms | — |
| 拖动节点、平移、缩放 | 60fps（单帧 ≤ 16ms） | 200 节点、300 连线 |
| 运行中画布更新 | 60fps；每帧合并一次事件（`W.06.15`） | 30 个节点同时运行 |
| 输入框打字延迟 | ≤ 50ms | — |
| 图校验（增量） | ≤ 5ms；全量 500 节点 ≤ 20ms | — |
| 前端包体积（gzip） | 首屏 JS ≤ 350KB；字体 ≤ 600KB | — |
| 内存 | 打开 200 节点的图 ≤ 300MB（浏览器标签页） | — |

## 2. 硬性实现要求（沿用设计规范 v0.3 §11）
| 编号 | 规则 |
|---|---|
| U.17-R1 | 平移和缩放只改**一个**世界容器的 `transform: translate3d() scale()`，设 `will-change: transform` |
| U.17-R2 | 端口坐标用布局常数计算，不用 `getBoundingClientRect` |
| U.17-R3 | `pointermove` 只记录最新坐标，在 `requestAnimationFrame` 里统一处理，每帧最多一次 |
| U.17-R4 | 拖动节点时只更新被拖节点的 `transform` 和相连连线的 `d`，不重建其他 DOM |
| U.17-R5 | 节点 DOM 按 ID 复用；状态变化只切换 class 和文字，不重写 innerHTML |
| U.17-R6 | 拖动用 `setPointerCapture` |
| U.17-R7 | 节点数 > 150 时开启视口裁剪（`U.10.06-R3`） |
| U.17-R8 | 连线全部放在一个 SVG 里；流动动画只加在活跃连线上（`U.07.03-R1`） |
| U.17-R9 | 缩放过程中暂停网格和文字过渡，停止 120ms 后恢复 |
| U.17-R10 | 平移、缩放、拖动、运行状态更新期间，React 提交次数为 0（`G.06.02-R4`） |
| U.17-R11 | 预览浮层、父图位置卡、节点缩略图、小地图用 canvas 绘制，刷新间隔 ≥ 400ms（运行中）或只在结构变化时重画 |

## 3. 检查方式
`Q.08` 性能基准在 CI 里跑（Playwright + Performance API）；低于基线 95% 时门禁失败（`G.08`）。前端的场景、指标、基线和参考机测量见 `W.11` §6.4–§6.6：比较的是帧耗时而不是帧率（无头浏览器帧率封顶 60）；§1 里受机器影响大的时长（如首屏 1.5 秒）按"测量环境"一列在中端笔记本上判定，每个里程碑结束前测一次（`P.09` K169）。
