## 1. 两级急停
| 级别 | 范围 | 谁能触发 | 谁能解除 |
|---|---|---|---|
| 运行级 | 一次运行 | 用户；规则（预算超限等）；**模型自己**（允许模型"踩刹车"） | 只有用户 |
| 全局 | 整个 Harness | 用户（界面按钮、`Ctrl+.`）；`harnessctl estop` | 只有用户 |

## 2. 触发后
1. 立即取消对应运行的根 context，取消沿 context 树传到所有执行器和进行中的模型、工具调用（1 秒内全部停止，`P.07` M3）。
2. 所有模型主体视为 0 档；未处理的审批一律标为已取消；未处理的提议保留但不能采纳。
3. 写 `estop.triggered` 事件和审计记录，推送前端。
4. 已完成节点的结果和检查点保留；解除后可以从检查点继续。
5. 全局急停期间：拒绝所有 `actor.kind=model` 的 Op（423）；拒绝启动新运行（包括用户发起的，`U.19.04`）；用户只能只读和解除急停。

## 3. 规则
| 编号 | 规则 |
|---|---|
| S.09-R1 | 急停状态保存在内存原子变量里，同时持久化到数据库；重启后仍处于急停 |
| S.09-R2 | **两层拦截**：内核 `authz.Check` 第一步就对非用户主体的 `estop.release` 硬编码拒绝；API 层的解除接口只接受用户会话（cookie）或 `harnessctl`（Bearer token），拒绝任何内部调用路径 |
| S.09-R3 | 模型的工具集里没有解除急停的工具；对话 Agent 被要求解除时，只能回复"需要你点「解除急停」" |
| S.09-R4 | 急停按钮触发不需要确认；解除需要确认（`U.14.04`） |
| S.09-R5 | 解除后档位保持 0，不自动恢复原档位 |

## 4. 验收标准
1. 模型通过任何途径（工具调用、Op、HTTP 请求）解除急停：全部失败。
2. 急停后 1 秒内所有运行中的节点进入终态。
3. 急停后重启 `harnessd`：仍处于急停。
