> 数据格式和判定表在 `C.09`；本文规定产品层面的授权规则和审批规则。

## 1. 授权
| 编号 | 规则 |
|---|---|
| S.04-R1 | 两个独立维度：档位（模型能改多少）和工具风险等级（工具会碰到什么），不合并（INV-15） |
| S.04-R2 | 默认档位：会话默认 1 档（建议）；外部调用 0 档 |
| S.04-R3 | 用户不受授权书约束，但受急停约束 |
| S.04-R4 | 档位 4 的模型也不能：解除急停；修改授予自己的授权书；新建比自己更宽的授权书；关闭审计；设置 `l3_skip_human`；设置节点锁 |
| S.04-R5 | 编排者生成子编排者时，子编排者的权限 ⊆ 父编排者；预算从父级**划拨**，不新增额度；嵌套深度上限默认 3，最多 8 |
| S.04-R6 | 授权书收回在安全点生效；但 L2、L3 工具调用在发出前**再检查一次**（T12） |
| S.04-R7 | 风险等级由工具注册时声明：内置工具按 §3 表；扩展和 MCP 工具声明的风险等级不能低于 §3 的下限 |

## 2. 审批
| 编号 | 规则 |
|---|---|
| S.04-R8 | 审批卡片必须写清：谁（哪个节点、哪个模型）、要做什么、风险等级、关键参数（例如收件人、URL、要写的文件路径）、是否受污染及来源 |
| S.04-R9 | "以后都允许"只对 L0–L2 提供；生成的规则只放宽**这一个工具**、**这一层**（挂载在当前容器节点上），不放宽整个档位 |
| S.04-R10 | 同一运行里同类审批（同一工具、同一节点）合并为一张卡片，显示"共 5 次"，可以一次处理 |
| S.04-R11 | L3 工具：任何档位下都需要人工（3 档及以下审批，4 档要求图上游有人工节点，除非用户设了 `l3_skip_human`） |
| S.04-R12 | 审批默认 24 小时超时；超时视为驳回（人工节点按 `on_timeout` 处理） |
| S.04-R13 | 审批结果先落事件再执行（INV-11） |

## 3. 内置工具风险等级
| 工具 | 风险等级 | 说明 |
|---|---|---|
| 检索（本地文档、搜索 API 的 GET） | L0 | 只读 |
| 文件读 | L0 | 限工作区和用户授权的目录 |
| 文件写 | L1 | 限运行工作区；写用户目录为 L2 |
| 代码执行 | L1 | wazero 沙箱，无网络；声明了出站白名单时为 L2 |
| HTTP GET | L0（白名单内）/ L2（白名单外需审批加入） | — |
| HTTP POST / PUT / PATCH / DELETE | L2 | 对外、可能可撤销 |
| 浏览器（读页面） | L0 | — |
| 邮件发送、支付、删除外部数据 | L3 | 对外、不可撤销 |
| MCP 工具 | 服务器声明，缺省 L2；用户可以在设置里逐个工具调高（不能调低到声明以下） | — |
