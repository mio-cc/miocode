## 1. 记录什么
| 记录 | 内容 |
|---|---|
| 所有授权判定 | 需审核、拒绝、修改性的允许（只读的允许默认不记，可配置为全记） |
| 所有审批结果 | 批准、驳回、超时、取消 |
| 授权书和挂载的变化 | — |
| 急停的触发和解除 | — |
| 密钥的增删（不含值） | — |
| 扩展包、MCP 服务的启用和停用 | — |

每条记录：时间、主体（含上级编排者链）、动作、目标、结果、授权书、理由、关联的 Op / 审批 / 图版本、是否受污染。

## 2. 防篡改
| 编号 | 规则 |
|---|---|
| S.10-R1 | 审计表只追加，不提供修改和删除接口 |
| S.10-R2 | 哈希链：每条 `hash = sha256(prev_hash ‖ 规范化(本条))`，第一条的 `prev_hash` 为安装时生成的随机值 |
| S.10-R3 | `anydoorctl audit verify` 校验整条链，报告第一处断裂的位置 |
| S.10-R4 | 审计不能被关闭；模型无权修改审计相关设置（`S.04-R4`） |
| S.10-R5 | 数据保留期设置（`P.09` Q8）不作用于审计表；审计表只能随"彻底删除所有数据"一起清除 |

## 3. 查看
设置 → 审计：按主体、动作、时间、结果筛选；每条可以跳转到对应的 Op、审批、图版本。

## 4. 局限（如实说明）
本机单用户产品里，拥有电脑权限的人可以直接改数据库并重算整条哈希链。哈希链能发现"程序之外的局部篡改"和程序缺陷，不能防御拥有完全权限的本机攻击者。界面上不宣称"不可篡改"，只说"可以校验完整性"。
