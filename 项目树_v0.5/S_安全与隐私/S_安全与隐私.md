## 1. 这一枝管什么
Harness 会调用模型、执行工具和代码、加载别人写的扩展、在本机开一个网络服务。这一枝集中规定怎么防止出事：威胁模型、本机服务安全、密钥、授权与审批、提示词注入、沙箱、网络出站、扩展信任、急停、审计、本地数据与隐私、供应链、安全测试。

## 4. 整枝共同约束
- **S-R1** 默认安全：所有新功能的默认值都取最安全的一侧（模型 1 档、外部 0 档、污染防护开、沙箱无网络、遥测关）。用户可以放宽，但必须是用户本人、显式操作。
- **S-R2** 两层拦截：关键限制（急停解除、密钥读取、本机鉴权）在内核和 API 两层都检查，任何一层出错都不会导致越权。
- **S-R3** 每条安全规则都要有对应的测试（`S.13`），测试放进 CI。
- **S-R4** 安全相关的改动在 PR 里标记 `security` 标签，必须由设计方评审。

## 6. 相对旧文档的改动
| 改动 | 原因 |
|---|---|
| 代码执行沙箱默认改为 wazero（WASM），容器作为可选 | 单二进制形态，不要求用户安装 Docker（`P.09` K25） |
| 密钥默认存系统密钥库，不再优先用环境变量 | 环境变量会被子进程继承、容易泄露；只在开发模式允许（`G.11-R3`，`P.09` K26） |
| 外部触发（Webhook）相关威胁暂不适用 | v1 不做触发器（`P.02`），保留条目以备后续 |
