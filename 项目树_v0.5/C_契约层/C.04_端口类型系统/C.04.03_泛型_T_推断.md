## 1. 职责
定义类型变量（`$T`、`$U`）从哪里取值、怎么沿连线推断、推断不出来时怎么报错。

## 2. 来源写法（`NodeDef.type_vars`）
| 写法 | 含义 | 例子 |
|---|---|---|
| `param:<参数名>` | 取某个参数的值作为类型（参数类型必须是 `type_ref`） | Agent：`T: param:output_schema` |
| `input:<端口名>` | 取连到这个输入端口的上游类型 | 分支：`T: input:value` |
| `input:<端口名>.elem` | 上游是 `列表[X]` 时取 `X` | 扇出：`T: input:items.elem` |
| `body:<端口角色>` | 取容器子图里某个端口节点推断出的类型 | 扇出：`U: body:exit` |
| `op:<算子>(<变量>)` | 查算子类型表 | 聚合：`U: op:<op 参数>(T)` |

聚合算子类型表（`schema/builtin/aggregate_ops.yaml`）：
| 算子 | 输出类型 |
|---|---|
| `count` | `整数@1` |
| `group`、`group_ratio` | `聚合结果@1` |
| `vote` | `$T` |
| `dedupe`、`sort`、`filter`、`top_k` | `列表[$T]` |
| `concat` | `列表[$T]` |
| `stats` | `统计@1` |
| `divergence` | `分歧报告@1` |

## 3. 推断算法（规范，实现在 `E.03.02`）
1. 填入所有写死了具体类型的端口。
2. 绑定所有 `param:*` 变量。
3. 按拓扑顺序传播 `input:*`；容器节点当成黑盒，先单独推断它的子图。
4. 子图推断完后，把 entry / exit 端口节点的类型提升为容器节点外部端口的类型，然后绑定 `body:*`。
5. 重复 3–4，直到没有变化；最多重复"节点数"轮。
6. 仍有未确定的变量：诊断 V16，"无法推断 {变量}，请设置 {建议的参数}"；该端口按 `任意` 显示，连线检查按 `任意` 处理。

## 4. 冲突
- **C.04.03-R1** 同一个变量从两个来源得到不同类型（例如分支的 `yes` 已经连到只接 `方案@1` 的端口，上游又改成了 `判定@1`）：不报推断错误，而是按新类型重新检查所有连线，不兼容的连线报 V06。
- **C.04.03-R2** 推断结果不写进图文档，每次校验重新计算；前端缓存推断结果，按子图哈希失效。

## 5. 验收标准
1. 闭环迭代模板全图推断后没有 V16。
2. 删除 Agent 的 `output_schema` 后，下游端口报 V16 并给出建议。
3. 500 个节点的图全量推断 < 10ms（`Q.08` 基准）。
