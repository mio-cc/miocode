## 1. 职责
定义各种版本号的含义，以及旧数据怎么自动升级。

## 2. 版本号一览
| 版本 | 写在哪 | 格式 | 什么时候变 |
|---|---|---|---|
| schema 文件版本 | 各 schema 的 `x-version` | 主.次 | 按 `C.01` §5 |
| 图文档格式版本 | `Graph.schema_version` | 主.次 | 图文档结构变化时；等于 `graph.schema.json` 的 `x-version` |
| 图版本 | `Graph.version` | 整数 | 每应用一个 Op |
| NodeDef 版本 | `NodeDef.version` | 主.次 | 节点类型变化时 |
| 类型版本 | `方案@1.2` | 主.次 | 字段变化时：次版本只能加可选字段 |
| 扩展包、子图库、模板版本 | 清单里的 `version` | 主.次.修订 | 语义化版本 |
| 注册表哈希 | `run.created.registry_hash` | `sha256:` | 已安装的 NodeDef / 类型集合变化时 |

## 3. 自动升级
### 3.1 图文档
- **C.12-R1** 读取图文档时，`schema_version` 低于当前版本就按链式迁移函数逐级升级：`1.0 → 1.1 → 2.0`。
- **C.12-R2** 升级结果作为一个 `migrate` Op 写入（actor 为 `runtime/migrate`），版本号 +1；历史版本不改写。
- **C.12-R3** `schema_version` 高于当前程序支持的版本：拒绝读取，提示"这张图由更新版本的 Anywhere Door 创建，请升级"（`C.01-R20`）。
- **C.12-R4** 迁移函数注册在 `engine/schema/migrate/`，每个函数有"旧文档 → 新文档"的黄金文件测试。

### 3.2 类型主版本
- **C.12-R5** 类型升主版本（`方案@1` → `方案@2`）时，扩展包要提供迁移函数（纯函数，表达式或 Go）。连线上旧类型接新类型端口时，校验通过并标记 `migrate`（`C.04.02` C4），运行时自动转换，同时给 V06 级别 warn 提示用户。

### 3.3 运行快照
- **C.12-R6** 运行快照记录当时的注册表哈希。回放时注册表哈希不同：给警告"节点定义已变化，回放结果可能不同"，但仍然回放（回放使用记录下来的输出，不重新执行，INV-13）。
- **C.12-R7** 续跑（不是回放）时注册表哈希不同：拒绝续跑，提示用户从检查点 fork 一次新运行（新运行使用新的注册表）。

### 3.4 数据库
- 表结构迁移使用 goose，规则在 `E.07.03`，不在本文范围。

## 4. 导出与导入
- **C.12-R8** 导出的文件带 `schema_version` 和依赖清单（扩展包 `名@版本`、子图库引用 `名@版本`）。
- **C.12-R9** 导入时先迁移到当前版本，再检查依赖是否都已安装；缺失时列出清单，不导入半成品。

## 5. 验收标准
1. 准备一份 `schema_version: "0.9"` 的旧文档（v0.4 原型导出格式），能自动升级到 `1.0` 并通过校验。
2. `schema_version: "9.0"` 的文档被拒绝，提示文案正确。
3. 续跑时注册表哈希不同被拒绝。

### 实施卡
- 要建的文件：`schema/examples/migrate/0.9_to_1.0/{in,out}.json`。
- 测试用例：`C12-T1`…`T3`（迁移代码在 `E.03.01` 一起实现）。
