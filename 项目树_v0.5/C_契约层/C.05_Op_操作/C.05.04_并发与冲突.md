## 1. 职责
定义多方同时修改同一张图时的规则：版本检查、自动 rebase、冲突判定、草稿分支合并、连续拖动合并。

v1 是单用户产品，但"人"和"模型"会同时改图，所以这些规则是必需的。

## 2. 版本与自动 rebase
1. 每个分支的 `version` 单调递增；客户端提交时带 `base_version`。
2. `base_version` 等于最新版本：直接进入授权和应用。
3. 落后时：取出中间被错过的 Op，判断能否交换（§2.1）。
   - 能交换：把本次 Op rebase 到最新版本上应用，响应 `rebased: true`。
   - 不能交换：返回 409 `graph_conflict`，带 `head`、`missed_ops`、`conflicts`。

### 2.1 可交换判定
两条 Op 可以交换 ⇔ 它们的**写集合**不相交，并且没有"一个删除、另一个引用"的关系。

写集合：
| Op | 写集合 |
|---|---|
| `add_node` | 新节点 ID |
| `remove_nodes` | 被删节点 ID、相连连线 ID |
| `connect` | 新连线 ID；目标端口 `(node, port)`（非多连时） |
| `disconnect` | 连线 ID |
| `set_param` | `(node, key)` |
| `promote_param` / `demote_param` | `(node, key)`、对应端口 |
| `set_label` / `set_tags` / `set_lock` | `(node, 字段)` |
| `move_nodes` / `set_node_ui` | `(node, 视图)` |
| `group` / `ungroup` | 涉及的所有节点、连线、容器节点 |
| 便签类 | 便签 ID |

允许的特殊情况（视为可交换）：
- 两条 `move_nodes` / `set_node_ui` 作用于同一节点：后写者胜（`C.02.05-R3`）。
- 两条 `remove_nodes` 删同一个节点：幂等。

## 3. 草稿分支与三方合并
- 模型在档位 1–3 的修改默认写进草稿分支 `draft/model-<会话或运行 ID>`；档位 4 可以直接写 `main`，由授权书的 `scope.branch` 控制（`C.09`）。
- 合并算法（实现在 `E.05.03`）：
  1. `base` = 草稿分支创建时 main 的版本；`ours` = main 最新版本；`theirs` = 草稿最新版本。
  2. 结构化比较：`Δo = Diff(base, ours)`，`Δt = Diff(base, theirs)`。比较单元：节点增删、节点移动、`(节点, 参数)` 改动、连线增删、`(节点, 显示名)` 改动、便签改动。
  3. 对 `Δt` 的每个单元：`Δo` 没有动同一对象 → 自动采纳；两边结果相同 → 采纳；都是移动 → 取 ours（用户的布局优先）；否则 → 冲突。
  4. 自动采纳的部分预先校验；冲突和校验错误一起返回，用户逐条选择 ours / theirs / 手工值。
  5. 用户确认后提交 `merge_branch`，作为一条复合 Op 原子应用。
- 坐标冲突永远不阻塞合并。

## 4. 连续拖动合并（coalesce）
- 拖动、数字步进拖动、滑块拖动时，前端在按下鼠标时生成 `coalesce_key`（`drag:` / `step:` / `slide:` + ULID），拖动过程中**最多每 250ms 提交一次**，松手时提交最后一次。
- 服务器：新 Op 的 `coalesce_key` 与**同一操作者**的上一条 Op 相同，且间隔 < 2s → 原地合并：更新上一条的 `to`，保留最初的旧值，**不增加版本号**，只广播 `op.coalesced`。
- 效果：一次拖动在历史里只有一条，撤销一步回到原位。

## 5. 人和模型同时编辑
| 场景 | 规则 |
|---|---|
| 模型在草稿分支，人在 main | 互不影响；草稿顶部显示"落后 main N 个版本"，可以一键 rebase |
| 模型档位 4 直接写 main，人也在改 | 照常版本检查；**模型的 Op 冲突时自动转进草稿分支**并通知用户；人的 Op 优先，人看到冲突时弹"已被修改为 X，是否覆盖" |
| 人正在编辑某个节点 | 前端广播 `presence`；模型的图操作工具 `read_graph` 返回"正在编辑"的节点，角色卡要求模型回避（`E.17.02`） |
| 运行中改图 | 修改进入新版本；正在运行的运行在安全点决定是否采纳（`E.16.02`，INV-12） |
| 急停中 | 拒绝所有 `actor.kind=model` 的 Op，返回 423 `estopped` |

## 6. 验收标准
1. 100 个并发请求同时提交，最终版本号连续，没有丢失的 Op。
2. 两条 `set_param` 改同一参数、base 相同：第二条返回 409，`conflicts` 指明 `(node, key)`。
3. 模拟拖动 60 次 `move_nodes`：历史里 1 条，撤销后回到原位。
4. 三方合并覆盖 §3 第 3 步的每种情况。
