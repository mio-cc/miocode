## 4. 整枝共同约束
- **O-R1** 所有构建、检查步骤都是 `go run ./tools/<名>` 或 `pnpm -C web <脚本>`，在 Windows、macOS、Linux 上同样能运行；仓库根的 `Makefile` 和 `Taskfile.yaml` 只是同名目标的薄包装（`G.15`）；不写只能在 bash 下运行的脚本。
- **O-R2** 工具版本固定（`S.12-R6`）：Go 用 `go.mod` 的 `toolchain` 行；Node 与 pnpm 用 `web/package.json` 的 `engines`、`packageManager`；检查工具（`golangci-lint`、`gitleaks`、`govulncheck`）写在 `tools/versions.txt`，从这里读。
- **O-R3** `CGO_ENABLED=0`（ADR-004）；同一提交在同一工具版本下两次构建，二进制哈希相同（`S.12-R6`）。为此版本信息里的"构建时间"取**提交时间**，不取当前时间（`P.09` K186）。
- **O-R4** 构建和 CI 不调用任何模型 API；CI 不配置任何模型密钥（`Q.06`、`G.02.05-R35`）。
- **O-R5** 程序只嵌入生产构建 `web/dist/`；性能构建 `web/dist-perf/`（`W.11`）、组件陈列页（`W.12`）、测试工具不进程序。
- **O-R6** `O.04` 完成之前，产物都是**预览版**：文件名带 `preview`，只在代码仓库的 GitHub Releases 里以"预发布"出现，不对外分发；`S.12-R4`（SBOM）、`R5`（签名、公证）从 `O.04` 起对公开发布生效（`P.09` K190）。
- **O-R7** 代码仓库与设计文档仓库分开（`G.02.06-R1`）：设计文档在 `sj/`（推送到 `mio-cc/miocode`）；代码在 `mio-cc/Anywhere-Door`（公开），本地 `C:\Users\Administrator\Desktop\harness`，推送用 SSH 别名 `anywheredoor-github`。用户决定先不处理许可证，仓库保持公开、照常推送（`P.09` Q27 已定）。
