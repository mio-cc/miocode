# 17 性能

> 技术栈：Next.js + React（画布外壳）+ 命令式渲染层 + zustand。本文第 9 节给出 React 写法和“哪些不能交给 React 渲染”。
>
> 硬目标：**200 个节点、300 条连线时，拖动、平移、缩放、连线保持 60fps**（每帧 ≤ 16.7ms，主线程脚本 ≤ 8ms）；1000 节点时仍可用（≥ 30fps）。任何操作 100ms 内有视觉反馈。

---

## 1. 帧预算拆解（16.7ms）

| 阶段 | 预算 | 说明 |
|---|---|---|
| 输入处理 | ≤ 1ms | pointer 事件只记坐标，不做计算 |
| rAF 回调：状态计算 | ≤ 3ms | 命中检测、吸附、端口坐标 |
| rAF 回调：DOM 写入 | ≤ 3ms | 只写 transform 和少量 path d |
| 样式重算 + 布局 | ≤ 2ms | 不触发布局最好 |
| 绘制 + 合成 | ≤ 5ms | 由 GPU 承担 |
| 余量 | ≥ 2.7ms | 给 GC 和浏览器 |

**原则：读写分离，每帧先全部读，再全部写；动画帧内不读布局。**

## 2. 规则 R1–R10 详解

### R1 平移缩放只改一个世界容器的 transform
**原理**：`transform` 只触发合成，不触发布局和绘制。所有节点和连线放在同一个 `.hx-world` 容器里，视图变化时只改这一个元素。

✅ 正确
```js
const world = document.querySelector('.hx-world');
world.style.willChange = 'transform';
function renderView(v) {
  world.style.transform = `translate3d(${v.x}px,${v.y}px,0) scale(${v.k})`;
  canvas.style.backgroundPosition = `${v.x}px ${v.y}px`;
  const g = (v.k < .5 ? 40 : 20) * v.k;
  canvas.style.backgroundSize = `${g}px ${g}px`;
}
```
❌ 错误
```js
nodes.forEach(n => { el(n).style.left = (n.x*k + x) + 'px'; }); // 每个节点都改 left，触发布局
```
**检测**：Performance 录制平移，主线程不应出现紫色 Layout 块。

### R2 端口坐标用布局常数计算
**原理**：节点结构固定（头部 38、端口行 24），端口位置可以直接算出来，不需要问 DOM。

✅
```ts
const HEAD = 38, ROW = 24, W = 236;
function portPos(n: Node, side: 'in'|'out', index: number) {
  return { x: n.x + (side === 'out' ? n.w ?? W : 0),
           y: n.y + HEAD + index * ROW + ROW / 2 };
}
```
❌
```js
const r = dot.getBoundingClientRect(); // 在拖动帧里调用 → 强制同步布局
```
**检测**：Performance 中出现 “Forced reflow” 警告即违规。节点高度变化（端口增减、控件展开）时，由 `renderNode` 更新 `n.h` 缓存，而不是在使用时测量。

### R3 pointermove 在 rAF 里合并
**原理**：高回报率鼠标每秒可达 1000 次事件，远超 60 帧。

✅
```ts
let pending: PointerEvent | null = null, scheduled = false;
el.addEventListener('pointermove', e => {
  pending = e;
  if (!scheduled) { scheduled = true; requestAnimationFrame(flush); }
}, { passive: true });
function flush() { scheduled = false; if (pending) handleMove(pending); pending = null; }
```
需要平滑轨迹（如手绘）时用 `e.getCoalescedEvents()`，画布场景不需要。
**检测**：在 handleMove 计数，每秒不应超过刷新率。

### R4 拖动时只更新被拖节点和相关连线
**原理**：拖动的工作量应与“被拖动的东西”成正比，与整张图大小无关。

✅
```ts
// 拖动开始时预先算好受影响的连线
const affected = edgesOf(selection);           // Set<EdgeId>
function onDragFrame(dx, dy) {
  for (const id of selection) {
    const n = graph.nodes.get(id)!; n.x += dx; n.y += dy;
    nodeEl(id).style.transform = `translate3d(${n.x}px,${n.y}px,0)`;
  }
  for (const id of affected) edgePath(id).setAttribute('d', computePath(id));
}
```
❌ 拖动时调用 `render()` 重建全部节点或 `svg.innerHTML = …` 重画全部连线。
**检测**：200 节点下拖动一个节点，单帧脚本时间应 < 1ms。

节点位置一律用 `transform: translate3d`，不用 `left/top`。

### R5 节点 DOM 按 id 复用
**原理**：重建 DOM 会丢失焦点、事件绑定、过渡状态，还会产生 GC 压力。

✅
```ts
const pool = new Map<NodeId, HTMLElement>();
function renderNode(id) {
  let el = pool.get(id);
  if (!el) { el = createNodeEl(id); pool.set(id, el); world.append(el); }
  patchNode(el, graph.nodes.get(id)!, run.nodeStatus.get(id)); // 只改 class 和文字
}
function patchStatus(el, s) {
  if (el.dataset.s === s) return;          // 未变化不写
  el.classList.remove('is-' + el.dataset.s); el.classList.add('is-' + s); el.dataset.s = s;
}
```
❌ `el.innerHTML = template(node)` 每次状态变化都重写。

### R6 setPointerCapture
✅
```ts
handle.addEventListener('pointerdown', e => {
  handle.setPointerCapture(e.pointerId);
  // 之后的 move/up 都发给 handle，即使指针离开画布
});
```
同时监听 `lostpointercapture` 作为拖动结束的兜底，防止“卡在拖动状态”。

### R7 节点数 > 150 时视口裁剪
```ts
function cull(view, viewport) {
  const r = worldRect(view, viewport).inflate(200); // 留 200px 缓冲
  for (const n of graph.nodes.values()) {
    const vis = intersects(n, r);
    if (vis !== n._vis) { nodeEl(n.id).style.contentVisibility = vis ? 'visible' : 'hidden'; n._vis = vis; }
  }
}
```
- 只在视图停止变化 80ms 后或每 4 帧执行一次。
- 连线：两端都不可见且包围盒不与视口相交时，`display:none`。
- 节点空间索引：> 500 节点时使用均匀网格（cell 512px）加速查询。

### R8 连线放在一个 SVG，流动动画只给活跃线
- 一个 `<svg class="hx-edges">`，内含 `<g>` 分层：普通线、选中线、运行流动层、预览线。
- 流动动画是一条叠加 path，`stroke-dasharray:1 11; animation: hx-flow .6s linear infinite`。只有状态为“数据正在流过”的连线才有这条叠加层，同时最多 40 条，超过时按最近活跃排序截断。
- 不对连线使用 `filter`（阴影、模糊），代价很高。选中光晕用一条加粗半透明 path 实现。

### R9 缩放时暂停高成本效果
```ts
let zoomTimer;
function onWheel() {
  root.classList.add('is-zooming');            // CSS 里：.is-zooming * { transition: none !important }
  clearTimeout(zoomTimer);
  zoomTimer = setTimeout(() => root.classList.remove('is-zooming'), 120);
}
```
缩放期间 LOD 不切换，停止后再切换，避免缩放过程中反复重排。

## 3. 渲染分层

| 层 | 内容 | 什么时候更新 | 更新方式 |
|---|---|---|---|
| L1 视图 | 世界容器 transform、网格、小地图视口框 | 平移、缩放（每帧） | 只写 3 个 style |
| L2 节点结构 | 节点 DOM 的创建、删除 | Op 增删节点 | `renderNode(id)` / 移除 |
| L3 节点内容 | 标题、参数值、端口列表 | Op 改参数、转端口 | `patchNode` 局部写 |
| L4 节点状态 | 状态 class、进度、状态文字 | 运行事件 | `patchStatus`，节流见第 6 节 |
| L5 连线几何 | path d | 节点移动、连线增删 | 只重算受影响的连线 |
| L6 连线状态 | 流动、完成色 | 运行事件 | 切 class |
| L7 叠加层 | 选框、预览线、吸附光环、AI 光标 | 交互中每帧 | 独立元素，transform |
| L8 面板 | 检查器、抽屉、节点库 | 选中变化、数据变化 | 组件内部 diff |
| L9 小地图内容 | canvas 上的节点方块 | 图结构变化（节流 200ms） | 整体重画 canvas |

每层只订阅自己关心的状态片段（见 18_前端架构 的订阅机制）。

## 4. 事件处理

| 规则 | 做法 |
|---|---|
| 被动监听 | `pointermove` `touchmove` 用 `{passive:true}`；`wheel` 需要 `preventDefault` 阻止页面滚动，所以**不能**是 passive，但处理函数里只记录 delta，计算放进 rAF |
| 事件委托 | 画布上只挂一组 pointer 监听，通过 `e.target.closest('[data-hx]')` 分派，不给每个节点、端口单独绑定 |
| 防抖 | 搜索输入 120ms；检查器文本参数 300ms 后再生成 Op（失焦立即） |
| Op 合并 | 连续拖动、连续拖动调值，在 pointerup 时合成一条 Op，过程中只更新视觉 |
| 键盘 | `keydown` 在 document 上统一处理，输入框聚焦时跳过画布快捷键 |

## 5. 大图策略

| 节点数 | 策略 |
|---|---|
| ≤ 150 | 全部 DOM 渲染 |
| 150 – 1000 | DOM + 视口裁剪（R7）+ 空间网格索引 |
| > 1000 | **混合渲染**：缩放 < 0.6 时整张图用一个 `<canvas>` 绘制（方块 + 连线，忽略文字细节），DOM 节点全部隐藏；缩放 ≥ 0.6 时只为视口内节点创建 DOM（最多约 150 个），其余用 canvas 画 |
| > 5000 | 提示“建议封装为子图”；画布外部只显示子图层级 |

canvas 绘制：连线用 `Path2D` 按颜色分组批量 `stroke()`，每种类型色一次绘制调用；节点用 `fillRect` + 圆角近似；设备像素比按 `Math.min(devicePixelRatio, 2)`。

## 6. 运行时高频更新的节流

运行时引擎可能每秒推送上百条状态事件。

```ts
const dirtyNodes = new Set<NodeId>();
let flushScheduled = false;
engine.on('node.status', ev => {
  run.nodeStatus.set(ev.id, ev.status);   // 立即更新数据
  dirtyNodes.add(ev.id);                   // 标脏
  if (!flushScheduled) { flushScheduled = true; requestAnimationFrame(flushRun); }
});
function flushRun() {
  flushScheduled = false;
  for (const id of dirtyNodes) patchStatus(nodeEl(id), run.nodeStatus.get(id));
  dirtyNodes.clear();
}
```

| 数据 | 频率上限 |
|---|---|
| 节点状态、进度 | 每帧合并一次 |
| 时间线条段 | 每 250ms |
| 日志 | 每 100ms 批量追加，列表虚拟滚动，保留最近 5000 条在内存，其余按需加载 |
| 顶部条统计（用时、tokens） | 每 500ms |
| 小地图 | 200ms |
| 读屏播报 | 见 16_可访问性，最多每 2 秒 |

页面不可见（`document.hidden`）时：停止所有 rAF 动画，只累积数据；回到前台时一次性刷新。

## 8. 用 Performance 面板验收

1. Chrome DevTools → Performance，勾选 Screenshots，CPU 不降频（另做一次 4× 降频测试作为参考）。
2. 打开命令面板 → 「压力测试」生成 200 节点 300 连线。
3. 录制 5 秒：平移 1 秒、滚轮缩放 1 秒、拖动节点 1 秒、拖线 1 秒、框选 1 秒。
4. 检查：
   - Frames 轨道无红色掉帧段；
   - Main 轨道无 > 50ms 的长任务（红角标）；
   - 无 “Forced reflow” 警告；
   - Layout 事件只在增删节点时出现，平移和拖动时不出现。
5. Rendering 面板打开 “Paint flashing”：平移时只有网格区域闪，节点不闪。
6. Memory 面板：反复创建删除 200 节点 10 次，堆快照不应持续增长（DOM 池正常回收）。
7. 把结果写进 19_交付验收清单 的性能一节。

## 9. 在 React / Next.js 中落实

### 9.1 不能交给 React 渲染的部分

| 内容 | 原因 | 由谁负责 |
|---|---|---|
| 世界容器 transform（平移、缩放） | 每帧变化 | `CanvasEngine.renderView` |
| 节点 DOM（创建、复用、位置、状态 class、进度） | 数量多、高频 | 渲染层 DOM 池 |
| 连线 SVG path | 拖动时每帧 | 渲染层 |
| 叠加层（框选、拖线预览、吸附环、AI 光标） | 每帧 | 渲染层 |
| 小地图 | canvas 绘制 | 渲染层 |
| 运行状态的高频刷新 | 每秒上百次 | 渲染层 rAF 合并 |

React 只渲染：外壳、面板、检查器表单、对话卡片、通知。**任何每秒变化超过 4 次的数据都不能进 React state。**

### 9.2 正确写法

```tsx
'use client';
// ✅ 画布外壳：渲染一次，之后由引擎接管
export function Canvas() {
  const host = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const engine = new CanvasEngine(host.current!);
    // 非 React 订阅：不会引发任何组件重渲染
    const off1 = useViewStore.subscribe(s => s.view, v => engine.scheduleView(v));
    const off2 = useGraphStore.subscribe(s => s.lastChange, c => engine.markDirty(c));
    const off3 = useRunStore.subscribe(s => s.lastEventSeq, () => engine.markRunDirty());
    return () => { off1(); off2(); off3(); engine.destroy(); };
  }, []);
  return <div ref={host} className="hx-canvas" />;
}
```

```ts
// ✅ 拖动：指针事件在引擎里处理，直接写 DOM；松开时才 dispatch 一条 Op
onPointerMove(e) { this.pending = e; this.raf ||= requestAnimationFrame(this.flush); }
flush = () => {
  this.raf = 0; const e = this.pending!;
  const dx = (e.clientX - this.last.x) / this.view.k, dy = (e.clientY - this.last.y) / this.view.k;
  for (const id of this.dragIds) { const n = this.pos.get(id)!; n.x += dx; n.y += dy;
    this.nodeEl(id).style.transform = `translate3d(${n.x}px,${n.y}px,0)`; }
  for (const id of this.affectedEdges) this.edgeEl(id).setAttribute('d', this.path(id));
  this.last = { x: e.clientX, y: e.clientY };
};
onPointerUp() { useGraphStore.getState().dispatch(moveOp(this.dragIds, this.origin, this.pos)); }
```

```tsx
// ✅ 面板：精确 selector，只在该节点标题变化时重渲染
const label = useGraphStore(s => s.doc.nodes[id]?.label);
// ✅ 顶部条显示缩放百分比：节流订阅
const zoom = useThrottledStore(useViewStore, s => Math.round(s.view.k * 100), 200);
```

### 9.3 错误写法

```tsx
// ❌ 用 React state 存视图，每次滚轮都重渲染整个画布树
const [view, setView] = useState({ x: 0, y: 0, k: 1 });
<div style={{ transform: `translate(${view.x}px,${view.y}px) scale(${view.k})` }}>
  {nodes.map(n => <NodeView key={n.id} node={n} />)}
</div>

// ❌ 面板订阅整个 doc：任何节点移动都会重渲染检查器
const doc = useGraphStore(s => s.doc);

// ❌ 拖动中每帧 dispatch：历史被刷爆，所有订阅者每帧触发
onPointerMove = e => dispatch(moveOp(...));

// ❌ 在 render 里读 DOM 尺寸
const rect = ref.current?.getBoundingClientRect();
```

### 9.4 Next.js 相关注意事项

- `Canvas` 用 `dynamic(() => import('@/canvas/Canvas'), { ssr: false })` 引入；`canvas/core` 不能在服务端被 import。
- 开发模式下 React StrictMode 会把 effect 执行两次：`CanvasEngine` 的构造和 `destroy` 必须可重入（destroy 后彻底清理监听和 DOM 池）。
- 不要把节点、运行状态放进 React Context，Context 变化会导致全部消费者重渲染。
- 检查器表单的输入用本地 state 做中间值，失焦或回车才 `dispatch`。
- 用 React Profiler 验收：平移、拖动 5 秒期间，**React 提交次数应为 0**（除缩放百分比的节流更新外）。
