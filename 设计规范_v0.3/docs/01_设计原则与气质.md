# 01 · 设计原则与气质

## 1. 产品气质

| 关键词 | 含义 | 在界面上意味着 |
|---|---|---|
| **精密仪器** | 每个数值、每条线都有理由 | 对齐到 4px；数字等宽；状态精确到秒和 token |
| **白天工作台** | 默认浅色，长时间使用不累 | 白色面板浮在浅灰底上；文字对比度够但不刺眼；颜色只在需要时出现 |
| **安静而高效** | 界面退后，内容和状态说话 | 铬件低对比；没有装饰动画；常用操作一步到位、有快捷键 |
| **可信的协作者** | 模型的每一步都看得见、可撤销 | 模型操作有专属身份色、理由和撤销入口 |

一句自检：**截一张图给陌生人看，他应该先看到"图和它的状态"，而不是"这个界面的装饰"。**

## 2. 七条原则

### P1 内容是主角，界面退后
- **解释**：画布、节点、运行状态是内容；工具栏、边框、面板是铬件。铬件用最低能用的对比度。
- **正例**：浮动面板距边缘 12px 浮在画布上，画布满铺；工具栏图标用 `--hx-text-2`，不加底色。
- **反例**：顶部一条深色大工具栏 + 左右两条固定侧栏，把画布切成中间一小块。
- **怎么判断**：展开态下画布可见面积 ≥ 中间栏面积的 70%（面板展开时）；按 Tab 后 ≥ 95%。

### P2 颜色 = 含义
- **解释**：每种颜色只表达一种含义（见 02 号文档）。中性灰承担一切非语义的视觉。
- **正例**：运行中的节点外框是 `--hx-accent-line`；完成后回到 `--hx-line-2`，只留状态点 `--hx-ok`。
- **反例**：按节点类别给头部涂不同颜色；用蓝色做"普通按钮"、紫色做"卡片装饰"。
- **怎么判断**：随便指一个彩色像素，能说出它表示什么含义；说不出就删掉。

### P3 状态一眼可读
- **解释**：状态必须同时由**颜色 + 图形 + 文字**三种方式表达。
- **正例**：失败节点：红色外框 + 叉形状态点 + 状态脚"失败 · 超时"。
- **反例**：只把外框变红。
- **怎么判断**：把界面转成灰度（DevTools 渲染模拟 achromatopsia），仍能分辨所有状态。

### P4 模型的行为永远可见
- **解释**：模型做的任何修改都有 `--hx-model` 标记、理由、时间、所用授权、撤销入口。
- **正例**：模型把并发 3 改成 5，节点上出现 AI 签，参数显示 `3 → 5`，悬停看理由，通知里有"撤销"。
- **反例**：模型悄悄改了参数，界面上和人改的一模一样。
- **怎么判断**：在操作历史里随便点一条，能立即区分是人还是模型做的，并能看到理由。

### P5 直接操作优先
- **解释**：能在节点上直接改的不进检查器；能拖的不用点；高频操作都有快捷键。
- **正例**：节点内联的数字步进可以直接左右拖动调值；拖线到空白处直接弹出可接的节点。
- **反例**：改一个并发数要先选中、再打开检查器、再找到参数。
- **怎么判断**：最常见的 10 个操作（加节点、连线、改参数、删、撤销、运行、封装、进子图、适应视图、搜索）每个 ≤ 2 步。

### P6 流畅是功能
- **解释**：拖拽、缩放、连线在 200 节点时保持 60fps；任何操作 100ms 内有视觉反馈。
- **正例**：拖动节点时只改它的 transform 和相关连线（见 17 号文档）。
- **反例**：每次 pointermove 重建整个画布 innerHTML。
- **怎么判断**：Performance 面板录制拖动 5 秒，没有超过 16.7ms 的长帧。

### P7 渐进披露
- **解释**：信息按需出现。缩小时只显示标题；悬停才出类型；选中才出完整参数。
- **正例**：端口类型名平时不显示，悬停端口才浮出类型标签。
- **反例**：每个端口旁边常驻一个类型徽标，节点密密麻麻。
- **怎么判断**：在缩放 1.0 下，一个标准 Agent 节点上的文字 ≤ 8 段。

## 3. 禁止清单

| 禁止 | 原因 |
|---|---|
| 渐变色块、渐变文字 | 制造廉价的"AI 产品"感；与颜色=含义冲突 |
| 玻璃拟态（模糊背景 + 半透明） | 浅色下对比度不可控；性能开销大 |
| 彩虹配色、按类别涂色 | 稀释语义色，用户无法再靠颜色判断状态 |
| emoji 图标 | 风格不统一，无法控制线宽和颜色 |
| 每张卡片都有悬停放大/阴影 | 噪音；让"可交互"信号失去意义 |
| 每个区块都有入场动画 | 打断阅读；重复播放令人厌烦 |
| 全大写的小标签 | 中文环境无意义，英文下降低可读性 |
| 所有元素同一个圆角和阴影 | 抹平层级，看起来像模板 |
| 一条标题里单独染色/斜体某个词 | 装饰性强调，信息没有增加 |
| 重型网格线、粗边框 | 抢内容的视觉重量 |
| 自定义滚动条做得很花 | 降低可用性；与系统习惯冲突 |
| 在浅色主题下用纯黑 `#000` 阴影大面积铺开 | 显脏；用 02 号文档的阴影令牌 |

## 4. "高级感"从哪里来（可检查标准）

| 来源 | 标准 | 检查方法 |
|---|---|---|
| 间距精度 | 所有间距都是 `--hx-s-*` 中的值；同一组件内边距对称 | 抽查 DevTools 计算样式，不出现 5px、7px、13px 之类的间距 |
| 层级清晰 | 浅色下：浅灰底 `--hx-bg-0/1` 上浮白色面板 `--hx-bg-2/3`，靠 `--hx-line-2` + 阴影令牌区分；一屏内不超过 3 层 | 截图转灰度，仍能分辨面板、节点、画布三层 |
| 细线 | 外框 1px；分隔线用 `--hx-line-1`；不出现 2px 以上的边框（选中环除外） | 搜索 CSS 中 `border:` 宽度 |
| 内高光 / 细阴影 | 浮动元素统一用 `--hx-shadow-*`；浅色下阴影多层、低不透明度 | 不出现自定义 box-shadow |
| 数字等宽 | 所有数值（tokens、耗时、并发、轮次、坐标）`font-variant-numeric: tabular-nums` 或用 `--hx-font-mono` | 运行中数字跳动时文字不左右抖动 |
| 克制的动效 | 只有 05 号清单里的动效；时长只用 `--hx-t-*` | 搜索 CSS 中的 `ms` 字面量为 0 |
| 排版节制 | 同屏字号 ≤ 4 档；字重只用 400/500/600 | 抽查 |
| 对齐 | 节点端口圆心精确压在边框上；文字基线在同一行对齐 | 放大 400% 截图检查 |
| 一致的图标 | 全部 1.5px 线宽、20px 网格、圆角端点 | 见 06 号文档 |
| 空间感 | 面板内容区留白 ≥ `--hx-s-5`；不要把控件挤满 | 抽查 |

## 5. 设计决策的优先顺序

当规则之间冲突时，按以下顺序取舍：

1. **安全与可撤销**（急停、授权、模型行为可见）
2. **可读与可用**（对比度、状态表达、键盘可达）
3. **性能**（60fps、100ms 反馈）
4. **一致性**（遵守令牌与组件规范）
5. **美观**

美观排最后，不是因为不重要，而是因为前四条做对了，美观通常会自然出现。
