# Harness · 积木编排 UI/UX 设计规范 · 总索引

> 版本：v0.3.1　｜　默认主题：**浅色**　｜　适用范围：harness「积木编排」运行模式的全部界面

## 1. 这是什么

这是一套**可以直接照着实现**的界面规范，描述 harness 中"积木编排"模式的视觉、交互和前端工程约定：对话中的画布卡片、展开后的编辑画布、节点、连线、控件、面板、模型作为操作者时的界面表达、运行观测。

它不是一份灵感板，而是一份**合同**：凡是文档里写了的，实现必须一致；文档没写的，先补文档再实现。

## 2. 给谁看

| 读者 | 关心什么 |
|---|---|
| 前端实现者（人） | 尺寸、令牌、状态、交互细节、性能要求 |
| 接手的模型（代码 agent） | 明确、无歧义的规则；可复制的结构与命名；验收标准 |
| 设计评审 | 原则、气质、禁止清单、验收清单 |
| 后端 / 引擎接入者 | 状态模型、Op 协议、运行事件流在界面上的映射 |

## 3. 三个事实来源与优先级

| 来源 | 角色 | 冲突时 |
|---|---|---|
| `tokens.css` | 所有颜色、字号、间距、圆角、阴影、动效的**唯一取值来源** | 数值以它为准 |
| `docs/*.md`（本目录） | 规则与细节的**权威说明** | 规则以 docs 为准 |
| `DESIGN.md` | 一页式摘要，便于速读 | 与 docs 冲突时，改 DESIGN.md |
| `画布_旗舰demo.html` / `设计规范.html` | 参考实现 | 与 docs 冲突时，改 demo |

一句话：**数值看 tokens，规则看 docs，摘要看 DESIGN，样子看 demo。**

## 6. 文档写作约定

- 引用令牌一律写成 `--hx-xxx`，**不写裸色值**（只有 02 号文档的令牌表例外）。
- 尺寸写 px；比例写小数（0.45）；时长引用 `--hx-t-*`。
- "必须 / 禁止"是硬性要求；"建议"可以有理由地偏离，但要在 PR 里说明。
- 标注 **(P1)** 的内容属于第二阶段，首版可以不做，但结构上要留出位置。
- 示例代码用 HTML / CSS / TypeScript，class 用 BEM + `hx-` 前缀，例如 `.hx-node__head`、`.hx-node.is-running`。

## 7. 版本与变更规则

| 项 | 规则 |
|---|---|
| 版本号 | `主.次.修订`。主：破坏性改动（令牌改名、结构改动）；次：新增规则或组件；修订：措辞、修错 |
| 令牌改名 | 必须保留旧名作为别名至少一个次版本，并在变更记录注明 |
| 变更记录 | 写在本文件第 8 节，每条格式：`版本 · 日期 · 文件 · 改了什么 · 为什么` |
| 同步要求 | 改了 docs 的数值，必须同时改 `tokens.css`；改了规则，必须检查 DESIGN.md 与 demo 是否需要同步 |
| 谁能改 | 人和模型都可以提修改；模型提交的改动需要在说明里写理由，并经人确认 |
