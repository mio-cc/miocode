# 15 文案与术语

> 界面上的每个字都按本文写。所有文案集中放在 `T` 对象里（见第 7 节），不在组件里硬编码。

---

## 1. 语气原则

| 原则 | 做法 | 反例 → 正例 |
|---|---|---|
| 直接 | 先说结果，再说原因 | 「很抱歉，似乎出现了一些问题」→「运行失败：检索工具超时」 |
| 具体 | 写出对象名、数字、位置 | 「部分节点有错误」→「3 个节点缺少必填参数」 |
| 克制 | 不卖萌、不用感叹号、不用 emoji、不拟人撒娇 | 「哎呀，出错啦！」→「连接已断开」 |
| 可操作 | 能告诉用户下一步，就写出下一步 | 「授权不足」→「当前授权最高 L1，需要批准才能使用“发邮件”」 |
| 一致 | 同一个东西永远用同一个词（见术语表） | 「执行/运行/跑」混用 → 只用「运行」 |
| 短 | 按钮 2–4 字，标签不超过 8 字，提示一句话 | — |

标点：中文用全角标点；中英文、中文与数字之间加半角空格（`第 2 轮`、`Agent 节点`）；句末是按钮或标签时不加句号；正文完整句子加句号。

## 3. 按钮与动词规范

1. **动词 + 对象**，对象明显时可省：「运行」「采纳全部」「删除子图」。
2. **不用**：确定、好的、OK、提交（除非真的是提交表单）、执行。
3. 成对动作固定搭配：

| 场景 | 主 | 次 |
|---|---|---|
| 模型提议 | 采纳 | 拒绝 |
| 审批 | 批准 | 驳回 |
| 提权申请 | 仅本次批准 / 永久批准 | 拒绝 |
| 确认对话框 | 具体动词（删除子图） | 取消 |
| 合并 | 合并到主线 | 继续编辑 |
| 运行控制 | 运行 / 暂停 / 继续 | 停止 |

4. 加载中按钮文字改为进行时：「运行」→「运行中…」，并禁用。
5. 菜单项后面要打开对话框的加「…」：「重命名…」。
6. 快捷键用键帽显示，不写进文字。

## 4. 错误信息写法

公式：**发生了什么 + 为什么（如果知道）+ 怎么办**。主语是对象，不是“你”或“系统”。

| # | 修改前 | 修改后 |
|---|---|---|
| 1 | 操作失败 | 无法连接：「列表」不能接到「上下文包」 |
| 2 | 错误：invalid edge | 环只能通过循环节点形成。把要迭代的节点封装进循环 |
| 3 | 参数错误 | 并发必须在 1–32 之间 |
| 4 | YAML 格式错误 | 第 12 行：缩进不一致，应为 4 个空格 |
| 5 | 运行出错了！ | 「检索」超时（60 秒）。已自动重试 2 次 |
| 6 | 模型返回异常 | 「决策者」的输出缺少 tasks 字段。查看原始输出 |
| 7 | 权限不足 | 模型想使用「发邮件」（L2），当前授权最高 L1 |
| 8 | 网络异常，请稍后重试 | 连接已断开，正在重连。修改会保存在本地 |
| 9 | 冲突 | 你和模型同时改了「执行池」。你的修改已保留，模型的放到了草稿 |
| 10 | 无法删除 | 「入口」是子图必需的端口，不能删除 |

禁止：错误码直接给用户看（放进「详情」）；“请联系管理员”；把责任推给用户（「你输入的值无效」→「并发必须是整数」）。

## 5. 数字、时间、单位格式

| 类别 | 格式 | 示例 |
|---|---|---|
| 整数 | 千分位逗号，等宽数字 | 12,480 |
| tokens | <1000 原样；≥1000 用 k，一位小数；≥1M 用 M | 860 / 12.5k / 1.2M tokens |
| 预算 | 已用 / 上限 | 128k / 500k tokens |
| 费用 | ¥ 两位小数；<0.01 显示「<¥0.01」 | ¥3.20 |
| 百分比 | 整数，进度可显示到个位 | 62% |
| 时长（运行中） | `m:ss`，超过 1 小时 `h:mm:ss` | 4:05 / 1:02:30 |
| 时长（统计） | 中文单位 | 3 分 12 秒 |
| 预计时间 | 约 + 整数分钟 | 约 3 分钟 / 不到 1 分钟 |
| 相对时间 | 刚刚（<1 分）/ N 分钟前 / 今天 14:20 / 11 月 20 日 | — |
| 绝对时间（日志） | `HH:mm:ss.S` 等宽 | 14:20:05.3 |
| 轮次 | 第 N/M 轮；节点头部只写 N/M | 第 2/5 轮 |
| 计数 | 数字 + 量词 | 3 个节点、2 条连线、1 项待审批 |
| 版本 | v + 数字 | v12 |
| 档位 | 数字 + 名称 | 2 · 部分授权 |
| 路径 | 用 `/` 分隔，等宽 | 根图/闭环迭代#r2/执行池 |

## 6. 模型说话的口吻

模型在对话、提议理由、诊断中说话时：

- **第一人称、陈述事实**：「我在验收者后加了人工审批，因为结果会对外发送。」
- 理由一句话，不超过 40 字，先写目的。
- 不道歉、不自夸、不说“我觉得你可能会喜欢”。
- 涉及数字时给出来源：「依据：第 2 轮运行，执行池排队 38 秒」。
- 需要用户做决定时，明确列出选项，不用反问句。
- 失败时说清它做到哪里了：「改了 3 处，第 4 处“删除格式转换”被拒绝，原因是授权不包括删除。」
- 模型输出在界面上始终带模型标识（AI 签或模型色），不伪装成系统提示。

| 场景 | 示例 |
|---|---|
| 提议理由 | 抽检率提到 0.4：第 1 轮有 2 条价格无来源 |
| 直接修改后 | 已把执行池并发从 3 改为 5。可撤销 |
| 提权申请 | 需要「发邮件」（L2）向 B 公司询价，当前上限 L1 |
| 诊断 | 瓶颈在检索限流：10 次/分，执行池 4 个任务排队平均 38 秒 |

## 7. T 对象与 key 命名

所有文案放在一个对象里，组件只引用 key。

```ts
export const T = {
  'canvas.empty.title': '从一个节点开始',
  'canvas.empty.desc': '从左侧拖入节点，按 A 快速添加，或者告诉模型你想做什么',
  'node.status.running': '运行中',
  'node.status.waiting': '等待审批',
  'edge.error.typeMismatch': '「{from}」不能接到「{to}」',
  'edge.error.cycle': '环只能通过循环节点形成',
  'run.eta': '约 {min} 分钟',
  'model.proposal.bar': '模型提议 {n} 处修改',
  'action.accept': '采纳',
  'action.reject': '拒绝',
} as const;
```

**命名规则**

| 规则 | 说明 |
|---|---|
| 结构 | `域.对象.用途`，最多 4 段，全小写，多词用 camelCase |
| 域 | `app` `canvas` `node` `port` `edge` `panel` `inspector` `run` `model` `auth` `history` `action` `error` `time` |
| 通用动词 | 放在 `action.*`，不在各处重复定义 |
| 占位符 | `{name}` 形式；数字占位符由格式化函数处理（第 5 节），不在文案里拼 |
| 复数 | 中文不区分，统一「{n} 个」 |
| 禁止 | key 里写中文；用文案本身做 key；在组件里拼接字符串 |

格式化函数：`t(key, vars)`；数字统一走 `fmt.tokens()` `fmt.money()` `fmt.duration()` `fmt.relTime()`。
