## 1. 端口

### 1.1 规格

| 项 | 值 |
|---|---|
| 圆点直径 | `--hx-port`（10px） |
| 填充 | 类型色 `--hx-type-*` |
| 缝隙描边 | 2px，颜色 `--hx-bg-3`（与节点主体同色），用 `box-shadow: 0 0 0 2px var(--hx-bg-3)` 实现 |
| 圆心位置 | **正好落在节点左边框（输入）或右边框（输出）上** |
| 热区 | 圆心周围 18×18 的透明方块（`::before` 伪元素） |
| 端口名 | `--hx-fs-12`、`--hx-text-2`；和圆点间距 8 |
| 悬停 | 圆点放大到 `scale(1.3)`，`--hx-t-1`；在外侧 8px 处浮出类型标签 |

### 1.2 类型标签（悬停出现）

```css
.hx-port__tag { position:absolute; top:50%; transform:translateY(-50%);
  height:18px; padding:0 6px; border-radius:var(--hx-r-xs);
  font:500 var(--hx-fs-10)/18px var(--hx-font-mono);
  color: var(--port-color); background: var(--hx-bg-2); box-shadow: var(--hx-shadow-float); white-space:nowrap; }
.hx-port--in  .hx-port__tag { right: calc(100% + 8px); }   /* 输入端口：标签在节点外左侧 */
.hx-port--out .hx-port__tag { left:  calc(100% + 8px); }
```

标签内容：类型名加版本，例如 `上下文包`、`列表[方案@1]`、`T = 方案@1`。泛型端口显示推断后的类型；还没推断出来时显示 `T`。延迟 250ms 出现，移开后立即消失。

### 1.3 圆心坐标（世界坐标，常数计算）

```js
const HEAD = 38, ROW = 24, PAD = 4;  // 与 --hx-node-head / --hx-node-row 一致
function portPos(node, side, rowIndex) {
  const x = side === 'in' ? node.x : node.x + node.w;   // w = 236 或 184
  const y = node.y + HEAD + 1 + PAD + rowIndex * ROW + ROW / 2;  // +1 为分隔线
  return [x, y];
}
```

**规则**：连线的端点**只能**用这个函数计算，不允许在拖动帧里读取 DOM 坐标（17_性能.md R2）。分支节点的出口行号、汇合节点的动态插口行号，都由节点定义算出。

### 1.4 端口种类与外观

| 种类 | 外观 | 说明 |
|---|---|---|
| 单连（默认） | 实心圆点 | 输入端口默认只接一根线；接新线会替换旧线 |
| 多连 `multi` | 圆点改成 10×10 的圆角方块（`border-radius: 3px`） | 例如 Agent.tools。输出端口天然可以连多根，不需要特殊外观 |
| 可选 | 实心圆点，端口名后加 `?`（`--hx-text-3`） | — |
| 必填 | 端口名后加 `*`（`--hx-danger`，只在**没连**时显示） | 没连时圆点改为空心（2px 类型色描边，内部 `--hx-bg-3`），运行前图检查会报错 |
| 由参数转来 | 端口名后加 `⇢` 小标记（`--hx-text-3`）；端口名用参数名 | 在检查器里取消转端口后，这一行消失，连在上面的线一起删除（可撤销） |
| 动态插口 `[+]` | 已连接的插口照常显示；末尾总有一个空插口：空心圆点，端口名显示 `+`（`--hx-text-3`） | 汇合、上下文装配的 `in_*`。连上空插口后自动新增一个；断开后多余的空插口自动收起，只保留一个 |
| 互斥（二选一） | 未被使用的一个端口整行 `opacity: .45` | 例如扇出的 `items` 和 `n` |
| 已连接 | 实心圆点（同默认） | 没连的可选端口也是实心，不需要区分 |

## 2. 连线

### 2.1 路径公式

```js
// a = 源（输出端口），b = 目标（输入端口），世界坐标
function edgePath([ax, ay], [bx, by]) {
  const dx = bx - ax;
  let c;
  if (dx >= 0) c = Math.min(Math.max(dx * 0.5, 48), 180);   // 正常方向
  else         c = 120 + Math.min(-dx * 0.25, 80);          // 回连：终点在起点左侧
  return `M${ax},${ay} C${ax + c},${ay} ${bx - c},${by} ${bx},${by}`;
}
```

- 两端的切线始终水平。
- 回连（只会出现在循环节点内部，从循环体末尾连回开头时由系统画出）：控制点固定往外拉 120–200，形成一个从两侧绕出去的弧形，不会穿过节点。
- 中点（用于 `+` `×` 按钮和标签）：贝塞尔曲线 t = 0.5 处，`P = (a + 3·c1 + 3·c2 + b) / 8`。

### 2.2 DOM

所有连线放在同一个 `<svg class="hx-edges">` 里，和节点共用世界容器的 transform。每条线是一个 `<g>`：

```html
<g class="hx-edge hx-type-ctx is-running" data-id="e7">
  <path class="hx-edge__hit"  d="…"/>   <!-- 14px 透明热区 -->
  <path class="hx-edge__halo" d="…"/>   <!-- 选中光晕 -->
  <path class="hx-edge__line" d="…"/>   <!-- 主线 -->
  <path class="hx-edge__flow" d="…"/>   <!-- 运行流动层，只在 is-running 时存在 -->
</g>
```

### 2.3 颜色与状态

连线颜色 = **源端口**的类型色（`--edge-color` 由 `.hx-type-*` 设置）。

| 状态 class | 主线 | 其他层 |
|---|---|---|
| 默认 | 1.75px，`--edge-color`，`opacity .7`（浅色主题下用 .8） | — |
| 悬停 `is-hover` | 2.5px，`opacity 1` | 中点出现 `+`（插入节点）和 `×`（删除）两个 18px 圆形按钮，`--hx-bg-2` 底，`--hx-shadow-float` |
| 选中 `is-selected` | 2.5px，`opacity 1` | 光晕层：6px 同色，`opacity .18` |
| 运行中 `is-running`（源节点在运行，或刚把数据传出去） | 1.75px，`opacity 1` | 流动层：2px `--hx-accent`，`stroke-dasharray: 1 11`，`stroke-linecap: round`，`stroke-dashoffset` 每 600ms 移动 -12，线性无限循环 |
| 完成 `is-done`（数据已经传过） | 1.75px，`opacity 1` | — |
| 跳过 `is-skipped` | 1.25px，`--hx-text-3`，`stroke-dasharray: 3 4`，`opacity .5` | — |
| 幽灵 `is-ghost` | 1.5px，`--hx-model`，`stroke-dasharray: 5 4` | — |
| 提议删除 `is-del` | 1.5px，`--hx-danger`，`stroke-dasharray: 5 4`，`opacity .6` | — |
| 不兼容预览 | 1.5px，`--hx-danger`，`stroke-dasharray: 4 4` | 光标旁出现原因标签（见第 4 节） |
| 正在拖的预览线 | 1.75px，`--edge-color`，`stroke-dasharray: 6 4` | — |

流动动画只加在 `is-running` 的线上，完成后移除流动层（17_性能.md R8）：

```css
.hx-edge__flow { stroke: var(--hx-accent); stroke-width: 2; stroke-dasharray: 1 11; stroke-linecap: round;
  animation: hx-flow 600ms linear infinite; }
@keyframes hx-flow { to { stroke-dashoffset: -12; } }
@media (prefers-reduced-motion: reduce) { .hx-edge__flow { animation: none; stroke-dasharray: none; opacity: .6; } }
```

L3 概览档下（07_画布.md 第 3 节），所有线固定为屏幕上 1px，并关闭流动层。

### 2.4 重叠与交叉

| 情况 | 处理 |
|---|---|
| 同一对端口之间重复连线 | 不允许，忽略这次操作 |
| 同一个输出连到很多输入 | 曲线从同一点出发，自然分开，不做额外处理 |
| 连线穿过节点 | 连线位于节点下方（07_画布.md 第 10 节），视觉上被节点遮住，不做绕行。按 L 自动布局可以减少这种情况 |
| 连线互相交叉 | 不处理。悬停时被悬停的线提到最上层（把它的 `<g>` 移到 svg 末尾），方便辨认 |
| 很多线挤在一起难以点中 | 热区为 14px；多条线的热区重叠时，取离光标最近的一条（按中点距离判断） |

### 2.5 连线标签（P1）

可选功能。在连线中点显示一个小标签，有两种用途：
- 运行后显示这条线上传过的数据摘要，例如 `3 项`、`方案@1 ×3`
- 用户手动写的备注

样式：高 18，`--hx-bg-2` 底，`--hx-shadow-float`，mono 10.5，`--hx-text-2`。只在 L1 档显示，悬停连线时隐藏（给 `+` `×` 按钮让位）。

## 3. 拖线交互

### 3.1 状态机

```
               pointerdown 在输出端口
   ┌──────┐  ───────────────────────────▶ ┌──────────┐
   │ idle │                               │ pressing │  移动 < 3px
   └──────┘ ◀── pointerup（只是点击）──── └──────────┘
      ▲                                        │ 移动 ≥ 3px
      │                                        ▼
      │        离开吸附范围              ┌──────────┐
      │      ┌────────────────────────── │ dragging │ ◀─┐
      │      ▼                           └──────────┘   │
      │  ┌──────────┐  进入兼容端口 18px     │  │        │
      │  │ snapping │ ◀───────────────────────┘  │        │
      │  └──────────┘                            │ 悬停不兼容端口
      │      │ pointerup                         ▼        │
      │      ▼                             ┌──────────┐   │
      │  ┌──────────┐                      │ invalid  │ ──┘ 离开
      ├──│ connect  │                      └──────────┘
      │  └──────────┘                            │ pointerup
      │                                          ▼
      │  pointerup 在空白处 ──▶ ┌────────────┐  提示原因，回到 idle
      │                         │ quick-add  │ 选中节点 → 创建并连线 → idle
      │                         └────────────┘  Esc / 点击外部 → idle
      └── Esc / 右键 / pointercancel（任何拖线状态下）= cancel
```

| 状态 | 进入条件 | 画布表现 | 光标 |
|---|---|---|---|
| `pressing` | 在输出端口按下 | 端口放大到 1.3 倍 | `crosshair` |
| `dragging` | 移动 ≥ 3px | ① 从端口拉出预览线，终点跟随光标<br>② **兼容的输入端口**：圆点放大到 1.3 倍，外加 4px 同色光环（`opacity .25`），端口名变为 `--hx-text-1`<br>③ **不兼容的端口**：`opacity .3`<br>④ 不能连接的节点（例如源节点自己）整体 `opacity .55`<br>⑤ 视口边缘 40px 内自动平移，速度与距离成正比，最快每帧 12px | `crosshair` |
| `snapping` | 光标进入某个兼容端口 18 个**屏幕**像素以内 | 预览线终点吸到这个端口的圆心；端口光环变为实色；如果目标是单连且已经接了线，旧线变为 `--hx-danger` 虚线，提示将被替换 | `copy` |
| `invalid` | 光标停在一个不兼容的端口上 | 预览线变为红色虚线；光标旁 12px 处显示原因标签（`--hx-danger-weak` 底，`--hx-danger` 字，12px） | `not-allowed` |
| `connect` | 在 snapping 状态下松手 | 生成 `connect` 操作（如果有被替换的旧线，同一个操作里一并 `disconnect`），新线有一次 `--hx-t-2` 的从 `opacity .4` 到 1 的淡入 | — |
| `quick-add` | 在 dragging 状态下、空白处松手 | 在松手位置打开快速添加面板（3.2）；预览线保持显示，终点固定在松手位置 | — |
| `cancel` | Esc、右键、pointercancel | 预览线以 `--hx-t-2` 淡出，所有端口恢复 | — |

实现要点：
- 指针按下时调用 `setPointerCapture`。
- **候选端口在 pressing 进入 dragging 时一次算好**：遍历当前层所有输入端口，算出世界坐标和兼容性，存进数组。之后每帧只做距离比较，不再读 DOM，也不再做类型判断。
- 每帧的处理在 rAF 中合并（17_性能.md R3）。

```js
function onDragStart(src) {
  candidates = allInputPorts().map(p => ({ ...p, pos: portPos(p.node, 'in', p.row),
                                           ok: canConnect(src, p) }));   // { ok:true } | { ok:false, reason }
  document.body.classList.add('hx-linking');                            // CSS 负责变暗和发亮
  candidates.forEach(c => c.el.classList.add(c.ok.ok ? 'is-candidate' : 'is-incompatible'));
}
function nearest(worldPt, k) {
  const r = 18 / k; let best = null, bd = r * r;
  for (const c of candidates) { if (!c.ok.ok) continue;
    const d = (c.pos[0]-worldPt[0])**2 + (c.pos[1]-worldPt[1])**2; if (d < bd) { bd = d; best = c; } }
  return best;
}
```

### 3.2 快速添加面板

| 项 | 规格 |
|---|---|
| 位置 | 松手点右下方 8px；超出视口时翻转到另一侧 |
| 尺寸 | 宽 280，最多显示 8 项，超出滚动 |
| 结构 | 顶部是搜索框（自动聚焦），下面是结果列表，每项 32 高：图标 + 节点名 + 将要连接的端口名（mono 11，`--hx-text-3`），例如 `Agent  → context` |
| 过滤 | 只列出**至少有一个输入端口能接这种源类型**的节点（原子节点、扩展节点、子图库里的子图）；按"最近使用 → 精确类型匹配 → 通过继承匹配 → 接受「任意」"排序 |
| 选择 | 方向键加 Enter，或点击 |
| 结果 | 在松手点创建节点（吸附网格），让被连接端口的圆心正好落在松手点附近；然后自动连线。整个过程是**一次**操作（`add_node` 和 `connect` 合并成一个复合操作），撤销一次就全部撤回 |
| 关闭 | Esc 或点击外部，预览线淡出 |

从**输入端口**往回拖到空白处也能打开这个面板，这时过滤条件变成"输出端口能接到这个输入的节点"，新节点放在松手点的左边。

### 3.3 拔线重接

| 操作 | 结果 |
|---|---|
| 在**已连接的输入端口**上按下并拖动 | 这条线的输入端从端口上"拔下"，跟随光标，状态直接进入 `dragging`（源还是原来的输出端口） |
| 拖到另一个兼容端口松手 | 生成一个 `reconnect` 操作（相当于 disconnect 加 connect，撤销时一次恢复） |
| 拖到空白处松手 | **删除这条线**（不打开快速添加面板，这和从输出端口拖出不同），并提示「已断开 · 撤销」 |
| Esc | 恢复原来的连线 |

输入端口是多连端口时，拔的是最上面那根线（最后连上的那根）。

### 3.4 其他连线操作

| 操作 | 结果 |
|---|---|
| Alt 加点击端口 | 断开这个端口上的所有连线（一个操作） |
| 选中连线后按 Delete | 删除 |
| 悬停连线后点击中点的 `×` | 删除 |
| 悬停连线后点击中点的 `+` | 在这个位置打开快速添加面板，过滤条件是"能同时接上源类型、并且能输出目标类型的节点"。选中后把新节点插在中间：原连线删掉，变成 源 → 新节点 → 目标 两根线，整体是一个操作。新节点放在中点处，如果和其他节点重叠，就把目标那一侧的下游节点整体右移，留出空间（带 `--hx-t-3` 位移动画） |
| 把一个节点拖到一条连线上并停留 400ms | 连线高亮，松手就插入，效果同上 |
| 右键连线 | 菜单：插入节点、删除、选中两端节点、跳到源节点、跳到目标节点 |

## 4. 类型兼容规则

规则按顺序检查，**第一个不通过的规则**决定提示文案。`canConnect(src, dst)` 返回 `{ ok: true, note? }` 或 `{ ok: false, code, reason }`。

| # | 规则 | 能否连接 | 不通过时的提示（reason） |
|---|---|---|---|
| R0 | 源节点和目标节点相同 | 否 | 不能把节点连到自己 |
| R1 | 两端在不同的层（子图内外） | 否 | 跨层连接要通过子图端口 |
| R2 | 连上后会形成环，并且环上没有循环节点 | 否 | 这条线会形成环。要重复执行，请把这部分放进「循环」节点 |
| R3 | 目标是上下文包端口（Agent.context），源不是上下文装配节点产出的 | 否 | Agent 的上下文只能来自「上下文装配」节点 |
| R4 | 源类型是「任意」，目标是具体类型 | 否 | 「任意」类型不能直接接到具体类型，先经过一个设了输出类型的 Agent |
| R5 | 类型名相同，主版本相同 | 是 | — |
| R6 | 源是目标的子类型（继承链上） | 是，`note: 子类型` | — |
| R7 | 源是目标的父类型 | 否 | {src} 是 {dst} 的父类型，缺少 {dst} 必填的字段 |
| R8 | 类型名相同，主版本不同，有迁移函数 | 是，`note: 将自动迁移 v1→v2` | — |
| R9 | 类型名相同，主版本不同，没有迁移函数 | 否 | {src} 与 {dst} 主版本不兼容，没有可用的迁移 |
| R10 | 源是 `列表[T]`，目标接收 `T`，并且 T 兼容 | 是，`note: 将对每一项各运行一次`，端口旁显示 `×N` 展开标记 | — |
| R11 | 源是 `T`，目标接收 `列表[T]` | 否 | 单个 {T} 不能接到列表端口。需要的话，先接「汇合」节点 |
| R12 | 目标是「任意」或泛型 T（尚未确定） | 是，T 由此确定 | — |
| R13 | 目标是泛型 T，但已经被其他连线确定为别的类型 | 否 | 这个端口的类型已经确定为 {T}，和 {src} 不一致 |
| R14 | 资源引用的种类不匹配（例如提示词接到 model 端口） | 否 | 这里需要「模型」资源，收到的是「提示词」 |
| R15 | 工具端点接到非 tools 端口，或反过来 | 否 | 工具端点只能接到 Agent 的 tools 端口 |
| R16 | 其他所有类型名不同的情况 | 否 | {src} 不能接到 {dst} |

- R2 的环检测：从目标节点出发沿出边做一次深度优先搜索，如果能到达源节点，就会成环。在拖线开始时，对每个候选端口算一次，结果缓存。
- 提示文案里的 `{src}` `{dst}` 用类型的显示名，例如「执行结果@1」。
- 带 `note` 的情况可以连接，但在 snapping 状态的端口旁显示 note 小字（`--hx-text-3`），连接后在连线中点短暂显示 2 秒。

### 4.1 兼容判断伪代码

```js
function canConnect(src, dst) {
  if (src.node === dst.node) return no('R0');
  if (src.layer !== dst.layer) return no('R1');
  if (wouldCycle(src.node, dst.node) && !pathHasLoopNode(src.node, dst.node)) return no('R2');
  if (dst.type === '上下文包' && src.node.type !== '上下文装配') return no('R3');
  if (src.type === '任意' && !isAnyOrGeneric(dst)) return no('R4');
  if (isAnyOrGeneric(dst)) return dst.bound && !compat(src.type, dst.bound) ? no('R13') : yes();
  if (isList(src.type) && !isList(dst.type) && compat(elem(src.type), dst.type)) return yes('将对每一项各运行一次');
  if (!isList(src.type) && isList(dst.type)) return no('R11');
  return compat(src.type, dst.type);   // 依次检查 R5–R9、R14–R16
}
```
