# 18 前端架构与组件约定

> 本文定义画布前端怎么组织代码、状态长什么样、修改怎么流转，以及前端和引擎之间的协议边界。它是从原型走向真实引擎的接口文档，实现时以本文的类型定义为准。

---

## 1. 技术栈（已确定）

| 层 | 选型 |
|---|---|
| 前端框架 | **Next.js（App Router）+ React 18/19 + TypeScript strict** |
| 画布 | 自研：React 外壳 + **命令式渲染层**（绕过 React 重渲染） |
| 状态 | **zustand**（含 `subscribeWithSelector`、`immer` 中间件按需） |
| 样式 | 全局 `tokens.css` + CSS Modules（组件）+ 画布用全局 BEM 类 |
| 后端 | **Go**（引擎、存储、授权、运行事件） |
| 契约 | **JSON Schema 为唯一事实来源**，代码生成 TS 类型与 Go 结构体 |
| 运行事件 | **SSE**（推荐，理由见 8.4），WebSocket 作为协同编辑阶段的升级选项 |
| Op 提交 | HTTP `POST`，带 `base_version` 乐观锁 |

### 1.1 画布为什么不能交给 React 渲染

React 的协调（reconcile）在每次状态变化时比较虚拟 DOM。画布上平移、缩放、拖动每秒 60 次，若每次都让 React 重渲染 200 个节点组件，单帧就会超出预算（R1–R6）。所以：

| 交给 React | 不交给 React（命令式渲染层直接写 DOM） |
|---|---|
| 画布外壳、面板（节点库、检查器、抽屉、顶部条、命令面板、通知） | 世界容器 transform（平移、缩放） |
| 节点的**创建与删除**（结构变化，频率低）——也可交给渲染层，见 1.2 | 节点位置（拖动中）、连线 path `d` |
| 检查器里的参数表单 | 节点运行状态 class、进度条 scaleX |
| 对话卡片 | 叠加层：框选、拖线预览、吸附光环、AI 光标 |
| — | 小地图 canvas 绘制、网格背景位置 |

### 1.2 画布层的两种挂载方式（取 B）

- A：每个节点是一个 React 组件，用 `React.memo`，拖动时用 ref 直接改 transform。问题：状态 class 更新仍可能触发组件重渲染，200 节点时边界情况多。
- **B（采用）**：`<Canvas>` 是一个 React 组件，只渲染一个空的根 `<div ref>`；`useEffect` 中创建 `CanvasEngine` 实例，由它用原生 DOM 创建和复用所有节点、连线（DOM 池）。React 只负责外壳和面板。节点内联控件也由渲染层生成原生 DOM 控件（或通过 `createPortal` 挂少量 React 控件到节点插槽，仅在选中节点上使用）。

```tsx
'use client';
export function Canvas({ graphId }: { graphId: string }) {
  const host = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const engine = new CanvasEngine(host.current!, useGraphStore, useRunStore);
    return () => engine.destroy();           // 卸载时清理监听与 DOM 池
  }, [graphId]);
  return <div ref={host} className="hx-canvas" />;
}
```

`CanvasEngine` 通过 zustand 的 **非 React 订阅**（`store.subscribe(selector, cb)`）拿到变化，完全不触发 React 渲染。

### 1.3 状态库选型：zustand

| 需求 | zustand 的满足方式 |
|---|---|
| 非 React 代码（渲染层）也要订阅 | `store.subscribe` / `getState()` 直接可用，无需 Provider |
| 精确订阅片段，避免面板重渲染 | `useStore(selector, shallow)`；`subscribeWithSelector` |
| 高频更新不卡 | 更新是同步赋值，渲染层自行在 rAF 合并 |
| 体积与心智负担小 | ~1KB，无模板代码，接手成本低 |
| 可拆分多个 store | 按域拆：graph / view / ui / run / auth / model |

不选 Redux Toolkit（模板多、渲染层接入要额外桥接）；不选 Jotai（原子分散，渲染层难以整体订阅）；Valtio 可行但代理对象在 rAF 热路径上有额外开销。

**拆分**：`useGraphStore`（doc、history、dispatch）、`useViewStore`（view，**只给渲染层用**，面板只读缩放百分比）、`useUiStore`、`useRunStore`、`useAuthStore`、`useModelStore`。`view` 单独成 store，是为了平移缩放时不惊动任何 React 订阅者。

### 2.1 服务端组件与客户端组件

| 组件 | 类型 | 理由 |
|---|---|---|
| `app/layout.tsx`、会话页外壳 | 服务端 | 取会话元数据、首屏 HTML；注入主题同步脚本防闪烁 |
| 对话消息列表（历史消息） | 服务端渲染首屏 + 客户端增量 | 首屏快 |
| `CanvasCard`（对话里的画布卡片） | **'use client'** | 订阅运行状态 |
| `Canvas` 及 `canvas/` 下全部 | **'use client'** | 指针、键盘、rAF、DOM 池 |
| 面板、控件、命令面板、通知 | **'use client'** | 交互 |
| 节点库数据（节点定义、扩展包列表） | 服务端获取，作为 props 传入客户端面板 | 静态、可缓存 |

规则：`canvas/core/` 里的文件不 import 任何 React；`Canvas.tsx` 用 `next/dynamic(..., { ssr: false })` 引入，避免服务端执行到 `window`。

### 3.1 图数据

```ts

export type AtomicKind =
  | '资源' | 'Agent' | '上下文装配' | '工具' | '扇出' | '汇合' | '聚合'

export interface GraphNode {
```

## 4. Op 与 dispatch

### 4.1 Op 类型

所有修改，无论来自人、模型、YAML 还是外部 API，都表示为 Op。每种 Op 都能生成自己的 `inverse`。

```ts
export interface OpBase {
  id: string;                 // 'op_' + nanoid
  actor: Actor;
  reason?: string;            // 模型必填，人可选
  at: number;                 // 时间戳
  scope: NodeId[];            // 所在子图路径，根图为 []
  baseVersion: number;        // 发起时看到的图版本（乐观锁）
  taint?: { source: string; ptr: string }; // 由外部内容引出
  mergeKey?: string;          // 连续操作合并用，如 'move:n_12'
}

export type OpPayload =
  | { kind: 'node.add';      node: GraphNode }
  | { kind: 'node.remove';   id: NodeId; snapshot: GraphNode; edges: GraphEdge[] }
  | { kind: 'node.move';     moves: { id: NodeId; from: Pt; to: Pt }[] }
  | { kind: 'node.rename';   id: NodeId; from: string; to: string }
  | { kind: 'node.resize';   id: NodeId; from?: number; to?: number }
  | { kind: 'param.set';     id: NodeId; key: string; from: unknown; to: unknown }
  | { kind: 'param.promote'; id: NodeId; key: string; on: boolean; removedEdges: GraphEdge[] }
  | { kind: 'node.tag';      id: NodeId; from: string[]; to: string[] }
  | { kind: 'edge.add';      edge: GraphEdge; replaced?: GraphEdge }
  | { kind: 'edge.remove';   edge: GraphEdge }
  | { kind: 'group';         ids: NodeId[]; into: GraphNode; rewired: { removed: GraphEdge[]; added: GraphEdge[] } }
  | { kind: 'ungroup';       id: NodeId; snapshot: GraphNode; restored: { nodes: GraphNode[]; edges: GraphEdge[] } }
  | { kind: 'subgraph.ref';  id: NodeId; from: GraphNode['ref']; to: GraphNode['ref'] }
  | { kind: 'layout';        moves: { id: NodeId; from: Pt; to: Pt }[] }   // 自动布局
  | { kind: 'doc.replace';   from: GraphDoc; to: GraphDoc }                // YAML 应用、载入模板
  | { kind: 'batch';         ops: OpPayload[]; label: string }             // 封装多个为一步
  | { kind: 'auth.level';    target: string; from: number; to: number }
  | { kind: 'auth.mandate';  from: Mandate; to: Mandate }
  | { kind: 'auth.taintGuard'; from: boolean; to: boolean }
  | { kind: 'branch.create'; name: string; from: string }
  | { kind: 'branch.merge';  from: string; into: string; diff: GraphDiff };

export type Op = OpBase & OpPayload;

// 不进入撤销历史、但要记录到审计日志的控制类操作
export type ControlOp =
  | { kind: 'run.start'; graphVersion: number }
  | { kind: 'run.pause' } | { kind: 'run.resume' } | { kind: 'run.cancel' }
  | { kind: 'run.estop' } | { kind: 'run.estop.release' }
  | { kind: 'approval.resolve'; id: string; result: 'approve' | 'deny'; once?: boolean }
  | { kind: 'proposal.resolve'; id: string; result: 'accept' | 'reject' };
```

### 4.2 inverse 规则

| kind | inverse |
|---|---|
| node.add | node.remove（snapshot = 该节点，edges = []） |
| node.remove | node.add（snapshot） + edge.add × edges |
| node.move / layout | 同 kind，from 与 to 互换 |
| node.rename / param.set / node.tag / subgraph.ref / auth.* | 同 kind，from 与 to 互换 |
| param.promote | on 取反，并恢复 removedEdges |
| edge.add | edge.remove（若有 replaced，则再 edge.add replaced） |
| edge.remove | edge.add |
| group | ungroup（snapshot = into，restored = 原节点与原连线） |
| ungroup | group |
| doc.replace | doc.replace（from/to 互换） |
| batch | batch（逆序的各 inverse） |
| branch.create | 删除分支（不进普通撤销栈，需确认） |

**完备性要求**：apply(op) 之后 apply(inverse(op))，图必须与之前**逐字段相等**（单元测试必测）。所以 remove 类 Op 必须携带完整快照。

### 4.3 合并

连续的同类 Op 在 600ms 内且 `mergeKey` 相同就合并成一条：拖动节点（`move:ids`）、数字步进拖调值（`param:id:key`）、文本参数连续输入。合并保留第一条的 `from` 和最后一条的 `to`。

### 4.4 dispatch 流水线

```ts
export function dispatch(input: Op | Op[], opts: { record?: boolean } = {}) {
  const ops = Array.isArray(input) ? input : [input];
  for (const op of ops) {
    // 1. 结构校验：引用的节点/端口存在、类型兼容、无非法环、内核锁定项未被修改
    const v = validate(state.doc, op);
    if (!v.ok) return fail(op, v.reason);              // 行内提示 / 拖线红色

    // 2. 版本检查：baseVersion 落后时，尝试变基；冲突则转入草稿分支
    if (op.baseVersion !== state.doc.version) {
      const rebased = rebase(op, state.history.past, op.baseVersion);
      if (!rebased) return toDraft(op);
    }

    // 3. 授权检查（人只检查急停和只读回放；模型按档位、授权书、污染标记）
    const a = authorize(state.auth, op);
    if (a.decision === 'deny')     return fail(op, a.reason);
    if (a.decision === 'propose')  return addProposal(op, a);   // 1 档 → 幽灵
    if (a.decision === 'approval') return requestApproval(op, a); // 超范围 → 审批卡

    // 4. 应用：纯函数，返回新文档和受影响集合
    const { doc, touched } = apply(state.doc, op);
    state.doc = { ...doc, version: state.doc.version + 1 };

    // 5. 记历史 + 审计
    if (opts.record !== false) pushHistory(op);        // 含合并逻辑，清空 future
    audit.append(op);

    // 6. 增量渲染：只通知受影响的节点、连线、面板
    store.emit({ nodes: touched.nodes, edges: touched.edges, panels: touched.panels });

    // 7. 同步给引擎（草稿分支不同步）
    engineClient.sendOp(op);
  }
}
```

`authorize` 的返回：`{ decision: 'allow' | 'propose' | 'approval' | 'deny', reason, needs?: string[] }`。授权规则见架构文档的授权章节；**人的操作不被档位拦截**，只受急停和只读回放影响。

## 5. Store 与订阅（zustand）

```ts
// state/graph.ts
export const useGraphStore = create<GraphState>()(subscribeWithSelector((set, get) => ({
  doc: emptyDoc(), history: { past: [], future: [] },
  dispatch: (op) => dispatch(op, set, get),     // 唯一修改入口
})));

// 面板（React）：精确订阅
const label = useGraphStore(s => s.doc.nodes[id]?.label);

// 渲染层（非 React）：订阅变化集合，在 rAF 中统一处理
useGraphStore.subscribe(s => s.lastChange, (c) => engine.markDirty(c.nodes, c.edges));
```
- `dispatch` 每次应用 Op 后写入 `lastChange: { nodes:Set, edges:Set, panels:Set, seq }`，渲染层只按这个增量更新。
- 面板禁止订阅整个 `doc`；必须用 selector + `shallow`。
- `useViewStore` 只被渲染层订阅；顶部条的缩放百分比用节流（200ms）订阅。
- 跨 store 的读取用 `getState()`，不在 React 渲染期间调用 `dispatch`。

## 7. 事件总线

内部事件（不改状态，只通知）用一个类型安全的总线：

```ts
type Events = {
  'op.applied':      { op: Op };
  'op.rejected':     { op: Op; reason: string };
  'proposal.added':  { proposal: Proposal };
  'approval.needed': { approval: Approval };          // 节点、对话、通知三处订阅
  'approval.resolved': { id: string; result: 'approve' | 'deny' };
  'run.event':       { ev: RunEvent };
  'toast':           { level: 'info'|'ok'|'wait'|'error'|'model'; text: string; action?: { label: string; op: () => void } };
  'a11y.announce':   { text: string; urgent?: boolean };
  'chat.post':       { role: 'model' | 'system'; html: string; refs?: NodeId[] }; // 发到 harness 对话
};
bus.on<K extends keyof Events>(k: K, fn: (p: Events[K]) => void): () => void;
bus.emit<K extends keyof Events>(k: K, p: Events[K]): void;
```
与 harness 宿主的对接只通过 `chat.post`（画布 → 对话）和 `<hx-canvas>` 的方法 `applyModelOps(ops)`、`focusNode(id)`（对话 → 画布）。

## 8. 前端 ↔ 引擎协议边界

前端不执行图，只编辑图、发起运行、消费事件。引擎是唯一的执行者。

### 8.1 图文档 JSON Schema（草案）

```json
{
  "$id": "hx.graph/1",
  "type": "object",
  "required": ["schema", "id", "name", "nodes", "edges", "version"],
  "properties": {
    "schema":  { "const": "hx.graph/1" },
    "id":      { "type": "string" },
    "name":    { "type": "string" },
    "version": { "type": "integer", "minimum": 0 },
    "nodes": {
      "type": "object",
      "additionalProperties": {
        "type": "object",
        "required": ["id", "kind", "label", "x", "y", "params"],
        "properties": {
          "id": { "type": "string" }, "kind": { "type": "string" }, "label": { "type": "string" },
          "x": { "type": "number" }, "y": { "type": "number" }, "w": { "type": "number" },
          "params":   { "type": "object" },
          "promoted": { "type": "array", "items": { "type": "string" } },
          "tags":     { "type": "array", "items": { "type": "string" } },
          "subgraph": { "$ref": "hx.graph/1" },
          "ref": { "type": "object", "properties": {
            "id": { "type": "string" }, "version": { "type": "string" },
            "pin": { "enum": ["snapshot", "link"] } } }
        }
      }
    },
    "edges": {
      "type": "object",
      "additionalProperties": {
        "type": "object", "required": ["id", "from", "to"],
        "properties": {
          "from": { "type": "object", "required": ["node", "port"] },
          "to":   { "type": "object", "required": ["node", "port"] }
        }
      }
    }
  }
}
```
`x/y/w` 属于视图信息，引擎忽略；其余字段引擎必须理解。`meta` 字段（创建者、理由）前端保留，引擎存档但不使用。

### 8.2 前端 → 引擎请求

| 方法 | 参数 | 说明 |
|---|---|---|
| `graph.save` | doc | 保存版本，返回 version |
| `graph.validate` | doc | 引擎侧图检查（权威），返回问题列表 |
| `op.submit` | Op | 协同编辑时实时同步 |
| `run.start` | graphId, version, inputs, mandate | 返回 runId |
| `run.control` | runId, `pause|resume|cancel|estop|patch` | patch 用于运行中改参数，在安全点生效 |
| `approval.resolve` | runId, approvalId, result, once | — |
| `trace.get` | runId, path?, range? | 拉取留痕 |
| `node.replay` | runId, path | 单节点重放 |
| `run.resumeFrom` | runId, checkpointId | 从检查点重跑 |

### 8.3 引擎 → 前端运行事件流

传输：WebSocket 或 SSE，每条一行 JSON；带单调递增 `seq`，断线重连时用 `?since=seq` 补齐。

```ts
export type RunEvent = { runId: string; seq: number; t: number; path: string } & (
  | { type: 'run.status';   status: AppState['run']['status'] }
  | { type: 'node.status';  status: NodeRunStatus; progress?: number; sub?: string; error?: string }
  | { type: 'node.round';   round: number; max: number }
  | { type: 'edge.flow';    edge: EdgeId; envelope: EnvelopeRef }
  | { type: 'node.output';  port: PortName; envelope: EnvelopeRef }
  | { type: 'tool.call';    tool: string; idemKey: string; state: 'queued'|'running'|'done'|'failed'; waitMs?: number }
  | { type: 'approval';     id: string; reason: string; risk: 'L0'|'L1'|'L2'|'L3'; options: string[] }
  | { type: 'escalation';   kind: string; severity: 'low'|'mid'|'high'; message: string }
  | { type: 'brief';        goalId: string; text: string }
  | { type: 'graph.patch';  ops: Op[]; actor: Actor }    // 运行时动态展开子图
  | { type: 'metrics';      tokens: number; cost: number; execs: number }
  | { type: 'log';          level: 'info'|'warn'|'error'; text: string }
);
export interface EnvelopeRef { type: TypeRef; schemaVersion: string; ptr: string; size: number; confidence?: number }
```
- `path` 是层级路径 ID：`根图/闭环迭代#r2/执行池/执行者#3`。前端用它把事件映射到当前视图里的节点（在子图外时，事件聚合到子图节点上显示）。
- 信封正文不随事件下发，只给指针；检查器打开时用 `trace.get` 按需拉取。

### 8.4 与 Go 后端的边界

**契约源**：仓库根 `schema/*.schema.json`（JSON Schema 2020-12）。前后端都**不手写**协议类型。

| 产物 | 工具 | 输出位置 |
|---|---|---|
| TS 类型 | `json-schema-to-typescript` | `web/lib/protocol/generated/*.ts` |
| Go 结构体 | `go-jsonschema`（omissis/go-jsonschema） | `server/internal/protocol/gen/*.go` |
| 运行时校验（前端） | `ajv` 预编译 standalone 校验函数 | `web/lib/protocol/generated/validate.js` |
| 运行时校验（后端） | `santhosh-tekuri/jsonschema` | 请求入口中间件 |

- `make schema` 一条命令同时生成两端；CI 检查生成物与 schema 一致（`git diff --exit-code`）。
- 判别联合（Op、RunEvent 的 `kind`/`type`）在 schema 里用 `oneOf` + `const` 判别字段；Go 端生成后补一个手写的 `UnmarshalJSON` 分派（放 `gen_ext.go`，不被覆盖）。
- schema 版本号写在 `$id`（`hx.graph/1`）；破坏性修改升主版本，后端同时支持新旧两版至少一个发布周期。

**运行事件流：推荐 SSE**

| 维度 | SSE | WebSocket |
|---|---|---|
| 方向 | 服务端 → 客户端（正好是运行事件的方向） | 双向 |
| 断线续传 | 内建 `Last-Event-ID`，与 `seq` 天然对应 | 需自研 |
| 基础设施 | 普通 HTTP，过代理、负载均衡、鉴权 cookie 都简单 | 需要升级握手，部分代理要配置 |
| Go 实现 | `http.Flusher` 即可，几十行 | 需 `gorilla/websocket` 或 `nhooyr/websocket` |
| Next.js 侧 | 浏览器 `EventSource`，或经 BFF 透传 | 不能经 Route Handler 长连接透传，需直连 |

结论：**运行事件用 SSE**；客户端到服务端的命令（Op、运行控制、审批）用普通 HTTP。等到多人/多模型实时协同编辑阶段，再为“图协同通道”单独引入 WebSocket，运行事件仍保持 SSE。

```
GET  /api/runs/{runId}/events        Accept: text/event-stream
     → id: 1832\nevent: node.status\ndata: {...RunEvent}\n\n
     断线重连自动带 Last-Event-ID: 1832，服务端从 1833 补发
```
- 心跳：服务端每 15 秒发 `: ping` 注释行，防代理断开。
- 背压：服务端按 50ms 窗口合并同一节点的进度事件再发送。
- 前端：`lib/protocol/events.ts` 封装 `EventSource`，事件写入 `useRunStore`，渲染层按 17_性能 第 6 节节流。

**Op 提交：HTTP + 乐观锁**

```
POST /api/graphs/{graphId}/ops
{ "base_version": 41, "ops": [ {...Op}, ... ], "client_id": "c_x9", "idempotency_key": "op_7f3a" }

200 { "version": 43, "applied": ["op_7f3a", "op_7f3b"] }
409 { "error": "version_conflict", "current_version": 44,
      "conflicts": [{ "op": "op_7f3a", "node": "n_12", "by": {"kind":"model","id":"orch-1"} }] }
403 { "error": "not_authorized", "decision": "approval", "needs": ["tool_risk>=L2"] }
```
- 前端先本地应用（乐观更新），收到 409 时回滚本地这批 Op，转入草稿分支并提示（14_状态反馈 4.8）。
- `idempotency_key` 让网络重试不会重复应用。
- 授权**以后端为准**：前端的 `authorize` 只用于即时反馈，后端在 Go 侧用同一张决策表复核；两者共用 `schema/auth-matrix.json` 生成的表。
- 字段命名：JSON 统一 `snake_case`（`base_version`），TS 生成类型保持 snake_case，不做转换，避免两套命名。

## 9. 组件 API 约定

- 组件只接收 props 和回调，**不直接修改 store**；修改一律通过回调触发上层 `dispatch`。
- 命名：组件 `PascalCase`；props 用 `value / onChange / disabled / size: 'md'|'sm' / tone: 'default'|'danger'|'model'`。
- 每个可交互组件必须支持：键盘操作、`aria-*`、`disabled`、紧凑尺寸。
- 受控优先：所有输入组件都是受控组件；数字步进的拖动过程用 `onInput`（预览，不生成 Op），松开时 `onChange`（生成一条 Op）。

```tsx
<NumberStepper value={n} min={1} max={32} step={1} size="sm"
  onInput={v => preview(v)} onChange={v => dispatch(paramSet(id, 'concurrency', v))} />
```

## 13. 代码风格

- TypeScript `strict`；禁止 `any`（`unknown` + 收窄）。
- 纯函数优先：`model/ ops/ geom/` 里没有副作用。
- 一个文件一个职责，≤ 400 行。
- 不用 `eval` / `new Function`；表达式（分支条件、循环出口）由引擎的安全表达式解析器执行，前端只做语法高亮和静态检查。
- 每个模块顶部写 5 行以内的说明：负责什么、依赖什么、谁调用它。
- 提交信息：`feat(canvas): …` / `fix(ops): …`。
