Harness · 积木编排架构v0.2 · 2026-11-21
一种 harness 运行模式

人和大模型，用同一套积木编排多 Agent 流程

系统只提供 13 个通用原子节点、一套内核规则和一个运行时。主脑、智囊团、执行池这些角色，只是用节点拼出的一种模板。大模型和你一样能搭图、改图、跑图，能做到哪一步，由你给它的授权档位决定。

八条设计理念

后面所有设计都从这里推出来。

大模型是一等操作者人能在画布上做的事，模型都能做，只是授权档位不同
一切皆数据、操作、授权图、角色卡、配方、授权书都是文档；每次修改都是一条操作；每条操作都要经过授权检查
节点内聪明，节点间"笨"agent 在节点内部自由思考；节点之间的通信、权限、连接规则由运行时强制执行
积木拼完还是积木所有节点对外接口相同，封装后的子图可以无限组合、嵌套
最小充分上下文每个 agent 只装它要干的那件事；该给的一样不少，无关的一样不放
状态外置长期运行的节点靠账本重建认知，不靠越堆越长的对话历史
内核管机制，不管语义业务含义通过类型、配方、策略、表达式填进去，原子节点本身不带业务词
授权可调，留有退路从只读到完全授权共五档；即使完全授权，也保留留痕、快照和急停

六个工作域如何协作

橙色是一次运行的主路径：搭图，经过授权，运行，观测，再优化。

六个工作域原型

每个原型都能直接操作，右上角有「演示脚本」按钮可以一键看完整流程。青线标注的是该域里模型能做什么。

01画布编排搭图、连线、类型检查、参数转端口、封装子图；画布、YAML、操作日志三种视图编辑同一份数据，支持撤销和草稿分支。模型：在对话里用文字改图，1 档生成幽灵节点，2 档以上直接改打开原型 → 02节点与类型13 个原子节点的通用定义和三级锁、类型库三层结构与字段属性、端口兼容性检查、扩展包与自定义节点。模型：起草新类型或新节点，先进临时命名空间，审批后入库打开原型 → 03角色卡与上下文提示词由六段拼装，只有角色卡需要手写；上下文配方决定每个 Agent 看到什么、裁掉什么、哪些换成指针。模型：读运行留痕后改角色卡，并用 A/B 评测比较新旧版本打开原型 → 04授权与安全五档授权可以按对象分别设置，部分授权按维度组合；包括提权申请、自动升降规则、污染标记、急停和审计。模型：申请提权；拿到 4 档后与你同权，但关不掉急停打开原型 → 05模型自主编排编排者本身也是节点组合：设计时生成整张图、运行时动态展开子图、运行后提出优化，授权逐级下传。模型：这一域的主角，从需求出发自己设计流程打开原型 → 06运行与观测层级运行树、时间线、节点输入输出信封、四条通信通道、资源池与背压，可以时间旅行、单节点重放。模型：读留痕诊断瓶颈和失败原因，给出修复补丁打开原型 →

授权五档

档位可以分别设给会话、子图或单个节点，随时调整，在安全点生效。

0
只读
只看图、看状态、看留痕
1
建议
提出补丁，你逐条批准
2
部分授权
范围内直接做，范围外提建议
3
高度授权
只有你列的例外项要审批
4
完全授权
和你同权，保留留痕、快照、急停
