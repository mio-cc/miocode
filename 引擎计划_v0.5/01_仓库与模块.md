# 01 仓库与模块

> v0.5：独立产品，单仓库。目标：`make dev` 一条命令拉起后端和前端开发服务；`make build` 产出一个包含前端的单二进制；包边界清晰，禁止循环依赖；`engine/` 是可被 import 的库，不依赖产品层。
> 总体方案见 [15_独立产品方案.md](15_独立产品方案.md)；每个包参考哪个开源实现见 [16_参考实现对照.md](16_参考实现对照.md)。

## 1. 目录树

```
harness/
├─ go.mod                            # module github.com/<org>/harness
├─ Makefile                          # 目标都转调 go run ./tools/…，Windows 下也可用 Taskfile.yaml
├─ cmd/
│  ├─ harnessd/main.go               # 读配置 → platform 默认实现 → 组装 engine 与 api/app → 起 HTTP → 打开浏览器 → 优雅关闭
│  └─ harnessctl/                    # audit verify / estop / eval compare / export / import / doctor
├─ schema/                           # ★ 唯一事实来源（JSON Schema 2020-12）
│  ├─ graph.schema.json  nodedef.schema.json  types.schema.json
│  ├─ op.schema.json  run-event.schema.json  graph-event.schema.json  session-event.schema.json
│  ├─ mandate.schema.json  graph_patch.schema.json  session.schema.json
│  └─ builtin/ nodedefs/*.yaml  types/*.yaml  recipes/*.yaml  rolecards/*.yaml
├─ gen/                              # ← schema 生成的 Go 类型与事件名常量（不要手改）
├─ engine/                           # 内核库：不依赖 net/http（llm、tools/builtin/http、mcp 例外），不依赖 internal/*
│  ├─ graph/  schema/  op/  authz/  run/  sched/
│  ├─ exec/  executor.go  registry.go
│  │  ├─ resource/ agent/ ctxasm/ tool/ fanout/ join/ aggregate/
│  │  └─ branch/ loop/ ledger/ human/ subport/ subref/
│  │  └─ declarative/                # 声明式扩展节点（prompt / http / mcp / subgraph）的解释执行器
│  ├─ ext/       package.go loader.go  # 扩展包：清单、加载、签名校验、注册到 schema.Registry 与 exec.Registry
│  ├─ ctxasm/    recipe.go assemble.go budget.go overflow.go prompt.go
│  ├─ llm/       llm.go quirks.go repair.go tokens.go  openai/  anthropic/  gemini/  fake/  cassette/
│  ├─ tools/     tool.go registry.go trim.go skill.go builtin/(search http file code)
│  ├─ mcp/       client.go bridge.go     # 基于官方 go-sdk
│  ├─ orch/      patch.go tools.go proposal.go expand.go
│  ├─ store/     store.go  sqlite/  memstore/  (postgres/ 在 M5)   # 所有表加 hx_ 前缀
│  ├─ blob/      blob.go fsblob/
│  └─ obs/       events.go path.go trace.go cost.go metrics.go
├─ internal/
│  ├─ api/                           # HTTP：router graphs ops runs approvals mandates defs models tools sessions settings audit errors idem
│  ├─ sse/                           # hub stream resume（运行流、图协同流、会话流）
│  ├─ app/                           # 产品层：session/ chat/ settings/ onboarding/
│  └─ platform/                      # 本地默认实现：auth/ secret/ config/ lock/
├─ web/                              # Vite + React + TS（目录见设计规范 18 号 §2）
│  └─ src/lib/protocol/generated/    # ← schema 生成的 TS 类型与事件名联合类型
├─ templates/                        # 内置模板包（闭环迭代、生成-评审、代码评审）
├─ evals/                            # 评测集
└─ tools/
   ├─ depcheck/                      # 依赖方向检查
   └─ gen/                           # schema → Go / TS；tokens.css 复制；字体子集化
```

`web/` 的构建产物（`web/dist/`）通过 `cmd/harnessd/embed.go` 里的 `//go:embed` 打进二进制；开发模式（`harnessd --dev`）不 embed，把非 `/api` 请求代理到 Vite dev server。

## 2. Go 包职责与核心接口

| 包 | 职责 | 依赖 |
|---|---|---|
| `gen` | schema 生成的纯数据类型和事件名常量 | 无 |
| `engine/graph` | 内存图模型、索引（按 id、按端口反查）、遍历、深拷贝 | gen |
| `engine/schema` | NodeDef/类型注册表、类型兼容、T 推断、图检查、版本迁移 | gen, graph |
| `engine/ext` | 扩展包加载：读清单 → 校验 → 把 NodeDef、类型、配方、角色卡注册进 Registry，把执行器注册进 exec.Registry | schema, exec |
| `engine/op` | Op 应用、逆操作、rebase、三方合并、拖动合并 | gen, graph, schema |
| `engine/authz` | 授权书解析、Check、污染、急停 | gen, graph |
| `engine/store` | 持久化接口 + sqlite/mem 实现 | gen |
| `engine/blob` | 工作区内容寻址存储 | 无 |
| `engine/obs` | 事件信封、路径 ID、成本累计、指标 | gen |
| `engine/llm` | 模型适配（三家官方 SDK 之上的统一接口 + quirks 表 + cassette） | obs |
| `engine/tools` | 工具注册与调用（含裁剪、指针、SKILL.md 技能） | blob, obs |
| `engine/mcp` | MCP 客户端，桥接为 tools.Tool | tools |
| `engine/ctxasm` | 上下文装配、提示词六段拼装 | schema, blob, llm（仅 token 计数） |
| `engine/exec/*` | 13 个原子执行器 + 声明式执行器 | exec 接口、ctxasm、llm、tools |
| `engine/sched` | 就绪判定、并发、资源池、令牌桶、虚拟时钟 | graph, obs |
| `engine/run` | 运行生命周期、作用域、安全点、崩溃恢复、fork | sched, exec, store, authz, obs |
| `engine/orch` | GraphPatch、图操作工具、提议、运行时展开 | op, schema, authz, tools |
| `internal/api` | HTTP 路由、幂等、错误码 | engine/*, internal/app, internal/platform |
| `internal/sse` | 订阅中心、续传、心跳 | obs, store |
| `internal/app/*` | 会话、对话 Agent、设置、首次引导 | engine/orch, engine/store, internal/platform |
| `internal/platform/*` | 本地鉴权、密钥、配置、单实例锁 | 无 engine 依赖 |

CI 用 `go list -deps` + `tools/depcheck` 校验：`engine/**` 不得 import `internal/**`、`cmd/**` 和 `net/http`（`engine/llm`、`engine/tools/builtin/http`、`engine/mcp` 例外）；`internal/platform` 不得 import `engine/**` 以外的产品层包。

### 核心接口（Go）

执行器接口和 `RunCtx` **以 03 号 §4 为准**，这里只列出跨包最常用的几个：

```go
// engine/exec/executor.go —— 完整定义见 03 号 §4
type Executor interface {
    Kind() string
    Validate(n *graph.Node, g *graph.Graph) []schema.Diag
    Run(rc RunCtx, in Inputs) (Outputs, error)
}

// engine/store/store.go
type Store interface {
    Graphs() GraphRepo
    Ops() OpRepo
    Runs() RunRepo
    Events() EventRepo          // Append / Range(since) / Tail
    Checkpoints() CheckpointRepo
    Approvals() ApprovalRepo
    Mandates() MandateRepo
    Audit() AuditRepo
    Sessions() SessionRepo      // v0.5：会话与消息
    Tx(ctx context.Context, fn func(Store) error) error
}

// engine/llm/llm.go
type Model interface {
    Complete(ctx context.Context, req Req) (Stream, error)
    CountTokens(msgs []Msg) (int, error)
    Window() int
    Quirks() Quirks             // v0.5：厂商差异写成数据
}

// engine/tools/tool.go
type Tool interface {
    Name() string
    Risk() authz.Risk           // L0..L3
    Schema() json.RawMessage    // 参数 JSON Schema
    Call(ctx context.Context, req Call) (Result, error)
}

// internal/platform —— 原 harness/host 的 Deps，现为内部接口
type Authenticator interface { FromRequest(r *http.Request) (authz.Principal, error) }
type SecretStore   interface { Get(ctx context.Context, name string) (string, error); Put(ctx context.Context, name, value string) error }
```

## 3. 前端结构要点

前端目录和规则以设计规范 18 号为准，这里只列和后端相关的约定：

| 目录 | 规则 |
|---|---|
| `web/src/routes/` | react-router 路由：`/`、`/c/:sessionId`、`/c/:sessionId/canvas/:graphId`、`/settings` |
| `web/src/canvas/` | 命令式渲染层（由旗舰 demo 的 `src/` 迁移）；`canvas/core/` 不 import React |
| `web/src/state/` | zustand：graph / view / ui / run / session / model 等 store；用 `createStore()` 工厂函数，每个画布实例（卡片或展开态）各有一份 |
| `web/src/lib/protocol/` | `generated/`（schema 生成）、`client.ts`（REST）、`events.ts`（SSE + 续传）、`mapping.ts`（snake_case ↔ camelCase） |
| `web/src/lib/runBridge.ts` | 高频运行事件按 rAF 合并后直接写画布（09 号 §5） |
| `web/public/fonts/` | 自托管字体（子集化后的 Geist、Geist Mono、Noto Sans SC） |

## 4. 代码生成流水线

```
schema/*.schema.json
   ├─► Go:  omissis/go-jsonschema         →  gen/*.go（含事件名常量 gen.EvNodeState …）
   └─► TS:  json-schema-to-typescript      →  web/src/lib/protocol/generated/*.ts（含事件名联合类型）
设计规范_v0.3/tokens.css ──► web/src/styles/tokens.css（原样复制，不做作用域化）
```

| 选项 | 结论 |
|---|---|
| Go 生成器 | **omissis/go-jsonschema**。M0-03 做 PoC；若对 `oneOf` / 判别联合支持不足，Op 和 RunEvent 的 payload 改为手写 Go 接口 + 生成的 payload 结构，并用测试锁定行为 |
| TS 生成器 | **json-schema-to-typescript**；判别联合生成为 union type |
| 运行时校验 | Go：`santhosh-tekuri/jsonschema/v6` 对入站 JSON 做 schema 校验；TS：`ajv` 预编译 standalone 校验函数（仅开发态） |
| 一致性保障 | CI 跑 `make gen && git diff --exit-code`，生成物不一致即失败 |

### Makefile（每个目标都只是 `go run` / `pnpm` 的薄包装，Windows 可直接调用底层命令）

```makefile
gen:        ## 从 schema 生成 Go / TS，复制 tokens.css
	go run ./tools/gen

dev:        ## 后端（代理到 Vite）+ 前端 dev server
	go run ./cmd/harnessd --dev & pnpm -C web dev

build:      ## 前端构建 → embed → 单二进制
	pnpm -C web build
	go build -trimpath -ldflags "-s -w -X main.version=$(VERSION)" -o dist/harnessd ./cmd/harnessd

release:    ## 6 个平台交叉编译
	go run ./tools/release

test:
	go test ./... -count=1
	pnpm -C web test

lint:
	golangci-lint run ./...
	go run ./tools/depcheck
	pnpm -C web lint
```

## 5. 依赖库选型

## 6. CI

```yaml
jobs:
  go:
    strategy: { matrix: { os: [ubuntu-latest, windows-latest, macos-latest] } }
    steps:
      - run: go run ./tools/gen && git diff --exit-code
      - run: go run ./tools/depcheck
      - run: golangci-lint run ./...
      - run: go test ./... -count=1 -coverprofile=cover.out      # Linux 上加 -race
  web:
    steps:
      - run: pnpm -C web i --frozen-lockfile
      - run: pnpm -C web lint && pnpm -C web test && pnpm -C web build
  e2e:
    needs: [go, web]
    steps:
      - run: make build
      - run: ./dist/harnessd --data-dir $RUNNER_TEMP/hx --no-browser --fake-llm &
      - run: pnpm -C web exec playwright test
  release:            # 打 tag 时
    steps:
      - run: go run ./tools/release   # 6 个平台的 harnessd，附校验和
```

门禁：生成物一致；依赖方向检查；三平台测试通过；`engine/op`、`engine/schema`、`engine/sched` 覆盖率 ≥ 80%；画布 200 节点基准帧率不退化（M1-19 起）。
