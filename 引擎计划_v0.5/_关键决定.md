# 引擎计划 · 关键决定（所有计划文档必须一致遵守）

> **v0.5 已定（2026-11-22）**：Harness 做成**独立产品**，不再嵌入任何宿主。① 单个可执行文件 `harnessd`，启动后在浏览器打开本地地址；② 前端是自有的 Vite + React 应用，构建产物嵌进二进制；③ 首批模型为 **OpenAI 兼容、Anthropic、Gemini**，适配层基于三家官方 Go SDK；④ 第一阶段本机、单用户。具体见 [15_独立产品方案.md](15_独立产品方案.md)，本文与之冲突时以 15 号为准。参考实现的逐层对照见 [16_参考实现对照.md](16_参考实现对照.md)。

> 这份是写计划用的共享底稿。全部计划文档都以这里为准；需要偏离时，在文档里写明理由。

## 理念（判断一切设计取舍的依据）
- **系统 = 节点库 + 契约层 + 运行时。** 「主脑、智囊团、执行池」这类角色只是用原子节点拼出来的模板，不是系统的固定部分。
- **积木拼完还是积木。** 任何子图对外都只暴露端口、参数、摘要端口、升级端口、权限需求、预算需求，可以无限组合和嵌套。
- **节点内部可以聪明，节点之间必须「笨」。** 通信、权限、连接规则写死，由运行时强制执行。
- **可扩展、高度自定义。** 节点、类型、工具、模型、配方、角色卡都可以注册扩展；13 个原子节点也走同一套注册机制，不享受特权。
- **大模型是一等操作者。** 人和模型用同一套 Op 改图、跑图、看图；一切修改都走 Op，一切都要经过授权，模型不能解除急停。

## 技术栈
- 后端：Go 1.23+，单个二进制，`CGO_ENABLED=0`。
- 前端：Vite + React 19 + TypeScript strict + zustand。画布是自研命令式渲染层，拖拽和缩放绕过 React 渲染（见设计规范 docs/17、18）。对话界面基于 assistant-ui 的 headless 组件。
- 引擎内核 `engine/` 是一个**可被 import 的 Go 库**，不依赖 HTTP，也不依赖 `internal/*`；`internal/api` 提供 HTTP + SSE，`internal/app` 提供会话、对话、设置等产品层，`internal/platform` 提供本地鉴权、密钥、配置等默认实现，由 `cmd/harnessd` 组装。
- 存储：第一阶段 SQLite（modernc.org/sqlite，纯 Go），通过 `store` 接口抽象；Postgres 实现放在 M5。表名统一 `hx_` 前缀。
- 所有 ID 用 ULID；时间一律 UTC，展示时转本地时区。

## 核心模型
- **图文档（Graph Doc）**：JSON，由 JSON Schema（`schema/graph.schema.json`）定义，前后端共用。TS 类型和 Go 结构体都从 schema 生成，不手写。
- **Op**：唯一修改入口。字段 `{id, kind, actor, mandate_id, reason, target, payload, base_version, taint, ts}`，每种 Op 都有 inverse。流水线：校验 → 授权 → 图检查 → 应用 → 写事件 → 广播。
- **操作者（actor.kind）**：`user | model | runtime | external` 四种，图文档、Op、事件统一使用（v0.4 里图文档写的 `system` 已改为 `runtime`）。
- **运行（Run）**：每次运行把当时的图冻结成一份快照（`graph_version`）。运行中改图在**安全点**生效；安全点 = 作用域边界（循环的下一轮开始、事件循环的下一个事件、扇出的下一份开始）。
- **运行状态**：`pending → running → (paused) → done | failed | cancelled`，以 14 号事件目录为准。
- **事件溯源**：运行状态的唯一来源是追加写入的事件日志 `run_events`，节点状态、时间线、留痕都从它投影出来。断点续跑 = 重放事件 + 从最近检查点恢复。运行入口和每一次外部响应（审批结果、人工输入、外部回调）到达时，都**先落事件再处理**，保证带人工环节的运行也能从输入完整回放。
- **节点执行器接口**：以 03 号 §4 为准（`Run(rc RunCtx, in Inputs) (Outputs, error)`；`RunCtx` 提供 `Emit(port, v)`、`Subgraph`、`LLM(ref)`、`Tool(id)`、`Ask`、`Checkpoint` 等）。13 个原子节点各有一个内置执行器；扩展节点分两档：**声明式**（YAML 写的 prompt / http / mcp / 子图节点，由内置执行器解释）和**编程式**（Go 实现 `Executor`）。
- **节点状态机**：idle → queued → running → (done | failed | waiting | cancelled | skipped | cached)，waiting → running。
- **调度**：数据流驱动。节点所有必填输入就绪就进入就绪队列；全局有并发上限，每个资源池（模型、工具）有独立配额，用令牌桶限流，超出排队（背压）。
- **有副作用的工具**（L1 以上）必须带幂等键 `run_id/node_path/attempt_key`；调用前先落「意图」事件。

## 通信
- 前端 → 后端：REST（JSON），前缀 `/api/v1`。Op 用 `POST /graphs/{id}/ops`，带 `base_version`，版本冲突返回 409 和最新版本，前端走合并或转成草稿。
- 后端 → 前端：**SSE**。运行事件 `GET /runs/{id}/events?since=seq`；图协同广播 `/graphs/{id}/stream`；会话消息 `/sessions/{id}/stream`。选 SSE 的理由：单向推送足够，自动重连，`Last-Event-ID` 天然支持断线续传。
- 事件信封：`{seq, run_id, ts, kind, path, actor, data}`，`path` 是层级路径 ID，例如 `根图/闭环迭代#r2/执行池/执行者#3`。

## 模型与工具
- 模型适配层 `llm/`：统一接口 `Complete(ctx, Req) (Stream, error)`，屏蔽各厂商差异；**厂商差异写成数据**（quirks 表：是否支持原生 JSON schema、思考内容是否要回传、缓存 token 字段名等），不散落在代码分支里。结构化输出的优先级：原生 JSON schema > 工具调用 > 文本解析加修复。首批 3 家：OpenAI 兼容（`openai-go`）、Anthropic（`anthropic-sdk-go`）、Gemini（`google.golang.org/genai`）；国内厂商和本地模型走 OpenAI 兼容。
- 工具层 `tools/`：内置检索、HTTP、文件、代码执行（wazero 进程内沙箱），以及 **MCP 客户端**（官方 `modelcontextprotocol/go-sdk`，stdio + Streamable HTTP）。内置工具、MCP 工具、SKILL.md 技能统一注册到同一个工具注册表，带同一套风险等级与授权检查。
- 每个工具注册时声明风险等级 L0–L3。

## 授权
- 五档：0 只读、1 建议、2 部分、3 高度、4 完全。授权书（Mandate）是一种文档，可以按对象（会话、图、子图、节点）挂载，向下继承，子级可以覆盖。
- **两个维度分开**：授权档位表达「模型能改多少」，工具风险等级表达「工具会碰到什么」，不合并成一个矩阵。
- 每个 Op 和每次工具调用都要调用 `authz.Check(actor, action, target, ctx) Decision`，结果是 allow、ask（需要审批）或 deny。判定内核默认自研（07 号），M3-00 PoC 评估是否换成 Cedar；`Check` 接口不变。
- 污染标记：由外部内容引出的 Op 和工具调用带 `taint=true`；开启时一律转为 ask。
- 急停：服务级的全局开关，以及每次运行各自的开关。模型无权调用急停的解除接口。
- 所有决策都写进审计日志，审计日志带哈希链，可用 `harnessctl audit verify` 校验（差异化能力）。

## 模型自主编排
- 编排者 = 上下文装配 → Agent（output_schema = `GraphPatch`，tools = 图操作工具）→ 子图引用（ref 由端口传入）。对话界面背后的「对话 Agent」就是以会话为上下文运行的编排者（15 号 §4.2）。
- 模型**逐步**用图操作工具改草稿，不一次性吐出整张图；大图先生成骨架，再并行补全各节点参数。
- GraphPatch 就是一组 Op，提交时同样走 Op 流水线和授权检查。1 档时生成提议（`proposal`），不直接生效。
- 运行时由模型生成的图写入事件日志（`orch.expanded`），回放时直接使用记录下来的图，不再调用模型。

## 里程碑
- **M0 地基（2 周）**：schema、代码生成、仓库骨架、存储接口、平台层、单二进制打包、CI、SDK 能力 PoC
- **M1 能跑的最小闭环（3 周）**：图的增删改与 Op、调度器、资源/Agent/上下文装配/工具/分支/汇合 6 个执行器、OpenAI 兼容适配、SSE 事件流、前端画布看到真实运行状态、应用外壳与会话
- **M2 完整节点集（3 周）**：扇出、聚合、循环、账本、人工、子图端口、子图引用；检查点、断点续跑与 fork；Anthropic 和 Gemini；MCP 工具；声明式扩展节点与扩展包
- **M3 授权与安全（2 周）**：授权书、五档、审批流、污染标记、急停、哈希链审计、沙箱
- **M4 模型自主编排（3 周）**：GraphPatch、提议与幽灵节点、运行时展开、运行后优化、评测；对话 Agent 与对话界面；设置页与密钥
- **M5 观测与打磨（2–3 周）**：时间线与时间旅行、成本计量、OpenTelemetry、性能压测、Postgres 适配、安装包与自动更新、首次引导

以上工期按 1–2 名全职开发估算，明细见 13 号。
