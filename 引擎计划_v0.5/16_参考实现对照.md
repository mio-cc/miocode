# 16 · 参考实现对照（v0.5 新增）

> 用途：实现每个模块之前，先看这里列出的开源实现，借它们的**设计**，避开它们踩过的坑。
> 原则：
> - **只借设计、不复制代码**，也不引入这些项目作为依赖（真正引入的依赖见 01 号 §5）。因此这里**不按许可证筛选**，只看与本产品理念的契合度。
> - 判断标准是理念契合：原子节点 + 自由连线 + 子图即积木；节点、类型、工具、模型可注册扩展；图由文档驱动、运行中可改；模型通过 Op 改图；状态来自事件。
> - 标「已核实」的文件路径来自仓库或官方文档；标「待核」的由 M0-14 打开仓库确认后改为已核实。
> - 依据：`sj/技术选型调研_v0.5.md` 第 7 节（含全部来源链接）。

## 1. 总体契合度

| 项目 | 语言 | 借鉴到哪一层 | 最值得借的设计 | 不契合、不要照搬的地方 |
|---|---|---|---|---|
| **Rivet**（Ironclad） | TS | 图引擎、子图、循环、可嵌入内核 | 图是数据文件，由一个可嵌入的核心库执行；循环控制节点是唯一允许成环的节点 | 不是事件溯源；没有模型改图、没有授权 |
| **ComfyUI** | Python | 节点契约、扩展包、运行时展开、执行缓存 | V3 `define_schema`；扩展包 = 一组节点；Node Expansion（节点在运行时把自己替换成一张子图） | 只有 DAG；模型不是操作者；没有授权和事件日志 |
| **Microsoft Agent Framework Workflows** | C# / Python | 调度、检查点、人工环节可回放 | 类型化 executor + 边组；超步边界检查点；入口检查点与响应入口检查点 | 图由代码构建，不是文档驱动 |
| **LangGraph** | Python / TS | 调度模型、通道、时间旅行 | Pregel / BSP 超步 + channels 做节点间状态同步 | 存快照不存事件；interrupt 恢复后整个节点重跑 |
| **OpenHands** | Python | 事件溯源、上下文压缩 | 不可变、类型安全的事件驱动执行；上下文压缩结果也写成一条事件 | 单 agent 循环，没有图 |
| **Eino compose** | Go | Go 写法的执行器、中断与续跑 | 恢复前可修改 State；并行工具被取消后，只重跑被取消的那几个调用 | 图在编译期固定；检查点只在中断路径写 |
| **n8n** | TS | 节点 SDK、凭据体系 | 声明式与编程式两种节点写法，内置节点和自定义节点走同一个接口 | 模型不是操作者 |
| **Dify** | Python / TS | 引擎事件分层、模型生成图 | 「模型一次生成整张图太慢」后改为逐节点并行生成 | 平台型，引擎与应用层耦合（有专门的重构议题） |
| **LlamaIndex Workflows** | Python / TS | 事件路由 | 步骤收发类型化事件，按事件类型触发下一步 | 没有可视化图和节点库 |
| **Burr** | Python | 调试体验 | 回到任意时刻并从那一点 fork 出新运行 | 状态机，不是数据流图 |
| **Goose**（Block） | Rust | 工具层 | 主循环很薄，能力全部挂在 MCP 扩展总线上 | 没有图 |
| **Codex CLI** | Rust | 授权与沙箱 | 「沙箱：能碰什么」与「审批策略：什么时候必须问人」两个维度分开 | 没有图和对象级多档授权 |
| **Flyde** | TS | 嵌入代码的可视化流 | 把现有函数包成节点，从任意代码里运行一个流 | 不面向 LLM |

## 2. 图运行时内核

### 2.1 借 Rivet 的「形」

- 精读：`packages/core/src/model/GraphProcessor.ts`（**已核实**，https://github.com/Ironclad/rivet/blob/main/packages/core/src/model/GraphProcessor.ts）。这是「图文档 → 就绪判定 → 执行 → 事件」的完整实现，可以逐段对照 03 号 §3 的调度器。
- 循环规则：Rivet 的循环控制节点是唯一允许包含环的节点，所有在循环里变化的值都必须流经它。与我们的 V09（环只能经循环节点形成）一致，说明这条约束在真实产品里可行。
- 子图节点：在当前图里执行另一张图。对应我们的子图引用（`ref`）。Rivet 没有「内联子图 `children`」，我们两种都要。
- **不要照搬**：Rivet 的运行状态在内存里，进程退出就没了；我们以事件日志为唯一来源（04 号）。

### 2.2 借 ComfyUI 的执行管线与运行时展开

- 精读：`comfy_execution/`（约 2000 行，8 个文件，**待核**具体文件名）与顶层 `execution.py`（`PromptExecutor`，**待核**）。管线是「JSON 工作流 → 执行节点 → 依赖管理 → 缓存中间结果 → 子图展开」。
- **Node Expansion**：节点可以返回一张新子图替换自己，ComfyUI 的自定义循环就靠它实现（https://docs.comfy.org/custom-nodes/backend/expansion）。对应我们 M4-08「运行时由模型展开子图」——机制相同，区别是我们的子图由模型产出、要过授权、写进 `orch.expanded` 事件，回放时读事件不再调用模型。
- 执行缓存：按输入签名缓存节点结果。对应我们执行器的 `Cacheable.CacheKey`（03 号 §4），缓存键里要加入 NodeDef 内容哈希和注册表快照哈希（02 号 §3.2）。

### 2.3 借 MAF Workflows / LangGraph 的调度语义

两者都是 Pregel 式超步：一轮里所有就绪节点并行执行，轮与轮之间同步并做检查点。

**我们不改成超步制**，继续用「节点就绪即派发」的数据流调度（吞吐更高、更符合 ComfyUI 用户的直觉），但借用超步的两个好处：

1. **安全点 = 作用域边界**：循环一轮结束、事件循环处理完一个事件、扇出完成一份。运行中改图只在这些点生效（03 号 §8 已按此改写）。
2. **入口检查点与响应入口检查点**：MAF 1.13 起，运行入口先记录初始输入，每个外部响应（人工审批、回调）在被处理前先记录下来，因此带人工环节的运行能从输入完整回放。我们照做：`run.created` 带完整输入快照；`approval.resolved` 等外部响应事件在调度器处理前落库（M1-07、M2-06、M2-08）。

## 3. 扩展机制（D7）

### 3.1 NodeDef 是唯一契约（借 ComfyUI V3）

ComfyUI V3 把节点的全部元数据集中到一个 `define_schema` 类方法里，返回 `io.Schema` 对象。我们的 NodeDef（02 号 §3）就是这个东西的数据版本。

ComfyUI 踩过的坑（`comfy_api/latest/_io.py`，**已核实**，Issue #16132）：Schema 缓存放在普通类属性上，子类会继承到已填充的缓存。**我们的 NodeDef 必须是不可变值**，注册表冻结快照时整体哈希，运行时只读快照。

### 3.2 扩展包（借 ComfyUI 的两层结构）

扩展包 = 一组节点 + 类型 + 配方 + 角色卡 + 执行器，`name@version`。清单示例：

```yaml
# extensions/pricing-pack/package.yaml
name: pricing-pack
version: 1.2.0
requires: { harness: ">=0.5" }
nodedefs:  [nodedefs/价格标准化.yaml, nodedefs/汇率换算.yaml]
types:     [types/报价@1.yaml]          # 新类型必须 extends 核心类型
recipes:   [recipes/定价调研员.yaml]
rolecards: [rolecards/定价分析师.yaml]
executors: []                            # 只用声明式节点时为空；编程式节点见 §3.3
```

### 3.3 两档写法（借 n8n）

n8n 支持声明式和编程式两种节点写法，新节点默认用声明式，内置节点和自定义节点用同一个接口。我们也分两档：

| 档 | 写法 | 适用 | 执行 |
|---|---|---|---|
| 声明式 | 一份 YAML：`impl.type` 为 `prompt` / `http` / `mcp` / `subgraph` | 大多数扩展：包一个提示词、一个 HTTP 接口、一个 MCP 工具、一张子图 | `engine/exec/declarative` 解释执行（M2-18） |
| 编程式 | Go 实现 `exec.Executor`，在扩展包里注册 | 需要新语义（新的控制流、新的聚合算子） | 编译进二进制；第一阶段不支持运行时加载 Go 插件 |

声明式节点示例：

```yaml
name: 价格标准化
version: "1.0"
kind: atomic
category: 扩展
impl:
  type: prompt
  rolecard: 定价分析师@1
  recipe:   定价调研员@1
ports:
  inputs:  { raw: { type: 报价@1, required: true } }
  outputs: { result: { type: 报价@1 } }
params_schema:
  currency: { type: enum, enum: [CNY, USD], default: CNY, widget: true }
```

**13 个原子节点也用同一套 NodeDef 注册**（M1-01），只是 `impl.type: builtin`，执行器内置。

### 3.4 工具层（借 Goose）

Goose 的主循环刻意做薄，真正的设计在 MCP 扩展总线上。我们的工具层同样：内置工具、MCP 工具、SKILL.md 技能统一注册进 `engine/tools` 的同一个注册表，带同一套风险等级（L0–L3）、同一个 `tools.Invoke` 入口（授权检查、幂等、计量都在这里，M3-04）。
