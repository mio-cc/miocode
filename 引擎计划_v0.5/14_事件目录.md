# 14 · 事件目录（唯一事实来源）

> 引擎和前端之间所有事件的**唯一清单**。03、04、07、09、10、11 号文档里出现的事件名都必须和这里一致，冲突时以本文为准。
> 代码里对应 `schema/run-event.schema.json` 和 `schema/graph-event.schema.json`，由它们生成 Go 常量与 TS 联合类型。**不允许在代码里手写事件名字符串。**

---

## 1. 命名规则

| 规则 | 说明 | 例子 |
|---|---|---|
| R1 格式 | `对象.动作`，全小写，下划线分词，动作用过去式或名词 | `tool.call`、`approval.resolved` |
| R2 **状态变化只有一个事件** | 凡是有状态机的对象，状态变化统一用 `<对象>.state` / `<对象>.status`，data 里写 `from`、`to`、`cause`。不为每个状态单独建事件 | `node.state {from:"queued", to:"running"}` |
| R3 成对事件用 `requested / resolved` | 需要等待结果的事件一律成对 | `approval.requested` → `approval.resolved` |
| R4 不和 Op 名、授权动作名混用 | `op.add_node` 是**授权动作**（见 07），不是事件；图上的修改统一用事件 `op.applied` | — |
| R5 不和图节点类型混用 | 分支节点的判定结果不单独建事件，放在 `node.state` 终态的 `active_outs` 里；`branch.*` 只指**草稿分支** | — |
| R6 日志消息不是事件 | slog 的 msg 可以沿用事件名风格，但不进入事件流 | — |

## 2. 事件信封

```json
{ "seq": 812, "run_id": "01JD…", "ts": "2026-11-21T09:12:03.120Z",
  "kind": "node.state", "path": "根图/闭环迭代#r2/执行池/执行者#3",
  "actor": {"kind": "runtime"}, "data": { … } }
```

- `seq`：每个运行内单调递增，也就是 SSE 的 `id`，断线后从 `Last-Event-ID` 续传。
- `path`：层级路径 ID，规则见 11 号文档 §1。
- `actor`：`user | model | runtime | external`，模型操作时还带 `instance_id`。
- 持久化级别：**P** = 落库，可以补发；**S** = 采样落库；**E** = 只广播，不落库、不补发。

## 3. 运行事件流（`GET /runs/{id}/events`）

### 3.1 运行级

| kind | 级别 | data | 产生方 | 主要消费方 |
|---|---|---|---|---|
| `run.created` | P | `snapshot_ref, graph_version, registry_hash, budget` | run | 时间线起点 |
| `run.status` | P | `from, to, cause, by?, at_safepoint?, cost?` — to ∈ `pending, running, paused, done, failed, cancelled` | sched | 顶部状态、规则引擎（`to` 为终态时回收"仅本次"授权） |
| `run.graph_swapped` | P | `from_version, to_version, op_ids, at_round?, scope_path, source: user\|model` | sched（安全点） | 时间线标记、画布刷新 |

### 3.2 节点级

| kind | 级别 | data | 说明 |
|---|---|---|---|
| `node.state` | P | `from, to, attempt, cause` + 按 `to` 附加字段（见下） | **唯一的节点状态事件** |
| `node.progress` | S（每节点 ≤ 4/s） | `pct?, note?, sub?` | 进度条、"第 2/5 轮" |
| `node.chunk` | E | `port, delta` | 流式输出 |
| `node.input` | P | `port, value_ref` | 节点详情 |
| `node.output` | P | `port, value_ref, partial` | 节点详情、下游就绪判定 |
| `node.throttled` | S | `pool, waiting` | 背压、甘特图排队段 |
| `node.log` | P（≥ info） | `level, msg, kv` | 日志 Tab |

`node.state` 的 `to` 取值和附加字段：

| to | 附加字段 |
|---|---|
| `queued` | `cause`：`ready \| retry \| resume`；`retry` 时带 `error, idem_key, backoff_ms` |
| `running` | `inputs_ref` |
| `waiting` | `approval_id, reason` |
| `done` | `outputs_ref, active_outs?`（分支、人工节点被激活的出口）`, cost` |
| `cached` | `outputs_ref, cache_key` |
| `failed` | `error: {class, message, retryable}` |
| `cancelled` | `cause`：`user \| emergency_stop \| k_of_n_satisfied \| timeout \| budget` |
| `skipped` | `cause`：`inactive_edge \| upstream_skipped` |

### 3.3 控制流

| kind | 级别 | data |
|---|---|---|
| `loop.round` | P | `round, max, exit?, carry_ref` |
| `checkpoint.saved` | P | `scope_path, round?, ref` |
| `ledger.changed` | P | `store, path, version, by` |

### 3.4 模型、工具、上下文

| kind | 级别 | data |
|---|---|---|
| `llm.call` | P | `pool, provider, model, usage{in,out,cached}, cost_micros, latency_ms, req_ref, resp_ref, strategy` |
| `llm.fallback` | P | `from_strategy, to_strategy, reason` |
| `tool.call` | P | `tool, risk, idem_key, queued_ms, req_ref, result_ref, taint, status` |
| `ctx.assembled` | P | `sections[{name, tokens, source}], dropped[], budget_tokens` |
| `prompt.rendered` | P | `segments[{name, tokens, cache_break}], ref` |

### 3.5 编排者（模型自主编排）

| kind | 级别 | data |
|---|---|---|
| `orch.started` | P | `orch_path, mode: design\|runtime\|post_run` |
| `orch.tool_call` | E | `tool, target_node?, ok` — 驱动 AI 光标 |
| `orch.expanded` | P | `patch_id, patch, subgraph_ref（完整子图）, graph_version_before, after` — **回放时据此复现，不再调用模型** |
| `orch.finished` | P | `result: patch\|proposal\|none, stats` |

### 3.6 授权、审批、升级、预算

| kind | 级别 | data |
|---|---|---|
| `approval.requested` | P | `approval_id, kind（approval\|elevation\|taint\|budget\|human_node）, summary, detail_ref, options` |
| `approval.resolved` | P | `approval_id, outcome: approved\|rejected\|expired\|cancelled, scope: once\|forever, by, note?` |
| `escalation.raised` | P | `escalation_id, kind, severity, question, options, merge_key` |
| `escalation.merged` | P | `escalation_id, into, count` |
| `escalation.routed` | P | `escalation_id, to_path` |
| `escalation.resolved` | P | `escalation_id, by, outcome` |
| `budget.charged` | P | `tokens, cost_micros, scope_path` |
| `budget.warn` | P | `scope_path, ratio: 0.5\|0.8\|1.0` |
| `budget.exceeded` | P | `scope_path` |
| `estop.triggered` | P | `scope: global\|run, by` |
| `estop.released` | P | `scope, by`（只有 `actor.kind=user` 能触发） |
| `brief.updated` | P | `goal_id（merge_key）, status, conclusion, criteria_check, cost, superseded` |

### 3.7 只广播

| kind | 频率 | data |
|---|---|---|
| `edge.flow` | 每次数据通过 | `edge_id` — 画布上的光点动画 |
| `pool.usage` | 1/s | `pools[{name, used, cap, queued}]` |
| `engine.illegal_transition` | 偶发，P | `path, from, to` — 告警用 |

## 6. 前端消费分工（对应设计规范 docs/17、18）

| 事件 | 前端去向 |
|---|---|
| `node.state`、`node.progress`、`edge.flow`、`node.throttled`、`pool.usage` | **高频**：runBridge 在 rAF 里合并后直接写画布，不进 React |
| `run.status`、`approval.*`、`escalation.*`、`brief.updated`、`estop.*`、`budget.warn` | **低频**：进 zustand store，驱动顶部条、审批卡片、通知 |
| `node.log`、`llm.call`、`tool.call`、`ctx.assembled`、`prompt.rendered` | 写入运行抽屉和节点详情，按需懒加载 ref |
| `op.applied`、`proposal.*`、`model.activity` | 图 store；`model.activity` 驱动 AI 光标 |
