# 15 · 独立产品方案（v0.5 已定）

> 2026-11-22 定：Harness「积木编排」**不再嵌入任何宿主**，做成独立产品。本文替代 v0.4.1 的《15_嵌入集成方案》（存档在 `引擎计划_v0.4/`）。
> 本文与 00–14、16 号文档冲突时，**以本文为准**；受影响的文档已同步修改，改动清单见 `_变更记录.md`。
> 选型依据：`sj/技术选型调研_v0.5.md`（下称《调研》）。参考实现的逐层对照见 16 号。

| # | 决定 | v0.4.1 | v0.5 |
|---|---|---|---|
| D1 | 形态 | 引擎嵌入现有 Go 服务 | **独立进程 `harnessd`**，单个可执行文件，启动后在浏览器打开本地地址 |
| D2 | 前端 | 嵌入现有 Next.js 应用的 `/canvas` | **自有 Web 应用**：Vite + React + TS，构建产物用 `go:embed` 打进二进制 |
| D3 | 首批模型 | OpenAI 兼容、Anthropic、Gemini | 不变；适配层基于三家**官方 Go SDK** |
| D4 | 用户与部署 | 跟随宿主 | **第一阶段本机、单用户**；多用户和 Postgres 放到 M5 之后 |
| D5 | 主界面 | 宿主的对话页 | **对话为主，画布以卡片嵌在对话里**，可展开、可全屏（与设计规范 11 号一致，不改 UX） |
| D6 | 内核策略 | — | **图引擎、事件日志、Op、授权编排自研**；模型 SDK、MCP、沙箱、策略判定、评测用现成组件（《调研》第 3–6 节） |
| D7 | 扩展理念 | — | 13 个原子节点和扩展节点走**同一套 NodeDef 注册**，不搞特权；扩展分声明式（YAML）和编程式（Go Executor）两档（16 号 §3） |

> 以下几项是在没有用户逐条拍板的情况下按《调研》推荐先定的，**可以推翻**，推翻时只需改本文和 13 号：Vite 替代 Next.js、单二进制 + 浏览器（Wails 桌面壳放 M5 可选）、Cedar 作为授权判定内核的候选（M3 前 PoC 决定）、系统 keychain 存密钥。

## 1. 为什么独立以后内核不用改

v0.4 的引擎本来就是一个不依赖宿主的库（`engine/` 不 import HTTP、不 import 宿主），宿主只通过 `host.Deps` 注入鉴权、密钥、日志、数据库。独立以后：

- `engine/` **原样保留，并且继续是可被 import 的公开包**。以后真要把引擎嵌进别的系统，路还在。
- 原来由宿主提供的东西，改成 harness 自带的默认实现，放在 `internal/platform/`（见 §3）。
- 原来宿主负责的产品层能力（会话、对话界面、设置页、首次引导、打包分发）变成 harness 自己的新增范围（见 §4、§5）。

一句话：**内核不动，外壳自建。**

## 2. 仓库结构（单仓库）

```
harness/                              # 一个 Go module + 一个前端工程
├─ cmd/
│  ├─ harnessd/main.go               # 唯一服务入口：读配置 → platform 默认实现 → 组装 engine/api → 起服务 → 打开浏览器
│  └─ harnessctl/                    # CLI：audit verify、estop、eval compare、export/import、doctor
├─ schema/                           # ★ 唯一事实来源（JSON Schema 2020-12），见 02、14
│  └─ builtin/ nodedefs/*.yaml  types/*.yaml  recipes/*.yaml  rolecards/*.yaml
├─ gen/                              # schema 生成的 Go 类型（不手改）
├─ engine/                           # 内核库：不依赖 net/http（llm、tools/builtin/http、mcp 例外），不依赖 internal/*
│  ├─ graph/ schema/ op/ authz/ run/ sched/ exec/… ctxasm/ llm/ tools/ mcp/ orch/ store/ blob/ obs/ ext/
├─ internal/
│  ├─ api/                           # HTTP 路由、幂等、错误码（net/http 1.22 ServeMux）
│  ├─ sse/                           # 两条 SSE 流：hub、续传、心跳
│  ├─ app/                           # ★ 独立产品新增的产品层
│  │  ├─ session/                    #   会话与消息（会话里挂图、消息里嵌画布卡片）
│  │  ├─ chat/                       #   对话 Agent：把用户的话交给编排者（10 号），把回复与卡片写回会话
│  │  ├─ settings/                   #   模型提供方、默认模型、价格表、资源池配额、外观
│  │  └─ onboarding/                 #   首次启动引导
│  └─ platform/                      # ★ 原 harness/host 的 Deps，改为内部接口 + 本地默认实现
│     ├─ auth/                       #   本机 token / cookie
│     ├─ secret/                     #   系统 keychain，回退到加密文件
│     ├─ config/                     #   harness.yaml 读写与热更新
│     └─ lock/                       #   单实例锁、端口选择
├─ web/                              # Vite + React + TS（目录见设计规范 18 号 §2）
├─ templates/                        # 内置模板包：闭环迭代、生成-评审、代码评审
├─ evals/                            # 评测集（12 号 §6）
└─ tools/                            # depcheck、gen 脚本（全部用 go run，Windows 可直接跑）
```

依赖方向（CI 的 depcheck 强制）：

```
cmd/harnessd ──► internal/{api,sse,app,platform} ──► engine/** ──► gen
                                   internal/app ──► engine/orch（对话 Agent 通过编排者改图）
engine/** ✗ internal/**      engine/** ✗ net/http（llm、tools/builtin/http、mcp 例外）
internal/api ✗ internal/app 的实现细节（只经 app 暴露的接口）
```

## 3. 平台层：原宿主能力的本地默认实现

| 原 `host.Deps` | v0.5 位置 | 默认实现 | 说明 |
|---|---|---|---|
| `Authenticator` | `internal/platform/auth` | 首次启动生成随机 token 写入 `DataDir/token`；浏览器打开 `http://127.0.0.1:<port>/?t=<token>` 时换成 HttpOnly cookie；只监听 127.0.0.1 | 单用户阶段主体固定为 `user:local`；`authz.Principal` 结构保留 user_id，多用户时换实现 |
| `SecretStore` | `internal/platform/secret` | Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service；不可用时回退到 `DataDir/secrets.enc`（主密码派生密钥加密） | 密钥只在 `llm` 适配器发请求时取出，不进事件、不进日志（05 号 §7） |
| `Logger` | `internal/platform` | `log/slog` JSON handler，写 `DataDir/logs/`，按天滚动；脱敏 handler（M0-09） | — |
| `Metrics` | `internal/api` 挂 `/metrics` | Prometheus registry，默认只在本机可访问 | 指标前缀 `hx_` 保留 |
| `DB` | `engine/store/sqlite` | `DataDir/harness.db`，modernc.org/sqlite，WAL | 表名 `hx_` 前缀**保留**，方便以后换库或被嵌入；Postgres 实现推迟到 M5-06 |
| 配置 | `internal/platform/config` | `DataDir/harness.yaml`（原「宿主配置中的 `harness:` 段」整体搬过来） | 设置页改的就是这个文件；改动热加载，资源池配额等在下一次运行生效 |

`DataDir` 默认：Windows `%APPDATA%\Harness`，macOS `~/Library/Application Support/Harness`，Linux `~/.local/share/harness`；可用 `--data-dir` 覆盖。

**v0.4 的嵌入问题清单（写超时、gzip、请求日志、全局超时）不再需要处理**，因为中间件都是我们自己的：SSE 路由天然不压缩、不设写超时、不记 body。保留的只有「每 15 秒发一次 `: ping` 注释帧」。

## 4. 产品层新增

### 4.1 会话与消息（`internal/app/session`，M1-21）

| 概念 | 说明 |
|---|---|
| 会话 `Session` | 左侧栏的一项；有标题、创建时间、最近活动时间；可重命名、删除、置顶 |
| 消息 `Message` | `role: user \| assistant \| system`；正文是 Markdown；可以带附件块 |
| 画布卡片块 | 消息里的一种附件块 `{kind:"canvas", graph_id, run_id?, version}`，前端渲染为 `CanvasCard`（设计规范 11 号 §11.2.1） |
| 会话与图 | 一个会话可以有多张图；图仍是独立文档（`graph_id`），会话只保存引用 |

表：`hx_sessions`、`hx_messages`（`hx_messages.blocks` 为 JSON）。接口和事件见 09 号 §2.9、§3.4（v0.5 新增 `session.*` 事件，已登记 14 号）。

**M1 到 M3 之间没有对话 Agent**：用户在会话里点「新建画布」或拖入模板，系统插入一条带画布卡片的 system 消息；打开卡片就是完整编辑器。这保证 M1 的演示脚本不依赖 M4。

### 4.2 对话 Agent（`internal/app/chat`，M4-15）

对话 Agent 不是新的引擎概念：它就是 10 号文档里的**编排者**，以会话为上下文运行。

```
用户消息 ──► chat.Handle(session, msg, selection)
               │  上下文：最近 N 条消息摘要 + 当前打开的图（read_graph 精简视图）+ 选中节点
               ▼
           orch.Run(mode=design|runtime|post_run, mandate=会话挂载的授权书)
               │  通过图操作工具改草稿 → GraphPatch → Op 流水线（授权、提议/直接生效）
               ▼
           写回会话：assistant 消息（文字 + 画布卡片块 + 提议摘要）
```

- 授权：会话本身是一个挂载点（07 号 §2.3 的 Target 层级最上层加一级 `session`），默认 1 档。
- 不改图的问题（「这个节点是干什么的」）走同一个 Agent，只是不产生 GraphPatch。
- 前端用 assistant-ui 的 headless 组件做消息流和输入框，主题变量由 `tokens.css` 提供，不引入 Tailwind 的颜色体系（设计规范 18 号 §10）。

### 4.3 设置（`internal/app/settings`，M4-16）

| 分组 | 内容 |
|---|---|
| 模型提供方 | 增删 provider（OpenAI 兼容 / Anthropic / Gemini）；base_url；密钥（写入 SecretStore，界面只显示末 4 位）；「测试连接」 |
| 默认模型 | 编排者默认模型、Agent 节点默认模型、摘要器默认模型 |
| 价格表 | 05 号 §6 的 pricing 表，可编辑，带生效日期（成本按版本结算） |
| 资源池 | 全局并发、每个 provider+model 的并发和速率 |
| 工具与 MCP | 内置工具开关、域名白名单、MCP 服务器列表（stdio 命令 / Streamable HTTP 地址） |
| 外观 | 主题（浅色默认 / 深色 / 跟随系统）、界面缩放 |
| 数据 | DataDir 位置、保留期（Q8）、导出 / 导入、清理工作区 blob |

### 4.4 首次启动（`internal/app/onboarding`，M5-12）

第一次运行：生成 token → 打开浏览器 → 引导页三步：选择语言与主题 → 配置至少一个模型提供方（可跳过，跳过时只能用 Fake 模型演示）→ 从模板创建第一张图。

## 5. 前端：自有 Web 应用

| 项 | 方案 |
|---|---|
| 框架 | Vite + React 19 + TypeScript strict；路由 react-router（`/`、`/c/:sessionId`、`/c/:sessionId/canvas/:graphId`、`/settings`） |
| 没有 SSR | 整个应用是客户端渲染；v0.4 里所有 `'use client'`、`next/dynamic({ssr:false})`、BFF 透传的约束一并取消 |
| 令牌 | `tokens.css` 直接作用在 `:root`（不再需要 `tokens.scoped.css` 作用域化）；构建时从设计规范目录复制 |
| 字体 | **自托管**：Geist、Geist Mono、Noto Sans SC（按常用字子集化）放在 `web/public/fonts/`，`@font-face` + `font-display: swap`；完全离线可用（Q10 因此关闭） |
| 主题 | `<html data-theme>`；首屏前用内联脚本从 localStorage 读，防闪色；默认浅色 |
| 画布 | 旗舰 demo 的命令式内核迁移成 `web/src/canvas/core/`，React 只做外壳（M1-19，验收不变） |
| 对话 UI | assistant-ui headless 组件 + 自己的样式；画布卡片嵌在 assistant 消息里 |
| 请求 | 同源：REST `/api/v1/...`，SSE `/api/v1/runs/{id}/events`、`/api/v1/graphs/{id}/stream`、`/api/v1/sessions/{id}/stream`；cookie 鉴权；EventSource 直连 |
| 开发 | `make dev`：`harnessd --dev`（不 embed，代理到 Vite dev server）+ `vite`；生产 `make build` 先构建 web 再 `go build` |

URL 前缀从 v0.4 的 `/api/harness/v1` 改为 `/api/v1`（不再需要和宿主路由区分）。

## 6. 分发

| 阶段 | 形态 | 任务 |
|---|---|---|
| M0 起 | `harnessd` 单二进制（Windows/macOS/Linux × amd64/arm64），`CGO_ENABLED=0` 交叉编译；双击或命令行启动，自动打开浏览器 | M0-12 |
