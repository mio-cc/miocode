# 05 模型与工具适配

> 对应包：`engine/llm`（统一接口）、`engine/llm/openai`、`engine/llm/anthropic`、`engine/llm/structured`、`engine/tools`、`engine/tools/builtin/*`、`engine/mcp`。
> 原则：执行器只认统一接口，厂商差异全部在适配层消化；每一次调用都经过 **资源池 → 授权 → 计量 → 留痕** 四层包装。

## 1. llm 包接口

```go
package llm

type Role string
const (RoleSystem Role = "system"; RoleUser = "user"; RoleAssistant = "assistant"; RoleTool = "tool")

type Part struct {               // 多模态片段
    Type     string `json:"type"`           // text / image / file
    Text     string `json:"text,omitempty"`
    Ref      string `json:"ref,omitempty"`  // ws:// 指针，图片、文件
    MimeType string `json:"mime,omitempty"`
}

type Message struct {
    Role       Role       `json:"role"`
    Parts      []Part     `json:"parts"`
    ToolCalls  []ToolCall `json:"tool_calls,omitempty"` // assistant 消息
    ToolCallID string     `json:"tool_call_id,omitempty"` // tool 消息
    Cache      bool       `json:"cache,omitempty"`      // 提示缓存断点（支持的厂商才生效）
}

type ToolSpec struct {
    Name        string          `json:"name"`
    Description string          `json:"description"`
    Schema      json.RawMessage `json:"input_schema"`
}

type ToolCall struct {
    ID   string          `json:"id"`
    Name string          `json:"name"`
    Args json.RawMessage `json:"args"`
}

type OutputSpec struct {
    Schema json.RawMessage // 由 output_schema 生成的 JSON Schema；nil 表示自由文本
    Name   string          // 类型名，如 "方案@1"
    Strict bool
}

type Req struct {
    Model       string
    Messages    []Message
    Tools       []ToolSpec
    ToolChoice  string        // auto / none / required / <name>
    Output      *OutputSpec
    Temperature *float32
    TopP        *float32
    Seed        *int64
    MaxTokens   int
    Stop        []string
    Metadata    map[string]string // run_id、path，透传给厂商的 user/metadata 字段
}

type Usage struct {
    InputTokens       int
    CachedInputTokens int
    OutputTokens      int
    ReasoningTokens   int
}

type Resp struct {
    Text       string
    ToolCalls  []ToolCall
    Structured json.RawMessage // 原生结构化输出时直接给
    Finish     string          // stop / length / tool_calls / content_filter
    Usage      Usage
    Model      string          // 厂商实际返回的模型版本
    Raw        json.RawMessage // 原始响应，存 blobs 用于回放
}

type Delta struct {
    Text     string
    ToolCall *ToolCallDelta
    Done     bool
    Resp     *Resp // Done=true 时给出完整响应
}

type Stream interface {
    Next() (Delta, error) // io.EOF 结束
    Close() error
}

type Client interface {
    Complete(ctx context.Context, r Req) (Stream, error)
    Caps() Caps
}

type Caps struct {
    Window           int  // 上下文窗口 tokens
    MaxOutput        int
    NativeSchema     bool // 支持 JSON Schema 约束输出
    Tools            bool
    ParallelTools    bool
    Vision           bool
    PromptCache      bool
    Tokenizer        string // tiktoken:o200k_base / anthropic / approx
}

// 便捷：非流式
func Collect(s Stream) (*Resp, error)
```

## 2. Provider 适配

### 2.1 OpenAI 兼容（覆盖 OpenAI、DeepSeek、通义、Moonshot、vLLM、Ollama 等）
- 接口：`POST {base_url}/chat/completions`，`stream: true`，SSE 解析 `data:` 行。
- 结构化输出：`response_format: {type: "json_schema", json_schema: {name, schema, strict: true}}`。很多兼容实现不支持 → 通过 `ModelConfig.caps.native_schema=false` 声明，走第二级或第三级策略（§3）。
- 工具调用：`tools: [{type:"function", function:{name, description, parameters}}]`；流式中 `tool_calls[i].function.arguments` 是**分片字符串**，按 `index` 累积拼接，结束后再 JSON 解析。
- usage：请求带 `stream_options: {include_usage: true}`，最后一个 chunk 给出 usage；`prompt_tokens_details.cached_tokens` 映射到 `CachedInputTokens`。
- 消息映射：`Part{type:image}` → `image_url`（先从 ws 读出转 data URL）；`RoleTool` → `role:"tool", tool_call_id`。

### 2.2 Anthropic
- 接口：`POST /v1/messages`，`stream: true`，事件类型 `message_start / content_block_start / content_block_delta / content_block_stop / message_delta / message_stop`。
- `system` 是独立字段：统一接口里所有 `RoleSystem` 消息合并后放入 `system`。
- 工具：`tools: [{name, description, input_schema}]`；调用以 `tool_use` 内容块出现，参数流式为 `input_json_delta.partial_json`，累积后解析。工具结果以 `user` 角色的 `tool_result` 块回传。
- 结构化输出：没有通用的 response_format 时，用**强制工具调用**实现——构造一个名为 `emit_<Type>` 的工具，`input_schema` 即输出 schema，`tool_choice: {type: "tool", name: "emit_<Type>"}`，取其 input 作为结构化结果（即第二级策略的原生形态）。
- 提示缓存：`Message.Cache=true` 的消息末块加 `cache_control: {type: "ephemeral"}`；usage 中 `cache_read_input_tokens` 映射到 `CachedInputTokens`。

### 2.3 Gemini（v0.4.1 新增，见 15 号文档）
- 实现：使用官方 Go SDK `google.golang.org/genai`。同一个 SDK 既能接 Gemini API（API key），也能接 Vertex AI（GCP 凭据），由 `ModelConfig.backend: gemini_api | vertex` 切换。
- 接口：`Models.GenerateContentStream`，对应 REST 的 `streamGenerateContent?alt=sse`。
- `system` 放在独立的 `SystemInstruction` 字段。角色只有 `user` 和 `model`：统一接口的 `assistant` 映射为 `model`，工具结果放在 `user` 角色消息的 `FunctionResponse` part 里。
- 工具：`Tools: [{FunctionDeclarations: [...]}]`。调用以 `FunctionCall` part 出现，**参数是一次性给出的完整对象**，不是分片字符串，适配器不需要拼接。要强制调用时，设置 `ToolConfig.FunctionCallingConfig{Mode: ANY, AllowedFunctionNames: [...]}`。
- 结构化输出：`ResponseMIMEType: "application/json"` 加 `ResponseJsonSchema`（或旧版 `ResponseSchema`）。Gemini 只支持 JSON Schema 的一个子集，对 `$ref`、`oneOf`、复杂嵌套的支持有限。适配器先把输出 schema 做一次**降级转换**：内联 `$ref`，把判别联合展开成带 `enum` 判别字段的对象；转换不了时，在 `Caps` 里标记，让这个类型走第二级（强制函数调用）或第三级策略（§3）。
- usage：`UsageMetadata` 里的 `PromptTokenCount`、`CandidatesTokenCount`、`CachedContentTokenCount`、`ThoughtsTokenCount`（思考 token 也要计费，映射到 `Usage.ReasoningTokens`）。
- 缓存：隐式缓存自动生效，读取 `CachedContentTokenCount` 即可。显式缓存（`CachedContents` API）对应提示词前五段的缓存断点，作为 P1 再做。
- 安全过滤：`FinishReason=SAFETY` 等原因映射为 `Finish=filtered`，归入错误分类里的"内容被拦截"，不重试，直接走升级端口。
- 实现前用 Cassette 录制真实响应，契约测试与另外两家共用同一套用例。

## 3. 结构化输出：三级策略与自动修复

```go
package structured

type Strategy int
const (Native Strategy = iota; ForcedTool; TextParse)

func Pick(c llm.Caps) Strategy {
    switch {
    case c.NativeSchema: return Native
    case c.Tools:        return ForcedTool
    default:             return TextParse
    }
}

// Decode：拿到响应后统一走这一步
func Decode(resp *llm.Resp, schema *jsonschema.Schema, rp RepairPolicy) (json.RawMessage, error) {
    raw := pickRaw(resp)                                  // Structured / 强制工具的 args / 文本里的 JSON 块
    if raw == nil { return nil, ErrNoJSON }
    fixed := raw
    if !json.Valid(fixed) {
        fixed = jsonrepair.Repair(raw)                    // 去 ``` 包裹、补括号、去尾逗号、单引号转双引号
    }
    var v any
    if err := json.Unmarshal(fixed, &v); err != nil { return nil, ErrFormatInvalid.Wrap(err) }
    v = coerce(v, schema)                                 // 宽松修正：数字字符串→数字、单值→单元素数组、缺省填默认值
    if errs := schema.Validate(v); len(errs) > 0 {
        return nil, ErrFormatInvalid.WithDetails(errs)    // 交给执行器决定是否"带错误信息重试"
    }
    return json.Marshal(v)
}
```

- 第三级（TextParse）时，适配器在 system 段末尾追加"只输出一个 JSON 对象，符合以下 schema"，并给出 schema 的精简版（去掉 description，保留 required/enum）。
- **带反馈重试**：`ErrFormatInvalid` 时，Agent 执行器把校验错误列表作为一条 user 消息追加（"上一次输出不合格：字段 sources 必填……请只输出修正后的 JSON"），最多 `repair.retry` 次（默认 2）。
- 校验库：`santhosh-tekuri/jsonschema/v6`（支持 2020-12）。JSON 修复：自研小函数，覆盖上述 5 类常见问题即可，不引入大依赖。

## 4. token 计数与窗口换算

- 上下文预算以**比例**表达（如 `0.1×窗口`），装配时换算：`tokens = floor(ratio × Caps.Window) − reserve`，`reserve = MaxOutput 默认值`。
- 计数器接口：
```go
type Counter interface { Count(msgs []llm.Message, tools []llm.ToolSpec) int }
```
- 实现：OpenAI 系列用 `pkoukk/tiktoken-go`（离线 BPE 文件打包进二进制）；Anthropic 和其他模型用**近似计数**：中文按 1 字 ≈ 1.1 token，英文按 4 字符 ≈ 1 token，再乘 1.1 的安全系数。实际 usage 回来后记录"估算/实际"比，按模型滚动校准系数（存 `model_stats`）。
- 工具 schema 也计入：每个工具约 `len(json)/3.5` tokens。

## 5. 限流、重试、退避、熔断

调用链包装（由外到内）：

```
authz.Check(llm.call) → Pool.Acquire（并发 + 令牌桶）→ Breaker → Retry → Provider
                                      ↘ Meter（usage、费用、延迟）→ Trace（存 req/resp 到 blobs，写 llm.call 事件）
```

```go
type RetryCfg struct { Max int; Base, MaxDelay time.Duration }   // 默认 3 / 1s / 30s

func withRetry(ctx context.Context, cfg RetryCfg, f func() (llm.Stream, error)) (llm.Stream, error) {
    for i := 0; ; i++ {
        s, err := f()
        if err == nil || i == cfg.Max || !retryable(err) { return s, err }
        d := backoff(cfg, i)
        if ra, ok := retryAfter(err); ok { d = ra }              // 429 的 Retry-After 优先
        select { case <-time.After(d): case <-ctx.Done(): return nil, ctx.Err() }
    }
}
```

| 错误 | 分类 | 处理 |
|---|---|---|
| 网络、超时、5xx、overloaded | Transient | 退避重试 |
| 429 | RateLimited | 按 Retry-After；同时把对应资源池速率临时下调 20%，5 分钟后恢复 |
| 400 上下文超长 | UserInput | 不重试；交给 ctxasm 收紧预算后由执行器决定重来一次 |
| 401/403 | AuthDenied | 不重试，告警（密钥问题） |
| content_filter | Structural | 升级 |
| 流中途断开 | Transient | 重试整个请求（不续传） |

- **熔断**（`sony/gobreaker`）：每个 provider+model 一个；60s 内错误率 > 50% 且请求 ≥ 20 → 打开 30s；打开期间调用直接失败为 Transient，若模型资源配置了 `fallback` 模型则自动切换并写事件 `llm.fallback`。

## 6. 成本计量

```yaml
# 宿主配置中 harness 段的片段：价格表（每百万 tokens，单位：元）
pricing:
  openai/gpt-x:      {input: 15.0, cached_input: 7.5, output: 60.0}
  anthropic/claude-x: {input: 21.0, cached_input: 2.1, output: 105.0}
  local/*:           {input: 0, output: 0}
```
- 每次调用：`cost_micros = (in−cached)×p.in + cached×p.cached + out×p.out`（按百万换算为整数微元，避免浮点累计误差）。
- 写 `llm.call` 事件和 `budget.charged`；按 `path` 前缀汇总即得到节点、子图、运行级成本。
- 预算检查在调用**前**按估算 tokens 预占，调用**后**按实际 usage 结算；预占超出剩余预算 → `ErrBudgetExceeded`。

## 7. 模型资源与密钥管理

图文档里的模型资源节点**只有引用，没有密钥**：
```yaml
# 资源节点 params
kind: 模型
value: {provider: anthropic, model: claude-x, sampling: {temperature: 0.7}, fallback: openai/gpt-x}
```
服务端配置：
```yaml
# 宿主配置中的 harness 段
providers:
  openai:
    base_url: https://api.openai.com/v1
    api_key: ${OPENAI_API_KEY}              # 环境变量
  anthropic:
    api_key: secret://anthropic/main         # 本地加密密钥库
  deepseek:
    type: openai-compat
    base_url: https://api.deepseek.com/v1
    api_key: ${DEEPSEEK_API_KEY}
    caps: {native_schema: false, window: 64000}
pools:
  anthropic/claude-x: {concurrency: 4, rpm: 50}
  openai/gpt-x:       {concurrency: 8, rpm: 300}
```
- `secret://` 密钥库：本地文件 `$HARNESS_DATA/secrets.enc`，AES-256-GCM 加密，主密钥来自操作系统钥匙串（Windows DPAPI / macOS Keychain，用 `zalando/go-keyring`），无钥匙串时用环境变量 `HARNESS_MASTER_KEY`。
- 密钥只在 provider 客户端内部使用；日志、事件、留痕、错误信息里统一脱敏（`sk-…` 等模式替换为 `***`）。
- 模型无权读取配置或密钥；`read_graph` 等工具返回的图里也不含密钥。

## 8. tools 包

### 8.1 接口与注册
```go
package tools

type Risk uint8
const (L0 Risk = iota; L1; L2; L3)

type Def struct {
    ID          string          // builtin:search / mcp:jira/search_issues / http:<name>
    Name        string          // 给模型看的名字（[a-z0-9_]{1,64}）
    Description string
    Input       json.RawMessage // JSON Schema
    Output      json.RawMessage // 可选
    Risk        Risk            // 注册时声明；实例只能调高
    SideEffect  bool            // L1+ 默认 true
    Idempotent  bool            // 外部 API 本身是否支持幂等键
    Timeout     time.Duration
    Pool        string          // 资源池键，默认 tool:<ID>
}

type Call struct {
    Args     json.RawMessage
    IdemKey  string
    Taint    bool   // 入参是否来自外部内容
    Caller   string // 节点路径
}

type Result struct {
    Summary  string          // ≤ 300 字摘要
    Snippets []Snippet       // 与任务相关的片段
    Data     json.RawMessage // 结构化结果（可选）
    Ref      string          // 原文指针，必有（内核锁定 keep_pointer）
    Taint    bool            // 结果是否含外部内容（检索、HTTP、文件读 → true）
    Bytes    int
}

type Impl interface {
    Def() Def
    Invoke(ctx context.Context, c Call) (Result, error)
}

type Registry interface {
    Register(i Impl) error
    Get(id string) (Impl, bool)
    List(filter Filter) []Def
}
```

### 8.2 调用包装（Handle）
```go
func (h *Handle) Call(rc exec.RunCtx, args json.RawMessage, taint bool) (Result, error) {
    d := h.impl.Def()
    key := idemKey(rc, d, args)
    if r, ok := rc.ToolCallRecord(key); ok { return r, nil }          // 已成功执行过：直接返回
    dec := rc.Authz().Check(authz.ToolCall{Tool: d.ID, Risk: h.risk, Taint: taint, Path: rc.Path()})
    switch dec.Kind {
    case authz.Deny: return Result{}, exec.AuthDenied(dec.Reason)
    case authz.Ask:
        resp, err := rc.Ask(exec.ApprovalReq{Kind: "tool_call", Tool: d.ID, Args: args, Reason: dec.Reason})
        if err != nil || !resp.Approved { return Result{}, exec.AuthDenied("rejected") }
    }
    if err := h.pool.Acquire(rc); err != nil { return Result{}, err }
    defer h.pool.Release()
    ctx, cancel := context.WithTimeout(rc, d.Timeout); defer cancel()
    raw, err := h.impl.Invoke(ctx, Call{Args: args, IdemKey: key, Taint: taint, Caller: rc.Path().String()})
    if err != nil { return Result{}, classify(err) }
    res := h.trim(rc, raw)                                            // 裁剪 + 保证 Ref
    rc.RecordToolCall(key, d, args, res)                              // 写 tool.call 事件
    return res, nil
}
```

### 8.3 裁剪
策略引用 `trim`，内置三种：

| 模式 | 行为 |
|---|---|
| `relevant`（默认） | 原文切块（约 500 tokens/块），用任务卡的 `instruction + purpose` 做 BM25 打分，取前 k 块直到 `max` tokens；全部原文存 ws |
| `head` | 取开头 `max` tokens |
| `none` | 不裁剪（只允许小结果，超过 8KB 仍转指针） |

第二阶段可选 `embedding` 模式（向量相似度），需要配置嵌入模型。

### 9.1 代码执行沙箱：选型与取舍
| 方案 | 隔离 | 跨平台 | 复杂度 | 结论 |
|---|---|---|---|---|
| 子进程 + 超时 + 临时目录 | 弱 | ✔ | 低 | 只适合可信代码，不采用 |
| WASM（wazero + Python/JS 的 wasm 运行时） | 强（无系统调用） | ✔ 纯 Go | 中 | **M2 首选**：Pyodide 体积大，先支持 JS（QuickJS wasm） |
| Docker / gVisor 容器 | 强 | 依赖 Docker | 高 | 服务端部署（M5）可选 |
| Firecracker | 很强 | 仅 Linux | 很高 | 不在计划内 |

第一阶段：不提供 `code_exec`，聚合和分支里的确定性脚本用 expr 解决；M2 引入 wazero + QuickJS，限制 CPU 时间 5s、内存 128MB、无网络、无文件（只能读传入的参数）。

## 10. MCP 客户端

- 实现：使用官方 Go SDK `github.com/modelcontextprotocol/go-sdk`（若届时不成熟，退回 `mark3labs/mcp-go`）。
- 传输：**stdio**（本地启动子进程）与 **Streamable HTTP**（远程）。
- 配置：
```yaml
mcp_servers:
  jira:
    transport: stdio
    command: npx
    args: ["-y", "@company/jira-mcp"]
    env: {JIRA_TOKEN: "secret://jira/token"}
    risk_default: L1
    risk_overrides: {create_issue: L2, delete_issue: L3}
  docs:
    transport: http
    url: https://mcp.example.com/mcp
    headers: {Authorization: "Bearer ${DOCS_TOKEN}"}
```
- 生命周期：服务启动时**懒连接**；首次使用时 `initialize` → `tools/list`，缓存工具列表；收到 `notifications/tools/list_changed` 时刷新。子进程崩溃自动重启（指数退避，最多 5 次）。
- 映射：每个 MCP 工具注册为 `mcp:<server>/<tool>`，`inputSchema` 原样作为 `Def.Input`，风险等级按 `risk_overrides` → `risk_default` → L1 决定（MCP 的 `annotations.readOnlyHint=true` 可降为 L0，`destructiveHint=true` 至少 L2）。
- 在节点库里，每个 MCP 服务器显示为一个分组，用户把工具拖上画布就是一个 `mode=endpoint` 的工具节点。
- 结果：MCP `content` 中的 text 合并进 Summary/Snippets，image/resource 存 ws 返回指针；一律 `Taint=true`。
- 权限：MCP 工具与内置工具完全走同一套 `authz.Check` 与审批；服务器级可以整体禁用。

## 11. 有副作用工具的幂等实现

1. **幂等键生成**：`idem = sha256(run_id | node_path | attempt_scope | canonical_json(args))`，其中 `attempt_scope` 对 direct 工具为空、对 Agent 内工具调用为 `turn/index`。节点重试时不变。
2. **执行前查询**：`tool_calls` 表（`idem_key` 主键，`status`，`result_ref`）。
   - `succeeded` → 直接返回记录结果。
   - `started` 且无结果（崩溃于调用中）→ `Def.Idempotent=true` 时带同一键重发；否则转人工确认（"上次可能已发送，是否重发？"）。
3. **执行**：先插入 `started` 记录（事务提交），再调用外部系统，成功后更新为 `succeeded` 并写 `tool.call` 事件。
4. **透传**：支持幂等的外部 API（HTTP 工具配置 `idempotency_header`）在请求头带上 `Idempotency-Key: <idem>`。
5. **回放**：回放运行永不调用 L1+ 工具，一律用 `tool_calls` 中的录制结果。

```sql
CREATE TABLE tool_calls (
  idem_key   TEXT PRIMARY KEY,
  run_id     TEXT NOT NULL, path TEXT NOT NULL, tool TEXT NOT NULL,
  status     TEXT NOT NULL,            -- started / succeeded / failed
  args_ref   TEXT NOT NULL, result_ref TEXT,
  started_at TEXT NOT NULL, ended_at TEXT
);
```

## 12. 测试支撑

- `llm/fake`：按 `(model, hash(messages))` 返回录制响应；支持脚本化（第 N 次调用返回 X），用于执行器和调度器测试。
- `llm/record`：包装真实 Client，把请求与响应存到 `testdata/cassettes/*.json`；CI 默认只回放，`-record` 标志才真调用。
- `tools/fake`：可注入延迟、失败、限流，用于背压与重试测试。
- 每个 provider 适配器都有一组共享契约测试：结构化输出、工具循环、流式拼接、usage 映射、错误映射。
